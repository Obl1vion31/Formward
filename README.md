Formward 是一个 AI 原生的个人健康与训练助理。名称由 `Form` 与 `Forward` 组合而成，表达体型塑造、自我管理与持续向前。

品牌采用 F＋手臂标志，搭配小写字标与金色圆点；手机业务页仅显示图标。透明 SVG、1024px PNG 及标签／主屏图标的来源和维护规则见[图标目录](public/icons/README.md)。

项目从饮食、运动和身体指标记录开始，逐步连接训练器材、健康平台和其他个人数据来源。网页与外部 AI 助手共用同一套业务功能：用户既可以在 PC 页面中操作，也可以授权外部 AI 查询、记录、分析并提出需要用户确认的计划调整。

## 为什么做 Formward

MacroFactor 已经很好地覆盖营养记录、趋势体重、能量消耗估算、周期性目标调整和训练追踪。Formward 不以复制这些功能为目标，而聚焦三个差异：

- **AI 原生操作**：AI 通过正式 API 使用系统能力，而不是只在页面上增加一个聊天框。
- **统一个人数据生态**：饮食、训练、身体指标、健康平台和器材数据进入统一模型，并保留来源与可信度。
- **跨领域教练**：长期将营养、训练、恢复、目标和实际执行情况结合起来，生成可解释、可确认、可追溯的建议与计划。

新会话先读 [项目交接](handoff.md)，了解最新用户要求、已完成工作与接手顺序。当前实现和验证结果见 `docs/status.md`。详细定位见 `docs/product.md`，首版交付顺序见 `docs/milestones.md`，页面方案见 `docs/interface.md`，设计与视觉验收统一依据为 [设计文档](docs/design-reference.md)，涉及界面修改时实施前、验收前必读。

界面工作流已纳入 Mobile Design（任务流）、Impeccable（控件与状态一致性）及 Unslop（适度视觉打磨），共用上述设计文档。当前界面采用已认可的共同规则与B版基准；保留品牌、输入边界及手机触控要求，局部优化不重排无关页面，已授权手机重设计可调整其构图、导航与转场。Unslop不加入运行依赖，完成已授权修改和必要验收后合入main并按既有发布授权上线。

AI 接入支持身体、摄入、食材和消耗任意组合，一次提交一个审核链接。

完整接入和补授权统一通过authorize_formward一次申请身体、饮食／食材、消耗的查询与提交预览，用户在OAuth网页明确同意。连接检查只返回授权状态，不读取健康内容或创建预览；日常只读连接保持只读，旧令牌不自动扩权。
单餐先展示日期、本餐kcal及宏量合计，再列食物与修改／取消；普通记录只需底部一次确认保存，不要求逐项核对或照片勾选，缺图可先保存文字。修改餐次突出移除、增加和修改后合计。AI只能新增修改，不得整条删除恢复或批量删除；网页手工操作保留。使用与请求格式见 [AI 接入](docs/ai-api.md)。

保存、估算、AI审核和登录绑定真实等待，按钮立即回应并保留输入／失败反馈。已登录总览、饮食、训练、消耗和身体的固定标题、语义色、导航与操作槽不等待健康数据；最近记录、查看记录、食材库和历史入口保持显示，只占位未知数据，依赖数据的操作分别禁用。资料、安全等次级页采用超过200ms才出现的局部读取反馈；缓存命中不强制播放等待动画。草稿及确认优先。

## 首次使用与个人资料

新账号首次正常进入会先填写或跳过身高、出生日期，再查看操作教程；进度随账号保存。已有账号直接进入，个人资料从账号菜单查看，教程从助手的常用功能进入。管理员可演练初次登录，不改真实资料。每天体重和体脂仍在身体页记录，资料不自动生成消耗。

## 总览与外观

“助手”平时收起，电脑从右下打开非模态浮窗，手机从五项导航右侧独立按钮打开底部面板。AI待确认、今日待开始计划及昨日饮食形成角标，每天最多一条站内轻提示；点击才展开。昨日饮食可按日期永久忽略并跨设备同步，不改餐次或记全。常用功能从面板底部按钮向上展开。读数按区间预留必要空间，悬停不推移图表；电脑双图后可查看区间收支覆盖和缺口，手机首页移除该区域。

总览的摄入／晨重／消耗卡片位于完整关系图之前，手机横滑、电脑并排且按实际空间整卡换行。卡片小图使用各自实际日期的七日数据，两端进入对应趋势页均携带日期、区间和初始指标，并通过主导航、Logo或浏览器返回总览。返回恢复原卡片、滚动、焦点及总览已应用的区间选项；状态仅在本人内存上下文保存，记录变化后读取最新事实。手机保留三个同级记录动作与紧凑关系图；电脑保留六项日读数、七日摘要及图后的区间覆盖。顶栏日／月按钮可切换浅色／深色并从按钮中心圆形展开，账号菜单保留跟随系统开关，记住本设备偏好，登录人物首页保持原样。检测到新构建时提醒刷新，有未保存输入先确认，不自动刷新。

## 技术方向

采用轻量的 Next.js 模块化单体：

- Next.js、React、TypeScript
- PostgreSQL 18（上海正式主库）、Drizzle ORM；Neon保留停写源材料
- Better Auth
- Tailwind CSS、shadcn/ui
- Vitest、Playwright

账号管理采用邀请制：owner 在站内 `/admin` 生成一次性激活／密码重设链接并手动交付，用户自行设置密码。账号菜单提供本人设置，owner 另有管理入口；后台再次验密仅对当前会话生效十分钟。停用、改密和全部撤销联动网页与 AI，恢复不复活旧授权。没有邮件或公开注册。正式环境已完成 0027 migration，并为用户指定的已有账号初始化唯一 owner，原密码保持；正式发布状态见 [交接](handoff.md)，使用方法见 [账号接入](docs/auth-setup.md)。

首页、PostgreSQL 数据库和内部账号登录已接入。登录后的 `/dashboard` 是全局总览。总览保留双层日期关联图：上层蓝色摄入线、红色消耗线，柔杏金盈余与雾蓝灰缺口填色；下层金色次晨变化，共用日期、选中线与命中区，缺测断开。默认选最近同时有摄入和消耗数值的一天，再回退至最近有记录日；手机7D、桌面30D，不足时扩大至容纳目标日的最短既有区间。能量线图按全区间留5%且至少100 kcal余量，整齐刻度与范围分开生成，kg轴独立包含零，选日不改变坐标。手机当日收支与次晨结果紧邻所属图层，前后晨重和数据不足原因在日期详情查看；桌面六项读数同排，七日起止晨重与缺测原因直接显示。7D／30D／90D／全部／自定义、键盘／触屏及详情保持，当天确认为已记完且摄入、消耗都有数值时计算盈余；营养部分未知或估算不额外阻止相减。未记全／未确认日保留摄入展示，不产生盈余。

状况摘要分别采用今天及以前最近的记录日期：摄入汇总该日全部有效餐次，显示日期、餐数及kcal；消耗采用最近有效日记录或已完成运动所在日期，显示日期和读数。部分、未知和明确0保持区别；各类日期可以不同。摄入／晨重／消耗及真实七日小图位于完整趋势图之前，手机横向滑动、电脑自适应并排；图后不再重复同类摘要，跨零点不会清空已有摘要。

身体页以晨重主卡、相关次卡和唯一完整趋势呈现；身体设置控制体脂展示和录入，体重始终开启。点击指标卡切换图形，保留日期；晨晚实测录入、历史编辑、来源和隐藏体脂原值保持。

各页复用日期行与Inspector，保留“查看”及按日期和状态显示的“录入／补录／编辑”；今天和近期待处理日期常驻，其他日期在列表下方点击查看全部就地展开，具体日期查看或编辑才打开Inspector。具体日期的 Inspector 查看时保留晨晚概览；编辑专注录入，日期归入标题、保存位于字段之后；手机先选晨晚、体重与体脂并排，电脑晨晚并排。更多设置入口与时段同行，展开后才显示各自的整数 GMT 时区，可只改时区后保存。新记录默认采用系统时区，已有记录回显原值。晨晚分别填写数据来源；新录入在晨晚合并的最近连续3次采用实测来源一致时预填，补录只参考目标时段之前，不覆盖已有记录或手工输入。来源可补填、更换或直接清空保存；点击输入框直接展开本账号全部建议，无需清空现有文字；身体录入与 AI 审核共用输入。历史建议旁“×”可移除选项并保留草稿和已有记录；旧记录保留原来源不恢复选项，明确再次使用并成功保存后恢复。成功实测才更新建议，留空不生成建议。设备与连接应用合成名称快照，BMI 已从列、业务模型、录入和展示移除，旧四列 TSV 仍兼容，原文件与既有输入／审计保留。数据库只保存 record_date 一个记录日期，凌晨继续放在前一天晚间；准确测量时间保持，未知时间显示“无”。

身体只保存实测，缺测留空；体重与体脂估算、历史补全和重建已完整退役。历史估计仅私有审计归档，正常查询和导出不可见。来源修正、实测维护和审计保持。身体记录 MCP + OAuth、HTTP API 与 30 天可撤销令牌已接入，助手常用功能内的“AI 接入”提供配置和说明，所有写入先预览、经登录网页确认；公网和本机使用方法见 [AI 接入说明](docs/ai-api.md)。规则见 [身体指标记录](docs/measurements.md)，完整字段与关系见 [数据库字典](docs/database.md)，账号接入见 [接入指南](docs/auth-setup.md)。

饮食页先显示今天及以前最近有记录的一天，保留明确日期、未知与0；今天及前6天待处理日期可直接补录，更早记录从查看全部分页进入。新自由项默认1份，常驻输入食物、单位、数量和本次总kcal及P／C／F，数量只作记录；旧每份项回显已保存总量，未修改项原样保留。可靠包装规格可按包数填写，服务端换算；单位不重复显示，不猜包装重量。输入框和餐次备注持续显示暖色边框，详情在按钮旁的小气泡中展示规格或选择营养依据，长内容内部滚动。桌面可点击或拖选食材，手机按名称、单位／数量与同行营养组织，长数字或文字放大时自然换行。

桌面总览悬停预览；点击后保持日期，鼠标移动或离开不取消，Escape或更换区间解除；未点击的预览离开面板后恢复最近完整日；查看入口捕获对应日期，键盘和触屏保留各自选择。总览不显示独立日期导航组件；手机以紧凑读数和区间栏优先呈现完整双图及共用日期刻度。查看记录中身体与消耗并排、当天总营养及唯一供能环图常驻，默认折叠餐次；展开后显示本餐三项宏量与完整食物清单，每项再原位查看来源及依据，备注／照片展开后才请求原图。饮食页与总览共用餐次展示，四项当天读数不足四列时整组转2×2。两餐样本在1440×900默认详情不需纵向滚动，更多餐次允许自然展开。

## 自己启动开发服务

国内服务器的原生部署、隔离验收、数据库恢复演练及域名备案安排见[国服网页与海外后台](docs/mainland-deployment.md)。唯一网页和海外 AI 后台共用上海主库；旧 Neon 不再作为正式数据源。

1. 在终端进入本仓库根目录：`cd /home/obl1vion/projects/Formward`。
2. 安装 `.nvmrc` 指定的 Node.js `24.21.0`。可从 [Node.js 官方下载页](https://nodejs.org/en/download)安装；安装后打开新终端，运行 `node --version` 确认显示 `v24`。当前共享环境自带的 Node.js 18 不满足本项目要求。
3. 运行 `pnpm --version`，确认 pnpm 9 可用。如果没有 pnpm，在 Node.js 24 环境下运行 `npm install -g pnpm@9.15.9`。
4. 首次使用或依赖变化后，运行 `pnpm install`。
5. 运行 `pnpm dev`。终端显示 `Ready` 后，按上一节的地址打开首页。这个终端需要保持运行。

如果提示 `3000` 端口已被占用，通常是已有开发服务正在运行；先尝试打开首页，不要同时启动第二个实例。

## 关闭开发服务

- 如果 `pnpm dev` 正在你自己的终端里运行，切回该终端按 `Ctrl+C`。终端返回命令提示符后，服务就已停止。
- 如果服务由其他终端或工具启动，先运行 `ss -ltnp '( sport = :3000 )'`，确认显示的是本项目的 `next-server`，再运行 `kill 进程号`，把“进程号”换成上一步显示的 PID。若看到的是其他程序，不要关闭它。
- 关闭后再次访问 `http://localhost:3000`，浏览器应无法连接；下次查看重新运行 `pnpm dev`。

## 私有文件

用户上传文件不能放在 `public/`。原始 Excel 位于本地 `data/imports/`，并被版本控制忽略。`public/` 中的文件会由网站公开提供，只能保存允许任何访问者读取的图标、图片等静态资源。

消耗页支持分开记录／只记总数，活动合计／运动累计明确选择，来源分别填写；总数与运动共存时确认已包含／额外增加；静息公式与资料已撤下，旧数据及审计保留。日常默认值已停用，历史初始化只通过明确范围的审核批次处理。规则见[热量消耗](docs/energy.md)。
