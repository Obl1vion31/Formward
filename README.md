# Formward

Formward 是一个 AI 原生的个人健康与训练助理。名称由 `Form` 与 `Forward` 组合而成，表达体型塑造、自我管理与持续向前。

项目从饮食、运动和身体指标记录开始，逐步连接训练器材、健康平台和其他个人数据来源。网页与外部 AI 助手共用同一套业务功能：用户既可以在 PC 页面中操作，也可以授权外部 AI 查询、记录、分析并提出需要用户确认的计划调整。

## 为什么做 Formward

MacroFactor 已经很好地覆盖营养记录、趋势体重、能量消耗估算、周期性目标调整和训练追踪。Formward 不以复制这些功能为目标，而聚焦三个差异：

- **AI 原生操作**：AI 通过正式 API 使用系统能力，而不是只在页面上增加一个聊天框。
- **统一个人数据生态**：饮食、训练、身体指标、健康平台和器材数据进入统一模型，并保留来源与可信度。
- **跨领域教练**：长期将营养、训练、恢复、目标和实际执行情况结合起来，生成可解释、可确认、可追溯的建议与计划。

新会话先读 [项目交接](handoff.md)，了解最新用户要求、已完成工作与接手顺序。当前实现和验证结果见 `docs/status.md`。详细定位见 `docs/product.md`，首版交付顺序见 `docs/milestones.md`，页面方案见 `docs/interface.md`，MacroFactor 的产品参考见 `docs/design-reference.md`。

AI 接入支持身体、摄入、食材和消耗任意组合，一次提交一个审核链接。逐项核对、修改和取消只更新草稿，底部统一保存；各类内容可以独立选择，取消食材入库仍保留本餐快照与对应图片。旧链接继续可用，来源与时区规则保持。使用与请求格式见 [AI 接入](docs/ai-api.md)。

保存、估算、AI 审核、登录与站内页面加载都有统一等待反馈：按钮立即变字，超过 200ms 显示虚化背景和居中动作提示，实际结束后恢复。快速操作不闪现遮罩，失败保留输入，加载层可覆盖编辑弹窗。

## 首版范围

- 少量内部账号和独立数据归属。
- 手动饮食、运动和身体指标记录；可记录的测量字段按实际来源逐步确定。
- 每日汇总与阶段趋势。
- 现有 Excel 历史数据导入。
- 面向 AI 的查询与记录 API。
- AI 访问令牌、数据来源和基本操作记录。

个性化训练计划、营养策略、器材连接和外部健康平台同步属于后续阶段，但首版数据必须保留扩展所需的时间、单位、来源和外部标识。

## 技术方向

采用轻量的 Next.js 模块化单体：

- Next.js、React、TypeScript
- PostgreSQL、Neon、Drizzle ORM
- Better Auth
- Tailwind CSS、shadcn/ui
- Vitest、Playwright

首页、PostgreSQL 数据库和内部账号登录已接入。登录后的 `/dashboard` 是全局总览。总览以一张图展示 D 日摄入、最终消耗、盈余（摄入−消耗）及 D+1 晨重−D 晨重。浅蓝／浅红／金色三柱固定并排，暖白细线用右侧 kg 刻度，两轴零点对齐。相邻日缺测或候选未决留空；开关可显示已有估计，以虚线区分，不生成未来体重或作确定因果结论。标题与日期范围紧邻，图例和读数紧凑排列，保留 7D／30D／90D／全部／自定义、键盘选择和日期详情。图下身体、摄入、消耗三张卡进入对应页面；身体卡显示最近有效空腹晨重。

身体页保留原有双图、四项录入、历史编辑、已有估计及来源规则。

每行保留“查看”，另按日期和实测状态显示“录入／补录／编辑”；桌面同排、手机上下排列。具体日期的 Inspector 顶部常驻晨晚概览，查看时展开时段详情，编辑时显示四格表单，晨晚各有整数 GMT 时区选择，可只改时区后保存。新记录默认采用系统时区，已有记录回显原值。晨晚分别填写数据来源，只回显已保存值；来源可补填或直接留空保存；点击输入框直接展开本账号全部建议，无需清空现有文字；身体录入与 AI 审核共用输入。历史建议旁“×”可移除选项并保留草稿和已有记录；旧记录保留原来源不恢复选项，明确再次使用并成功保存后恢复。成功实测才更新建议，留空不生成建议。设备与连接应用合成名称快照，BMI 已从列、业务模型、录入和展示移除，旧四列 TSV 仍兼容，原文件与既有输入／审计保留。数据库只保存 record_date 一个记录日期，凌晨继续放在前一天晚间；准确测量时间保持，未知时间显示“无”。

普通保存不自动估算；实测只替代对应指标的估计，其他依据和初始化冻结范围保持。来源修正、估计重建、软删除／恢复与审计已有维护入口，网页归属纠正、删除／恢复和导入尚待接入。身体记录 MCP + OAuth、HTTP API 与 30 天可撤销令牌已接入，邮箱右侧“AI 接入”提供配置和说明，所有写入先预览、经登录网页确认；公网和本机使用方法见 [AI 接入说明](docs/ai-api.md)。规则见 [身体指标记录](docs/measurements.md)，完整字段与关系见 [数据库字典](docs/database.md)，账号接入见 [接入指南](docs/auth-setup.md)。

饮食记录保留今天摘要，历史使用 P／C／F 蓝色层次的 kcal 堆叠柱和精确读数，可切换克数／能量占比，默认克数，全部范围固定宽度。餐次编辑桌面左侧为可搜索、按整餐／食材筛选的卡片，点击或拖入右侧小表格；手机保留选择／本餐分步。右侧顶部常驻合计，每项一行：名称、用量、kcal、P、C、F、操作，并常驻一行空白自由填写。桌面双击或 Enter 编辑、Tab 移动，触屏轻点；食材营养自动换算只读，自由项营养是本次摄入，不再次乘分量。份／勺等计数单位默认 1，重量、体积和未知单位留空；更换食材按新单位重新设置。新餐次按设备时间建议早餐／午餐／加餐／晚餐／夜宵，可手改，旧餐不覆盖。依据、新食材规格、备注和照片按需展开，上传／缺图／重复／审核保护保留。 食材库按整餐／食材分类，已移除基础预设采用。最近删除支持餐次和食材恢复／永久删除，食材删除后旧餐的营养、用量、原单位和照片继续保留。食材详情保留分项分析，AI 审核、Private Blob 原图与来源规则见[饮食记录](docs/meals.md)，生产状态见[交接](handoff.md)。


## 查看首页

公网部署使用 Vercel 与现有 Neon，正式地址为 [https://formward-ten.vercel.app](https://formward-ten.vercel.app)，可用原内部账号登录。外部 AI 可通过 `/api/mcp` 和 OAuth 登录授权连接，或使用公开 [OpenAPI](https://formward-ten.vercel.app/api/v1/openapi.json) 和独立访问令牌。写入仍需网页登录确认；连接步骤见 [AI 接入](docs/ai-api.md)。MCP 与手机调整已发布，当前状态见 [项目交接](handoff.md)。平台配置、发布与验收方法见 [公网 HTTPS 部署](docs/deployment.md)。

如果开发服务已经启动，在运行项目的同一台电脑上打开浏览器，访问 [http://localhost:3000](http://localhost:3000) 或 [http://127.0.0.1:3000](http://127.0.0.1:3000)。`next.config.ts` 已允许这两个本地地址加载开发资源。如果项目运行在远程工作区，在编辑器的「端口 / Ports」面板找到或转发 `3000` 端口，再打开面板给出的地址。`localhost` 指的是运行浏览器的电脑；远程工作区不能直接用自己电脑的 `localhost` 访问，除非已经做了端口转发。使用其他转发域名时，把它的主机名加入 `next.config.ts` 的 `allowedDevOrigins`，并重启开发服务，否则页面可能显示但客户端动画无法执行。

当前首页采用“数字雕塑 + 编辑式界面”：桌面为深石墨色中央人物舞台，人物背后有微弱暖金环境光和宽幅暖色层次，侧下方叠加极淡 petrol 环境色。手机使用纯石墨背景和原始透明 PNG 的正常合成，去掉舞台彩色环境光；点击首屏任意非交互位置即可直接显示登录尾帧，顶部“返回”可回到首帧并保留输入。手机不加载转身视频、不使用滑动进入或返回。第一屏显示左上角 Logo、居中人物，以及桌面左下角的 `SCROLL TO ENTER` 与细线滚动提示；停在第一屏时持续显示，鼠标移动或未触发播放的滚轮操作不会隐藏，倒放回第一屏后重新显示，触屏与窄屏不显示提示。人物有极弱的反向鼠标视差，停止后缓慢回中。转身后，Email、Password 和 `ENTER` 从液态尾部前方浮出；烟色衬底边缘渐隐，没有外框，肩背与腰线保持露出。首次聚焦输入框后人物回中，整个登录阶段保持固定。输入底线默认隐藏，只有可操作字段悬停或聚焦时显现；键盘保留清晰焦点框，触屏点击标签即可聚焦。ENTER 使用哑金文字及短下划线；键盘用户可通过聚焦时才显示的“进入登录”入口进入表单。

素材就绪后，封面显示三组同级、单行概念词：Discipline / NUTRITION、Drive / BUILD YOURSELF、Effortless / AI LOGGING。主词采用本地 Newsreader 正体 400、0.035em 字距与暖灰白，桌面字号为 `clamp(20px, 1.68vw, 26px)`；副标签使用本地 IBM Plex Mono 与哑金，Logo 和表单沿用系统 sans serif。桌面节点、引线与文字沿倾斜椭圆轨道随人物同步转动 150°，以轻微缩放和明暗表现纵深。节点与棕金引线位于文字上方，左侧标注向右对齐、右侧向左对齐，转动途中平滑改变对齐；文字始终朝向读者，不随人物鼠标视差移动。登录终点为 Discipline 右上、Drive 右下、Effortless 左侧；标题与轨迹减弱，微标签保持可读。手机保留 14px 主词、底部三列与细轴，登录后位置不变。认证阶段停留终点，失败保留，成功后随最终人物动画淡出；桌面 reduced motion 在 180ms 内交叠首尾静态构图，手机点击直接显示端点。概念词表达饮食自律、自驱力与 AI 记录方向，业务记录和 AI API 仍按里程碑实现。

桌面一次明确下滚后，页面自动以 2 倍速播放 v6 转身视频，完整时长为 0.5 秒；上滚以同样时长倒放，播放途中可立即从当前进度反向。静态首尾保留原来的 `1.png` 与 `12.png`，两端各 40ms 与经过大小及位置校准的视频交叠；视频黑底与宽幅暗光晕通过透明 Canvas 合成去除，背景与人物外层鼠标联动保持原设计。登录表单在最后 200ms 同步显现，倒放同步隐藏。三张静态图完成解码后开放交互；桌面视频主动静音内联播放以唤醒解码，当前帧就绪后立即暂停并转由时间线寻帧。失败、WebGL 不可用或预加载超过 4 秒则采用 180ms 静态首尾过渡，仍可登录。触摸、点击或按键可重试受限视频，恢复后在静态端点切回完整转身；系统 reduced motion 始终保持静态过渡。加载期间的最近方向会自动执行。停在 12.png 且 Email、Password 非空后，点击 `ENTER` 先验证账号；认证过程中保持第 12 张并禁止重复提交和方向变化。验证成功后从居中姿态播放原来的 700ms 的 12.png → 13.png，实际动画结束后进入 `/dashboard`。reduced motion 使用 180ms 静态首尾淡入淡出，最终过渡为 240ms。错误密码或网络失败留在表单并显示中文提示。账号与会话通过 Better Auth / Drizzle 保存在 PostgreSQL；主页验证当前会话并提供退出登录，未登录不能直接访问。视频素材见 [视频目录](public/videos/README.md)，页面与校准见 `docs/interface.md`、`docs/frame-calibration.md`。

## 自己启动开发服务

1. 在终端进入本仓库根目录：`cd /home/obl1vion/projects/Formward`。
2. 安装 `.nvmrc` 指定的 Node.js `24.21.0`。可从 [Node.js 官方下载页](https://nodejs.org/en/download)安装；安装后打开新终端，运行 `node --version` 确认显示 `v24`。当前共享环境自带的 Node.js 18 不满足本项目要求。
3. 运行 `pnpm --version`，确认 pnpm 9 可用。如果没有 pnpm，在 Node.js 24 环境下运行 `npm install -g pnpm@9.15.9`。
4. 首次使用或依赖变化后，运行 `pnpm install`。
5. 运行 `pnpm dev`。终端显示 `Ready` 后，按上一节的地址打开首页。这个终端需要保持运行。

如果提示 `3000` 端口已被占用，通常是已有开发服务正在运行；先尝试打开首页，不要同时启动第二个实例。

## 关闭开发服务

- 如果 `pnpm dev` 正在你自己的终端里运行，切回该终端按 `Ctrl+C`。终端返回命令提示符后，服务就已停止。
- 如果服务由其他终端或工具启动，先运行 `ss -ltnp '( sport = :3000 )'`，确认显示的是本项目的 `next-server`，再运行 `kill 进程号`，把“进程号”换成上一步显示的 PID。若看到的是其他程序，不要关闭它。
- 关闭后再次访问 `http://localhost:3000`，浏览器应无法连接；下次查看重新运行 `pnpm dev`。

## 私有文件

用户上传文件不能放在 `public/`。原始 Excel 位于本地 `data/imports/`，并被版本控制忽略。`public/` 中的文件会由网站公开提供，只能保存允许任何访问者读取的图标、图片等静态资源。

消耗页支持按账号设置平均静息与未录活动按零的起始日期、初始化活动估算及备注；公式对照独立显示，不替换采用值。规则见[热量消耗](docs/energy.md)。
