# AI 接入

提供令牌／连接管理和统一记录审核的 Server Actions，分别验证登录账号。混合批次、草稿和事务由 records feature 负责，身体／饮食规则继续由对应 feature 复用；API 不提供正式确认入口。

页面只负责登录校验及调用auth feature的视图读取；先返回当前有效连接，再以同一账号的Promise接管令牌和提交记录，不重新挂载用户已打开的详情。初次连接等待保留标题，超过200ms才显示局部反馈。ChatGPT和豆包按接入状态组织；历史提交默认收起，按来源与审核状态筛选。原审核链接、来源及权限规则见auth目录说明。

完整接入使用authorize_formward统一检查并申请身体、饮食／食材、消耗和训练的查询与提交预览权限。该工具只返回连接状态，不读取健康内容、不生成预览或保存事实；OAuth同意仍由用户完成。缺权限时保留原有授权，并合并申请四类记录权限；只有读取权限的连接在日常查询补授权时只申请四类读取，明确调用完整接入或提交工具才申请提交权限。已有令牌不会因请求授权而自动扩权，旧客户端与单类授权继续可用。

训练模板与排期沿用统一网页审核；确认及修改后使训练页缓存失效，返回日历读取当前事实。没有通过MCP直接确认的入口。

普通确认页面未登录时保留本站目标，登录后返回原记录；目标只来自proxy清理后的实际路径，外部地址和API路径不能成为返回目标。OAuth授权页面仍使用原流程。
