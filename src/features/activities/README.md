# 消耗记录

手机消耗进入首页B卡片带，专页顶部记录动作直接打开原每日消耗编辑器。全天总数／静息／活动、运动累计／手填、包含关系及历史继续共用原业务函数，不简化为单一补全字段。

energy-editor-state.ts归一化日记录和有效运动草稿，包括单运动包含关系的变化；中性空白运动不触发退出提醒。详情“添加活动”通过内部addActivity意图直接展开一条空草稿，普通编辑不新建。顶部保存区域显示失败并保留重试输入。内部entry参数只控制网页起点，不新增HTTP／MCP写入能力。

## 每日填写窗口

活动合计及单位同行，数值和来源按输入基线对齐；顶部实时总数与保存保留。对照版共享此布局，不把共同修正记作 Unslop 的专属收益。

顶部显示目标日总消耗与保存，其后为总消耗、运动明细和时间备注。新日默认activities累计；自动值只显示，不写为手填合计。手填包括0才切换total、要求新/已变运动核对；清空失焦与“填写方式”菜单切回累计都先确认草稿前后数值；取消保留手填数值、来源及包含关系，切回手填可恢复原草稿。改变总数或计入值让旧关系失效，来源备注不重问。新运动默认计入，页面不再提供已完成勾选；旧false保持未计入。单独修改运动也预览同日其余活动。旧消耗预览的规则摘要已更换，必须刷新；无migration。

运动填写calorieMode=total／components。旧caloriesKcal保持原值；分开填写增加exerciseRestingKcal／exerciseActiveKcal，只将纯运动计入每日。activityReadings区分本次总数与计入值；普通填写、AI、查询及Excel共用。0026只增列不回算历史。没有采用中的活动／全天总数不问包含关系。

沿用activities模块，集中每日消耗、运动明细、原始来源和确认审计；网页、HTTP、MCP与Excel复用同一规则。

- model.ts：输入schema、明确模式、energyBaseline包含关系绑定及energyDays最终读数。只记总数与分开记录互斥，运动明细始终可记录；存在总数／活动合计时，included不加、additional额外增加，不按大小猜测。
- records.ts：归属、凭据、版本、幂等、整批预览、包含关系校验、正式事务及来源审计。旧无关系明细沿用原结果；未知不补0。
- presentation.ts：服务端读数；公式／默认值不参与正常功能，旧资料及审计保留。
- energy-aggregate.ts：切换前后预览复用energyDays，列出当前草稿有效运动；未知不补零，取消不改变模式，确认只改草稿。
- energy-editor.tsx／energy-view.tsx：日记录与运动一次事务保存、关系逐项／全部选择、保存日期、草稿保护、补录及历史趋势。AI日编辑只更新日草稿，运动在独立审核项确认。
- ai-api.ts／ai-openapi.ts：共用查询和公开协议，不新增权限；AI仅新增修改，正式保存须网页登录确认。
- history.ts：构造明确账号、固定范围的私有一次性补缺动作，不是长期默认。真实数值不进入客户端或公共migration。
- sources.ts：独立消耗来源建议池，成功保存才记忆，软移除保留历史与草稿。
- energy.test.ts／inclusion.test.ts／migration.test.ts：原口径、未知／0、包含关系、两种顺序、旧事实、归属、幂等、撤销和回滚。

页面先显示最近有效日读数与趋势，再列今天与前6天待处理日期及可展开的更早记录；空日不入库，不自动产生静息或活动。来源可留空。日常默认值、静息公式／资料的新动作与恢复均停用，旧申请只能取消。完整规则见[消耗文档](../../../docs/energy.md)。

消耗页使用共用选日、区间按钮、每日行、历史和Inspector。日期与查看记录在读数上方，图表下无前后日或编辑所选日。主列表保留今天及前6天最终总数未知日期；只有活动仍可补日记录，0是有效值。手工网页保存传入服务端内部永久删除选项，批量活动删除同一事务执行，不能从HTTP／MCP请求注入；旧软删除数据及原审计保留。

“查看全部”在最近行下方展开页面历史，每批50日且不重复最近日期。具体日期的查看／录入／编辑才打开Inspector，原列表保持展开和加载批次。

activity-summary.ts统一填写窗口、日期详情和AI确认的运动总数、分项及是否额外增加说明，不重算每日读数。已包含时不再单列“计入741”暗示叠加；固定总数与首节一条边界，修改关系／移除操作分开。

网页每日消耗新增／修改使用records/web-entry.ts与web-entry-server.ts检查：当前采用模式至少一个主要数值为正，分项可只填已知部分，静息2058与活动0合法；总数模式不借用隐藏分项。已知旧记录仅修改备注／来源时，后台核对本人版本和未改变的数值后保留。单次运动、公开HTTP／MCP和未经手工修改的旧AI确认不新增此限制。

趋势柱图使用共用100ms选日、4%日期底纹、1px虚线和金色底部短标记，与饮食同规格；图层位于数据下方，分项／仅总数、未知与0以及柱宽和命中范围保持原状。鼠标离开完整面板恢复默认，移动到查看入口仍捕获当前日期。

消耗查看详情的日期仅在Inspector标题，摘要上下12px、数字上距4px且行高1.2；数字单位同行，常规三项同排、长数值按内容宽度整项退让。来源／操作间距8–12px，dayDetails样式只作用于查看；不修改填写窗口与合计规则。


运动详情默认显示名称、本次总数、分项和共用activitySummary的短状态；展开本条查看时长、来源、完整计入解释和编辑，删除位于本条更多且仍须确认。短状态不另算合计，填写与AI原有完整说明保持。

readEnergySnapshot的可选dates参数供助手只读今天／昨天，省略退役defaults与profiles；全天总数继续复用energyDays的正式记录模式和运动包含规则，不因仅有运动就认定全天完整。完整页面与写入预览仍读取原快照。

手机总消耗主卡下使用energy-composition.tsx绘制所选日静息／活动比例；只接受两项已知且合计为正，明确活动0合法，仅总数不猜分项。使用既有energyDays汇总，不重复累计运动。右上额外记录入口退出，首页、助手和日期行保留。
