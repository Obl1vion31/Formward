# 小助手

手机底栏和待办提醒在已登录工作区直接打开助手，浏览器历史记录地址及本次返回入口。来源业务页留在原位置，退出时等浏览器历史和路由同步到来源，再恢复已选日期、筛选、滚动及焦点。直接访问助手地址由服务端校验登录，返回总览。进出使用工作区的 200ms 短横移与淡变，减少动态效果时即时切换。消息和待办在各自区域读取并可重试，现有会话草稿、照片和引用由同一账号的聊天状态维护。

回答中的无序／有序列表显式使用disc／decimal，避免全站样式重置抹掉项目符号；GFM复选列表继续仅以复选框表示。实际浏览器同时核对语义节点、计算样式与原始截图，表格沿用现有GFM渲染及横向查看。

通用按钮悬停反馈使用低优先级选择器，只补充普通操作的底色，不覆盖确认保存、统一补充提交与发送等主操作的语义底色。失败后仍可操作的按钮保持清楚可辨；禁用、处理中与可重试状态分别核对实际样式。

聊天运行由数据库持久任务及独立chat-worker执行，网页SSE订阅真实正文分片、工具步骤和任务开始时间。重新连接读取同一运行，按消息与偏移续接。名字旁是消息时间，处理行从后台领取开始计时，等待补充或终态收起。当前输入、相关附件、已确认事实及待确认预览优先；较早可选历史按预算缩减，图片本身超限时可在原消息分批处理。切后台、刷新、断网或收起面板不取消生成；恢复后读取原任务，不重新调用模型。明确停止及撤销授权通过数据库状态取消，后台每秒检查；两个并发任务，8轮／每轮120秒及额度保护保持。未领取任务10分钟未执行、已领取任务150秒无心跳时保留结果并标记中断，未知费用不清零，不自动收费重放。

任务保存已鉴权的执行参数和附件来源，不存Cookie或Key。新图优先，明确引用／补充绑定原消息；重试沿用原绑定，普通新问题不隐式借用历史图片。发送前按归属、类型、大小和实际SHA核验原图，失败不降级为无图请求。私有requestDiagnostics逐轮保存prepared／request_started／response_received／completed、实际模型、消息／附件摘要及受限供应商请求编号，不保存图片正文或完整Prompt，不进入网页快照。历史回答模型与下一条所选模型分开。


沿用暖白／石墨／金色、品牌和漂浮导航。电脑为背景可见的860px双栏浮窗，左栏常规312px并随窄窗收缩，三个手动记录逐行，下方按需补记／AI确认／常用功能统一向下展开；右栏只聊天。手机进入独立助手页，返回、聊天／待办、历史和新对话同排；320px下三个简写记录入口同排。欢迎说明14px且正常字号单行，当前与历史正文15px、输入16px、操作14px、辅助13px、44px命中。桌面 AI 确认的营养摘要按组同行，D15与实际网页共同决定验收。

chat-store管理本人的会话、请求幂等、30天授权与合计用量；chat-provider开放千问／小米流式协议，智谱仅保留历史适配；chat-tools按需复用18项正式MCP2.0.2工具；chat-runtime只展示真实工具摘要，不输出原始内部推理。共用prompt仍由records/ai-prompt.mjs构建，千问original、小米compact，新智谱调用停用；默认10组完整问答、当前任务和引用，切换只作用下一条发送。5条分页、最多50条，不自动删除数据库历史。

业务资格独立于管理角色。auth/entitlements决定Free、内测、Plus及指定owner的能力，服务端每次调用和预占核对最新值；账号仍保留提醒、手工记录、历史和已开放设备接入。Free仅本餐识图4次／日，不允许通用聊天；内测合计¥1，Plus和指定管理员合计¥2，Pro预留不可分配。客户端打开、恢复前台及每60秒同步，不重新登录或重建草稿。用户只见百分比或识图次数，不展示金额明细。

followup在本人当前任务下解析题目、选项和原始回答。来源问题绑定日期与时段，source-followup从近30天真实记录取最多4个仍有效的候选，近期优先；候选不是白名单，不扩写型号。后续补充沿同一任务保留已确认字段，预览再核对绑定；新话题不继承旧任务答案。手机选项逐行，无预选，选完统一提交；显式留空与未知区分。

chat-preview-card与records/web-review复用同一人工审核。回答结束后显示业务摘要：测量日期／时段／空腹／新增修改在顶部，体重28px手机／32px电脑，来源与时区13px；饮食、消耗和训练各自突出真实主要事实。单项不重复待保存数量、逐项取消或常驻审核信息；修改与更多详情次级，底部本次不保存／确认保存同层。过期、撤销、版本、归属和幂等仍由正式服务控制，外部AI继续原网页审核。

meal-task是purpose=meal_entry、active=false的本餐独立任务，不占主聊天。服务器绑定日期、餐次和原手工草稿；模型仅提出新增食物，结果回填后人工统一保存。Free使用仅限meals的独立可撤销授权；过期／撤销后须明确重新授权。上传不扣次，第一次模型请求在账号锁内预占；同任务补充和技术重试复用，纯技术失败退次，成本原账仍保留。模型切换只改本餐任务，不改主聊天。

聊天与饮食共用meals/photo-upload与use-photo-draft。每批探测受控空入口，自动选择当前网络可达通道，不持久记住账号地区；原图字节一次读取，10分钟传输／60秒停滞／15分钟凭据，100%后核对，登记完成才可发送。真实进度、取消、重试和人工换通道保留其他内容；截图、原答和诊断保持私有。

聊天草稿、照片和阅读位置保留。异步卡片增高继续跟随底部；滚轮、触摸、键盘和滚动条的主动上翻解除跟随，居中悬浮箭头恢复，不占一行。食物照片说明单独监听visualViewport，保持焦点、光标和文字可见。

完整能力、开关、回退与接口见[站内助手](../../../docs/assistant-chat.md)；实际证据与未测项见[助手验收](../../../docs/assistant-chat-verification.md)。模型对照是私有隔离测试，不向真实健康记录写入虚构内容，不以单个案例或一次成功宣称准确率提升。

聊天正文通过chat-text的语义Markdown／GFM渲染，宽表局部滚动，不执行原始HTML；chat-presentation只整理站内误导性审核指引，原始消息与审计保持。preview-presentation仅按明确的正式对象标识及保存版本去重已保存回执，未知目标不猜测。消息从真实requestId衔接，逐条到达动效只播放一次；真实同类工具步骤在所属过程摘要归组。手机独立页复用可视视口的尺寸与偏移，输入、消息列表和返回操作适配软键盘。验收结果标明实机和模拟环境。手机新定位的公网发布验收覆盖真实 iPhone Safari 的正文、光标和操作可见性。

聊天主输入行包含加号、文字、当前模型和发送，选图后附件在左上方。按压编辑区会从触点铺开横向柔光。模型菜单读取本人当天可用额度，生成期间可查看。引用、复制与同条记录链接归到回答操作行。同任务连续回答由实际补充关联决定。

聊天输入按实际文字或完整占位语测量高度，监听自身宽度与字体变化。Safari空输入不依赖其占位语scrollHeight，200%文字仍自然换行；测量节点不可见、无焦点并即时移除。输入高度封顶后，正在末尾输入时仅滚动textarea内部使文字和光标可见；编辑中间文字不强制拉至末尾。面板与键盘沿用已发布定位处理。

旧聊天的审核指引按站内呈现规则处理，不要求旧URL编号与当前引用相同；已知Formward审核URL、登录及固定到期文案退出正文，实际卡片控制状态。缺少可用卡片时提示从AI确认查看，不伪造保存状态；原始消息、健康事实、外部引用及围栏代码保持。
引用输入预览采用相同站内显示规则；引用对象和服务端重建的原始问答保持。

新调用只开放千问original与小米compact。智谱通过既有FORMWARD_CHAT_GLM_DISABLED开关停用，默认停用；旧偏好显示千问但不重答，历史标识、授权和费用保留。补充沿用原任务绑定与来源原文校验。共用营养规则允许同口径总能量及两项宏量反推唯一缺项，结构化数值与依据分别填写；多项缺失且无依据、冲突、特殊供能或明确不估算仍保留未知。服务端不自动补值，手动录入不变。

补充表单逐题呈现，允许手填时直接显示输入框。选择「不知道」后推进或一键跳过本题，均在当前任务记为已处理；跳过全部保留有效答案并结束本任务追问。统一提交由服务器校验当前任务及字段，原问题下面可展开摘要。旧对话缺少定位时保留原补充记录。用户照片在文字气泡上方，发送前将本地预览交给消息，确认时复用同一气泡；手机等可视视口恢复再以右下为原点缩放一次。失败保留原发送内容，重试复用请求编号。待办快捷入口加号贴近文字，补记与AI确认数量来自当前真实事项，AI确认首次有有效内容时展开，后续刷新尊重用户收起。
所有模型调用由原费用账本和global-budget.ts共用全站每天10元预算，预占时锁预算日与用户，完成结算，未知继续占用；晚到用量可核实结算。个人AI策略可以覆盖金额／识图次数或暂停，后台worker每次供应商请求都读取新策略，恢复不重放收费任务。金额、任务与请求数的口径见[全站管理](../../../docs/security-admin.md)。

助手入口共用按账号挂载的会话与待办状态。手机软导航进入助手时保留来源页实例和滚动位置。历史会话按本人、chat 用途、更新时间和编号分页，每批20条。详情沿用消息、附件及预览查询，更早消息加载后恢复原阅读位置。历史摘要可跳转原审核页面，点「继续此对话」后由服务端切换会话。真实记录按原审核步骤保存。

待办的「AI 确认」在没有待确认提交时呈现静态行。有提交时可展开查看，读取失败在本页重试。
