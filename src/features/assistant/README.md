# 小助手

「待办」按今天、昨天平铺日常事项。当地 06:00 起提醒未记录的空腹体重，昨天缺全天消耗时按实际设备采用状态提供补记或查看同步。饮食区分未确认、未记全和没有餐次，有餐次可直接按「标为已记全」，网页确认复用当天版本、餐次摘要和幂等标识。空腹体重、昨日饮食、全天消耗和当天待开始训练各有「忽略」。只收起本人对应日期的这条提醒，待办与角标同步更新，重新登录仍生效。晚间测量从「身体」页当天记录进入。 本次忽略或标为已记全经服务端确认后，原行淡出并收拢，下方事项随之上移。日期组的最后一条随分组一起收起，空状态平滑补位。减少动态效果时即时更新。总览的临时提醒与图下读数重叠时，滚动或操作图表会让读数露出，待办仍可以从助手打开。

电脑聊天面板只处理自身的取消事件。取消上传文件选择器不会关闭助手、切换历史或清空当前消息与照片草稿。

聊天照片的重试和备用上传保留当前通道；主动选择国内／国际才切换，不重新采用本批最初的自动探测结果。

手机底栏和待办提醒在已登录工作区直接打开助手，浏览器历史记录地址及本次返回入口。来源业务页和原滚动位置持续保留，浏览器历史回到来源后将焦点归还入口。直接访问助手地址由服务端校验登录，返回总览。进出使用工作区的 200ms 短横移与淡变，动效只作用于助手前景，减少动态效果时即时切换。消息和待办在各自区域读取并可重试，现有会话草稿、照片和引用由同一账号的聊天状态维护。

回答中的无序／有序列表显式使用disc／decimal，避免全站样式重置抹掉项目符号；GFM复选列表继续仅以复选框表示。实际浏览器同时核对语义节点、计算样式与原始截图，表格沿用现有GFM渲染及横向查看。

通用按钮悬停反馈使用低优先级选择器，只补充普通操作的底色，不覆盖确认保存、统一补充提交与发送等主操作的语义底色。失败后仍可操作的按钮保持清楚可辨；禁用、处理中与可重试状态分别核对实际样式。

聊天运行由数据库持久任务及独立chat-worker执行，网页SSE订阅真实正文分片、工具步骤和任务开始时间。重新连接从同一只读快照读取消息、照片进度和运行状态，按消息与偏移续接。名字旁是消息时间，处理行从后台领取开始计时，等待补充或终态收起。当前输入、相关附件、已确认事实及待确认预览优先；较早可选历史按预算缩减，多于两张照片由后台分批读取，每批带同一段完整要求，证据保存后推进读数。一次最多上传八张，通常两张以下直接处理。分批只识图，全部读完后进行一次汇总与工具操作。同餐预览默认关联全部原图，正式写入待用户确认。技术中断后从检查点人工续读或重试汇总，旧手动分批消息仍可选未读照片。普通聊天按单次模型请求的50万估算单位接管上下文，接近上限时输入栏显示可继续发送的新建提示。模型请求仅携带一份重复的餐次明细；后续工具轮超限可在同一任务转为分批读图。仍中断时原回复保留正文与记录卡。「新会话继续回答」一次切换并启动任务，显示原问题、照片和真实进度，沿用原日期、观察及工具回执；已生成的记录沿用原卡，正式写入仍需人工确认。查询返回的部分明细按实际范围说明。切后台、刷新、断网或收起面板不取消生成；恢复后读取原任务，不重新调用模型。明确停止及撤销授权通过数据库状态取消，后台每秒检查；两个并发任务，8轮／每轮120秒及额度保护保持。未领取任务10分钟未执行、已领取任务150秒无心跳时保留结果并标记中断，未知费用不清零，不自动收费重放。

任务保存已鉴权的执行参数和附件来源，不存Cookie或Key。新图优先，明确引用／补充绑定原消息；重试沿用原绑定，普通新问题不隐式借用历史图片。发送前按归属、类型、大小和实际SHA核验原图，失败不降级为无图请求。私有requestDiagnostics逐轮保存prepared／request_started／response_received／completed、实际模型、识图或汇总阶段、消息／附件摘要、本地单次输入估算及受限供应商请求编号，不保存图片正文或完整Prompt，不进入网页快照。历史回答模型与下一条所选模型分开。


沿用暖白／石墨／金色、品牌和漂浮导航。电脑为背景可见的860px双栏浮窗，左栏常规312px并随窄窗收缩，左栏显示日常待办，AI确认和常用功能在原位向下展开。右栏专注聊天。手机进入独立助手页，返回、聊天／待办、历史和新对话同排。欢迎说明14px且正常字号单行，当前与历史正文15px、输入16px、操作14px、辅助13px、44px命中。桌面 AI 确认的营养摘要按组同行，D15与实际网页共同决定验收。

chat-store管理本人的会话、请求幂等、30天授权与合计用量；chat-provider开放千问／小米流式协议，智谱仅保留历史适配；chat-tools按需复用18项正式MCP2.0.2工具；chat-runtime只展示真实工具摘要，不输出原始内部推理。共用prompt仍由records/ai-prompt.mjs构建，千问original、小米compact，新智谱调用停用；默认10组完整问答、当前任务和引用，切换只作用下一条发送。5条分页、最多50条，不自动删除数据库历史。

业务资格独立于管理角色。auth/entitlements决定Free、内测、Plus及指定owner的能力，服务端每次调用和预占核对最新值；账号仍保留提醒、手工记录、历史和已开放设备接入。Free仅本餐识图4次／日，不允许通用聊天；内测合计¥1，Plus和指定管理员合计¥2，Pro预留不可分配。客户端打开、恢复前台及每60秒同步，不重新登录或重建草稿。用户只见百分比或识图次数，不展示金额明细。

followup在本人当前任务下解析题目、选项和原始回答。来源问题绑定日期与时段，source-followup从近30天真实记录取最多4个仍有效的候选，近期优先；候选不是白名单，不扩写型号。后续补充沿同一任务保留已确认字段，预览再核对绑定；新话题不继承旧任务答案。手机选项逐行，无预选，选完统一提交；显式留空与未知区分。

chat-preview-card与records/web-review复用同一人工审核。回答结束后显示业务摘要：测量日期／时段／空腹／新增修改在顶部，体重28px手机／32px电脑，来源与时区13px；饮食、消耗和训练各自突出真实主要事实。单项不重复待保存数量、逐项取消或常驻审核信息；修改与更多详情次级，底部本次不保存／确认保存同层。过期、撤销、版本、归属和幂等仍由正式服务控制，外部AI继续原网页审核。

饮食拍照表单汇总日期、餐别、原草稿、照片和说明。点「发给助手」后，服务器在同一账号事务内核对照片归属、餐次版本和额度，创建会话、首条消息与独立运行。重试同一请求返回已接收的会话。原图和说明保存在消息中，日期、餐次与手填项由服务器绑定。旧任务与原网页审核继续可读。

有聊天权限的账号可在本餐待补信息处理结束后续聊。仅有识图权限的会话共用消息、追问和餐次审核，工具及输入限制在本餐；历史可回看。识别只建议新增食物，正式保存复用同一个待核对预览。改用手填会结束本餐运行和待核对项，返回原手填草稿；重复提交复用同一次保存。上传不扣额度；接收新识图时预占，明确停止与未完成的识别按既有规则释放，成本原账保留。

聊天与饮食共用meals/photo-upload与use-photo-draft。每批探测受控空入口，自动选择当前网络可达通道，不持久记住账号地区；原图字节一次读取，10分钟传输／60秒停滞／15分钟凭据，100%后核对，登记完成才可发送。真实进度、取消、重试和人工换通道保留其他内容；截图、原答和诊断保持私有。

停止以当前消息的真实运行状态为准。尚未收到接收确认时先记下停止意图，取得同一条运行编号后提交。任务已有终态时，收到快照即收起停止入口。手动「重新读取对话」独立读取本会话，失败可再次点击，保留草稿与已收到正文。分片模式走应用自己的协商请求头，静默期间保活；只逐段展示明确标记的正文。

聊天草稿、照片和阅读位置保留。异步卡片增高继续跟随底部；滚轮、触摸、键盘和滚动条的主动上翻解除跟随，居中悬浮箭头恢复，不占一行。食物照片说明单独监听visualViewport，保持焦点、光标和文字可见。

完整能力、开关、回退与接口见[站内助手](../../../docs/assistant-chat.md)；实际证据与未测项见[助手验收](../../../docs/assistant-chat-verification.md)。模型对照是私有隔离测试，不向真实健康记录写入虚构内容，不以单个案例或一次成功宣称准确率提升。

聊天正文通过chat-text的语义Markdown／GFM渲染，宽表局部滚动，不执行原始HTML；chat-presentation只整理站内误导性审核指引，原始消息与审计保持。preview-presentation仅按明确的正式对象标识及保存版本去重已保存回执，未知目标不猜测。消息从真实requestId衔接，逐条到达动效只播放一次；真实同类工具步骤在所属过程摘要归组。手机独立页和底栏使用同一个固定视口。键盘开合时更新内容区底边，顶栏保持在原位。输入、照片和附件按各自的触点范围滚动，留白吸收拖动。验收结果标明实机和模拟环境。手机新定位的公网发布验收覆盖真实 iPhone Safari 的正文、光标和操作可见性。

聊天主输入行包含加号、文字、当前模型和发送，选图后附件和输入行共用一层外框。手机顶栏由固定外壳定位，键盘开合时更新可用高度。若浏览器随后把外壳实际向上移出可视区，按可见的外壳边界补偿并限制在外壳内部。消息、待办和长草稿各自滚动。短输入行收紧为50px外框，圆形发送和停止保留44px命中。模型菜单右对齐于当前按钮，底边距按钮顶边 8 CSS px。矮屏可在菜单内部滚动，生成期间仍可查看本人当天额度。引用、复制与同条记录链接归到回答操作行。同任务连续回答由实际补充关联决定。

聊天输入按实际文字或完整占位语测量高度，监听自身宽度与字体变化。Safari空输入不依赖其占位语scrollHeight，200%文字仍自然换行；测量节点不可见、无焦点并即时移除。输入高度封顶后，正在末尾输入时仅滚动textarea内部使文字和光标可见；编辑中间文字不强制拉至末尾。键盘出现时按可用高度调整内容区域，保持助手顶栏和工作区底栏的固定锚点。

旧聊天的审核指引按站内呈现规则处理，不要求旧URL编号与当前引用相同；已知Formward审核URL、登录及固定到期文案退出正文，实际卡片控制状态。缺少可用卡片时提示从AI确认查看，不伪造保存状态；原始消息、健康事实、外部引用及围栏代码保持。
引用输入预览采用相同站内显示规则；引用对象和服务端重建的原始问答保持。

新调用只开放千问original与小米compact。智谱通过既有FORMWARD_CHAT_GLM_DISABLED开关停用，默认停用；旧偏好显示千问但不重答，历史标识、授权和费用保留。补充沿用原任务绑定与来源原文校验。共用营养规则允许同口径总能量及两项宏量反推唯一缺项，结构化数值与依据分别填写；多项缺失且无依据、冲突、特殊供能或明确不估算仍保留未知。服务端不自动补值，手动录入不变。

补充表单逐题呈现，允许手填时直接显示输入框。选择「不知道」后推进或一键跳过本题，均在当前任务记为已处理；跳过全部保留有效答案并结束本任务追问。统一提交由服务器校验当前任务及字段，原问题下面可展开摘要。旧对话缺少定位时保留原补充记录。用户照片在文字气泡上方。两张及以上按发送顺序逐层向右上叠放，首图完整取景，点整叠从首张浏览本人私有原图。预览固定阅读框，160ms淡入。解码后一次显示原图，慢读保留已显示照片及页码，失败可就地重试。关闭时恢复触发按钮焦点。相同结构用于历史。发送前将本地预览交给消息，确认时复用同一气泡；手机等可视视口恢复再以右下为原点缩放一次。失败保留原发送内容，重试复用请求编号。待办快捷入口加号贴近文字，补记与AI确认数量来自当前真实事项，AI确认首次有有效内容时展开，后续刷新尊重用户收起。
所有模型调用由原费用账本和global-budget.ts共用全站每天10元预算，预占时锁预算日与用户，完成结算，未知继续占用；晚到用量可核实结算。个人AI策略可以覆盖金额／识图次数或暂停，后台worker每次供应商请求都读取新策略，恢复不重放收费任务。金额、任务与请求数的口径见[全站管理](../../../docs/security-admin.md)。

助手入口共用按账号挂载的会话与待办状态。手机软导航使用常驻视口框架，底栏与助手输入栏共用底边和系统安全区。全屏底色从助手入场首帧覆盖可见区域。手机助手持有外层滚动锁直到退场完成，再恢复工作区原位置。长文字和附件补充区原生滚动，单指纵向手势到各自边界时停在输入区。键盘已稳定时，输入区纵拖后的视口偏移不会改变顶栏和输入栏。真实的键盘高度或输入焦点变化继续重新定位。消息和待办各自滚动。历史会话按本人、chat 用途、更新时间和编号分页，每批20条。详情沿用消息、附件及预览查询，更早消息加载后恢复原阅读位置。历史摘要可跳转原审核页面，点「回到这段对话」后由服务端切换会话，等用户下一次发送。历史行左滑或从「更多操作」确认后可移出，原文留在本人私有存档，已有记录、待核对和用量在原处。删除当前对话时，新会话保留当前未发送文字和照片，清除旧引用。真实记录按原审核步骤保存。

冷读待办超过 350 ms 时在事项区显示读取提示。已有同账号、同日内容时继续显示。有效 AI 提交存在时才显示「AI 确认」。读取失败在本页重试，忽略失败在原提醒行反馈。

照片预览、手机聊天／待办、历史进退和补充题按空间顺序切换。两张原图交换时固定画框，待解码完成再从目标侧入场，反向接续当前姿态。聊天与待办共用一组固定标签，选中底色与文字随主题配对，同一切换保留草稿和独立滚动。

拍照任务的「改用手填」归属本餐消息。出结果后操作进入同一条核对卡。放弃识别或取消待确认后可回原草稿。核对保存和手填保存都在本餐消息显示回执，「查看饮食」打开实际保存的日期。
