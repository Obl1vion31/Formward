# 统一记录审核

AI确认页面蛋白质／碳水／脂肪最多显示一位小数并去掉末尾0，热量／消耗使用整数、身体使用两位显示。宏量手工修改最多接受一位小数，手填热量／消耗仍只收整数；计算与落库不提前取整，未修改旧值、未知与0及公开请求精度保持。不显示普通运动已完成选项。改变采用总数或运动计入值后须重新核对包含关系；自动累计不询问。应用修改仍只更新草稿。

changes.ts提供网页登录私有版本检查，change-state.ts整理新增、修改和删除；record-updates组件90秒及页面恢复检查，保存前再次核对，草稿不自动刷新。AI修改称“应用修改”，仍需底部确认保存；同一身体时段按顺序合并，后字段生效。

负责身体、摄入、食材库与消耗的混合提交、草稿核对和统一确认。`model.ts` 定义混合输入与审核视图；`operations.ts` 关联既有身体／饮食／消耗操作并在单个事务内确认；`record-review.tsx` 提供桌面和手机共用的紧凑审核页。

原始请求不可变，人工修改与取消仅影响草稿。各类内容可以独立选择；只保存摄入时由服务端保留食材快照，不强制入库。归属、授权、版本、图片安全和审计继续复用原 feature。旧链接只读展示，首次审核写操作幂等建立统一批次。测试使用虚构数据和隔离数据库。

审核信息的提交／到期时间首屏统一使用UTC，客户端完成初始渲染后采用设备时区，避免云端与手机时区不同导致水合错误；机器时间保留在time.dateTime。

公开工具输入不提供退役的日常默认动作，内部仍识别旧动作以正确分类、取消和展示旧审核。消耗按显式模式展示采用的字段及分项来源；日记录与运动仍为独立审核项，编辑只更新预览，正式确认受消耗规则版本、快照与版本共同保护。

审核先展示日期／中文餐次，再展示服务端MealView.totals的本餐kcal及P／C／F合计和食物；部分／未知／明确0保持原语义。修改前后逐餐对照，不汇成跨日批次总数。普通单餐不显示标记核对按钮或五项照片勾选，缺图可直接保存文字；底部一次确认是唯一正式保存操作。照片、依据与审核信息按需展开；缺图、冲突、过期和失败常驻。统一入口与旧饮食链接共用此界面。

消耗来源使用独立于身体的账号建议池，静息、活动合计、总数与运动共用。输入仅回显已保存值，点击展开全部历史，输入筛选，支持键盘和触屏；“×”只软移除建议，保留草稿和历史快照。正式保存成功才更新建议，普通编辑保留旧来源不会恢复已移除项；新记录或明确更换来源并保存后恢复。统一AI审核共用相同输入与事务，来源仍可留空。

重复餐次仅返回本账号匹配信息，统一显示一条中性提示和查看入口，不要求另一次进食勾选或再次确认；取消本次新增仍可用。饮食及食材移除历史倍数提醒，身体和消耗保持。审核编辑关闭前保护未提交输入，成功回执与2秒返回规则保持。

 review-summary.ts 整理回执和最近提交的业务日期／类型，不汇总跨日营养。最近提交沿用原状态，单独提供有效期与过期展示字段，排除取消和已跳过项目；所有子预览按账号读取。

AI只允许新增或修改，不得整条删除或恢复（包括批量）；餐内增减经审核且不得清空整餐。网页手工删除恢复不受影响，取消本次待保存项不删除既有记录。旧待确认申请也在实际写入前验证。

总数变化影响已有运动时，expandEnergyRelations列成独立核对项，在对应运动旁选择inclusion；修改总数会作废旧包含选择，来源备注不重复询问。energySnapshot是服务端整批投影，AI日编辑能看到完整运动，未确认不写事实。餐次变化摘要由meals规划器生成，明确增加／移除及修改后总量；照片展开后才请求。

消耗确认按业务日期分组：先显示服务器整批投影的当天总数及静息／活动分项，再列运动总数、期间静息与是否额外增加。来源、备注和原记录默认收起；无顶部批量包含按钮。组内更多菜单取消待保存内容先经应用确认，不删除已有事实。底栏区分新增消耗与更新运动数量；纯消耗保存不显示饮食记全提醒。

energy-review.tsx及样式提供消耗专用确认展示，energy-review-model.ts只比较字段、分组和组织保存范围，不重算每日合计。十进制同值不同格式不显示修改，真实小数差异按需展开原始精度；只核对包含关系不冒充热量修改。已有运动自动核对只引用id/version，省略数值与方式以沿用原值；旧复制总热量的自动草稿必须刷新并重选，原始请求不改写。活动单独提交同样返回既有day字段的服务端全天读数。

web-entry.ts仅供网页手工填写：餐次校验有效日期、非空食物和合法数量／营养，可全部未知或明确0；消耗沿用原正值门槛及旧值保留例外。web-entry-server.ts复用本人版本、请求幂等与feature换算，AI手工改餐次沿用整批食材引用；公共协议及未修改预览精度保持。

统一审核同时支持save_training_template和schedule_training；同批新模板通过templateRef引用key。训练预览投影复用training feature，保存在现有record_operations JSONB，24小时有效，原授权、归属、版本与事务保护保持。取消待保存模板会阻止其依赖排期，确认按模板后排期顺序写入，AI来源及人工修改留审计；不修改已完成训练或生成热量。plan-review在同一确认页显示动作目标、日期与修改前内容，回执直达训练页。

ai-query.ts统一AI可选的相对日期、summary／details及日历分段，不保存健康值。ai-response.ts投影任务所需结果，区分待补信息／待网页确认／过期与正式保存；旧工具未传view仍返回原结构。原业务预览、网页审核和计算保持。

reviewRecordOperation的内部AI修改上下文仅接受原授权的待确认餐次update，复核账号、meals:write、原连接／令牌、expiry与父子revision。重复修改在既有RecordItem.aiEdits记录operationId摘要，重试不再次合并、不增加revision；不提供MCP确认／删除入口。AI修改账与人工editedBy分别写入原餐次审计，payload不可变。局部修改返回仅包含目标餐次，不回传其他域内容或全部食材库。

AI字段说明由本目录的公共ai-field-definitions.json及各业务目录同名文件维护。ai-field-definitions.ts按21项工具选择字典，在MCP与HTTP成功出口附加fieldDefinitions；只解释实际存在的字段，混合记录按业务子树匹配，避免同名字段串义。ai-field-selection.mjs是正式出口与离线评测共用的选择实现。原业务对象、请求摘要、审计与正式保存逻辑不加入这些元数据。

ai-statistics.ts用四位定点整数计算查询页的合计、均值和范围，未知不补零；联合balance只纳入摄入记全且热量无缺项、消耗已知且非累计的交集。ai-errors.ts返回具体字段路径和下一步。统一提交可带previewId/revision修正同一待审批次，保持原key、类型及历史对象；复核全部原授权、版本与有效期，payload不可变，修改沿用aiEdits审计，不增加正式保存入口。

ai-tool-catalog.json提供21项简短用途目录。ai-tool-session.mjs供受控站内聊天／私有评测复用：未加载调用不执行，只给下一轮补定义；同一用户请求内相同提交复用回执，同批修正关联原草稿。每次用户请求新建session，不做跨请求记忆，不授予权限。外部GPT／豆包的工具调度由各平台控制，不能声称服务端替它们完成按需加载。

统一修正允许补齐原先遗漏的同账号、同日期已有消耗编号，身体按同日同一时段核对；已明确的历史对象仍不可替换。新餐、新运动、新食材和训练预览产生的临时编号不能冒充正式记录。失败指向具体items下的编号字段，不笼统要求另建批次。

受控会话还将同日同餐的再次新建请求指向原preview_meal_changes，补齐下一轮定义；简洁消耗的修正也指向原统一草稿。不执行被拦请求，不自动合并独立任务，含义不明时先澄清。不同餐次和新的用户请求继续独立。

编号恢复只核对数据库已保存的本人记录，不使用展示快照内的预览after；引用已有日记录的编号错误时，临时after不覆盖真实日期的展示快照；仅待核对运动包含关系的合法预览仍展示其待确认新值。遗漏或无效日编号可修正为同日真实记录，已有真实对象不得换成另一条。字段错误给出同日可用编号和版本，临时编号仍不能落成正式引用。
