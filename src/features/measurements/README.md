# Measurements

本目录负责身体指标的校验、时间归属、导入与日期时段实测写入、账号隔离、历史缺测估计及回看。体重、体脂率和 BMI 已实现；网页新增、修改、删除／恢复和正式 AI API 尚待接入，方案见 [身体指标记录](../../../docs/measurements.md)。

`assignment.ts` 按当地钟点将 06:00 前归前一天晚间、06:00–17:59 归当天白天、18:00 后归当天晚间；`time.ts` 解析 IANA 时区及夏令时偏移。精确测量时间、实际当地日期与分析归属分别保存。日期／时段来源使用 `day_period`；用户授权占位时间使用 `assumed`，两者 UTC 时刻均为空，不改变实测数值的真实性。晚间统一非空腹，白天空腹须明确确认。

`records.ts` 提供校验、事务导入、日期时段实测写入、事件和账号查询。`recordKind` 区分实测与估计，`entryChannel` 独立区分 API、人为和开发后台；设备与连接应用不冒充数据同步系统。全部写入锁定归属账号，新增或恢复实测会软删除同一时段的估计并保存审计；导入去重仍按真实来源时间，日期时段实测重复跳过、不复活删除记录。

`estimation.ts` 在最多 28 天的训练阶段内，分别拟合晨间空腹／晚间的体重和体脂率日期趋势。只用真实、有效、已选定的每日代表值，保存样本快照、系数、残差方差、样本量及双侧 95% Student-t 单次预测区间；点估计不加随机噪声，区间向外舍入。不足 3 条或拟合无效时保留缺项并报告。`completion.ts` 只在显式维护调用时修正指定阶段的实测来源、加入用户提供数值并补全空时段，绑定账号快照摘要，事务化且按请求幂等。

`days.ts` 统一配对和候选选择，实测优先，估计不会成为实测候选。`trend.ts` 提供日历区间、稀疏刻度、正常纵轴及晨晚连线；最小跨度为 3 kg／3 个百分点。实测连续段为实线，经过估计点为虚线，未补全缺口使用极淡同色点线；未解决候选处断开。`summary.ts` 始终只统计实测空腹记录，计算最新状态、截至该日的 7 日首末差、实际日均值与覆盖天数，独立于图表区间及估计开关。

`measurements-view.tsx` 与 CSS Module 提供指标切换、无框摘要、7D／30D／90D／全部／自定义、按需日期信息栏、最近 10 个记录日及原生 dialog 历史抽屉。默认 30D，晨晚及估计都显示；金色晨间主线、较淡蓝色晚间线、估计菱形及虚线明确区分。估计点的日期栏和详情显示预测区间，涉及估计的差值注明“估计差值”；详情展示来源、设备、连接应用、时间精度及模型。关闭估计影响图、最近记录及日期栏，完整历史继续保留全部记录。

抽屉仅在当前确实关闭时同步状态，忽略开发 Strict Mode 重放时过期的 close 事件，保留 Tab／Shift+Tab 循环、Escape／遮罩关闭、焦点返回与滚动恢复。`maintenance.ts` 支持快照预览、条件修正、实测候选清理、软删除／恢复；有有效同段记录时不能恢复估计覆盖它。

维护脚本见 [脚本目录](../../../scripts/README.md)。网页与后续 AI API 共用本目录规则，schema／migration 由 db／drizzle 管理，文件解析由 imports 负责。测试使用虚构数据，覆盖统计解析基准、正常／无效／重复／跨账号、回滚、实测替代估计、来源独立、占位时间、图表和抽屉；浏览器入口见 [测试目录](../../../tests/README.md)。
