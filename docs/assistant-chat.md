# 站内助手聊天

后台生成采用持久任务：接收消息时固定模型与附件来源，独立worker执行，页面只订阅。切后台、断网、刷新或收起助手后任务继续；恢复前台读取同一任务，不重新发送。停止按钮仍取消真实任务。进程异常不自动重跑，费用未知继续预留，旧结果和预览可核对。图片先核对归属、大小、格式和SHA，失败明确报错；逐次诊断仅在私有运行记录保存模型、请求阶段和图片摘要。


会员档位独立于管理权限。Free聊天锁定并标Plus，可手工记录、使用提醒和已开放设备接入，每日可识图4次；内测账号聊天与识图共用¥1，Plus及指定有效owner共用¥2。Pro预留且不可分配。现有及新建普通账号默认Free。千问、小米MiMo使用同一段可读对话和正式业务工具，不自动转交或重试。

## 提示词与工具

当前正式协议为MCP2.0.2，站内助手通过同一目录按需加载18项业务工具。千问使用original长版、小米compact精简版；智谱仅保留历史适配，新调用停用；共用生成器records/ai-prompt.mjs提供正式业务规则，再附站内补充、引用和私有附件说明。模型默认准备最近10组完整问答、当前任务与引用；上下文数量和模型参数保持；共用提示词修订2026-11-16-energy-macro-completion-v1增加同口径能量与两项宏量反推唯一缺项的说明，同时保留原文冲突时等待用户选择、合法来源说明保留原文的要求。无充分依据、明确不估算或特殊供能时保持未知。

新增餐次使用preview_meals，正式餐次修改使用preview_meal_changes，食材维护使用preview_foods；get_preview统一查询预览状态，update_preview修改原草稿及补照片，preview_record_bundle只用于至少两类功能的组合任务。受控会话生成稳定请求编号，重试复用原结果；来源、授权、归属、版本和最终人工确认保持。完整工具与已知边界见[AI调用规则](ai-tool-contracts.md)，模型回答质量与链路验收分开记录。

## 业务和授权

chat-tools通过进程内MCP适配器发现现有18项业务工具，按需定义、错误补定义和同题草稿协调复用records/ai-tool-session.mjs。网页、外部AI和站内助手继续使用同一套查询、版本、营养、预览及人工确认规则；load_tools和request_followup只是站内控制工具，不新增公开业务工具或scope。历史修改先查询最新对象和版本，AI不得整条删除。外部AI仍在原网页审核；站内AI通过聊天内卡片调用同一人工审核服务，保存仍来自已登录用户的明确操作。

千问与小米分别关联独立ai_tokens及assistant_connections，既有智谱关联保留用于历史追溯，Free饮食任务使用单独purpose=meal_entry且仅限meals的令牌，首次发送创建已授权的站内连接，有效期30天。数据库只保存随机原文的摘要；站内执行使用已验证会话与本人连接引用，不向浏览器发放Bearer原文。撤销、到期、停用或账号访问失效阻止后续工具调用；恢复须在连接详情明确启用，创建新授权，不复活旧令牌或旧预览。原授权关联保留以追溯“千问／小米MiMo／智谱 · 站内助手”来源。

照片复用私有meal_images上传和读取，最多8张，单张20MiB，仅JPEG／PNG／WEBP。消息保存附件ID，不保存公开图片地址。模型调用由服务器读取本人附件并传输；补充或引用时只带相关原图。已有清理脚本仅处理未登记对象，聊天中已登记原图同样保留，不因尚未关联正式餐次而删除。

## 每日用量

内测两家可用模型及历史已用费用合计每日¥1，Plus及指定管理员合计每日¥2，按每次模型请求开始时的北京时间归属日期，零点重置。模型菜单顶部展示扣除已结算、预占及待结算费用后的当日共用可用额度百分比，以及北京时间重置时间。正值低于1%显示「<1%」，耗尽为「0%」。服务端用未取整余额判断预算。

服务器在账号锁内按未命中输入上界、图片保守估计及8192输出预占，再按usage结算；同一请求只结算一次。明确HTTP拒绝释放预占，网络中断、停止或没有可靠usage时保留待结算，不将未知伪装为免费。刷新、打开助手、切换、结算、恢复前台及日界同步用量，读取失败保留原值并提供重试，不闪现0%。预算与私有模型评测分开。

平台余额、限流、凭据、网络、超时与站内额度分别说明。未确认原因显示通用故障。单家失败后由用户选择其他模型；站内共享预算不足则暂停三家新请求，提醒、历史和手工记录保持可用。停止和刷新均不自动收费重发。

## 饮食页内识别

私有GET／POST /api/assistant-meal管理本餐识别任务，沿用有效登录、最新档位、同源写入、附件归属、每账号单生成及共享日预算／免费计次。Free必须有本人本餐照片，不能通过此入口使用无图片通用聊天。create绑定draftKey及当前草稿；run调用同一生产适配器与流，模型选择只属于本餐任务，不改主聊天；apply仅返回待核对草稿；save经原审核服务更新草稿并确认；stop停止生成、cancel取消本次识别；enable_model／revoke_model管理本人当前任务模型的30天授权，恢复必须明确操作。生成结果本身不保存正式记录。

任务使用assistant_conversations.purpose=meal_entry、active=false及私有context，不替换主聊天的当前会话。context保留原手工草稿、当前绑定、附件引用、预览及实际提供方。模型仅能为当前餐次提出新增食物，目录限preview_meals、get_preview、search_foods与站内补充；日期、餐次及已有手填由应用固定合并，不信任模型覆盖。重复识别扩展同一预览；有预览后沿用其模型授权，不借切换复活旧授权。原始草稿与AI及人工修订可审计。

本餐手填始终保留。电脑库选和填写并排，手机食材库在当前餐次上方原位展开；不使用互斥的自己填写／食材库标签。每项营养独立原位展开，打开另一项不关闭当前项；三个主字段及四项营养正常字号同排，文字放大或长数值可换行。拍照录入有明确入口与返回本餐，添加食物直接增加手填项。通过同一个原生照片选择框选择相机或相册后复用原图字节上传、真实百分比、核对、取消／重试及国内手动备用通道。识别有独立任务与当前草稿签名，迟到结果不能覆盖新草稿，取消或失败保留原手工填写。回填后最后一次保存走原归属、授权、期限、版本和幂等检查。AI确认内的嵌套编辑不再次提供拍照入口。

## 聊天交互

桌面浮窗860px，左栏常规312px。左栏提供日常待办、AI确认和常用功能。餐次营养摘要在可用宽度内同行显示，长值按项换行。右栏为聊天，正文与输入栏侧边对齐。手机底栏直达独立助手页，聊天／待办与返回及历史使用同一条头部。有聊天权限时默认进入聊天，其余账号默认进入待办。业务页进入后返回原日期、筛选和位置，直接访问时返回总览。历史通过同一消息布局展示原话、附件、引用、步骤和只读记录摘要，由用户点继续才切换会话。输入主行是加号、文字、模型、发送。选好照片后缩略图在左上方，长文字在输入框内增加行数。触摸高光从接触位置横向铺开，移手时小幅跟随。模型菜单从当前按钮上方 8 CSS px 处展开，矮屏时可在菜单内部滚动，生成时仍可查看额度。手机键盘变化时只收缩内容区，顶栏与工作区锚点保持。文字框、照片行和附件区保有各自的手势，只有从消息区起滑才会翻动聊天。手机引用和复制为所属回答的图标操作。实际属同一补充任务且模型相同的连续回复只在首条标明模型名，每条保留时间和过程。向下按钮悬浮。

用户气泡随内容宽度，发送约180ms轻位移，本地待发与服务器用真实请求ID对齐，历史恢复不重播。引用只在完成回答下。查询链接及确认卡等到回答结束后出现，卡片复用RecordReview及web-review，确认保存与本次不保存同级；复杂内容展开原审核。卡片读取失败可打开原网页；网页和卡片不能并发绕过版本、到期、撤销、来源或幂等校验。减少动态效果即时呈现，工具摘要不包含原始内部推理。

## 来源补充与业务摘要

测量来源问题声明binding={kind:measurement_source,date,period}。服务器按本人近30天真实实测记录取最多4项仍有效来源，最近7天优先；已移除建议不显示。候选不是白名单，用户自由填写的合法简称不扩写型号；只有明确选中历史完整名称时才采用全称。答案保存原始文本、选项、字段类型和真实任务引用，同链后续补充及重试继续可用；新话题不继承旧答案。创建或局部修改预览再次核验同日期／时段，来源贯通预览、保存与审计，不能只放进一句聊天后重新猜测。

补充卡一次显示一题。短选项可双列，允许手填时直接显示输入框。选「不知道」后下一题，或按「跳过本题」直接推进。服务端按任务、字段及来源绑定保留已知、跳过和明确未知；「跳过全部」保留已有答案并停止本任务追问。整组统一提交，已补充摘要在原助手提问下展开。保存依然使用正式人工确认。

## 发送与增量回复

发送后本地照片和文字立即进入同一条右侧消息，授权原图就绪后交接。手机记录键盘收起前的可视视口，恢复稳定后缩放一次。网页按运行编号和正文偏移订阅真实分片，初末快照恢复状态，静默期间保活。同类工具展开能看各次实际结果。任务领取时间为处理计时起点，等待补充或工作结束收起。明确标记的正文逐段展示，未标记的内容在结果确认时呈现。

点停止会匹配当前会话和本次运行。接收确认尚未到达时先等待该条确认，结束快照到达就收起停止按钮。停止响应中断可以点「重新读取对话」查看真实状态，读取失败可在原处重试。已有正文、草稿和附件保留。

模型输入保留本轮内容、任务原文、已补充字段、明确引用和待确认预览。超过预算先减少较早可选历史，再缩减过长的工具列表并标记省略。原聊天记录与附件持续保留。同一条允许最多八张照片。三张起在缩略图下提示「发送后分批读取」。一次写完整说明并发送，后台依序每批读取最多两张，单次输入空间只够一张时按单张读取。每批沿用完整说明，后续批次可参考已有观察。所有照片读完后，用可核对的文字证据统一回答；同餐生成一张待确认卡并默认关联全部原图。用户确认后才写入一餐。

读数紧跟原消息显示，与实际任务计时同行。失败或停止后从原回复续读剩余照片，汇总失败后可重试汇总。检查点保存在任务已有数据内，聊天快照及SSE只公开读数和阶段。恢复同一任务时复用已完成的批次和记录卡。旧手动分批入口可继续处理之前未读的原照片。

## 原图与网络切换

每批上传重新探测服务器提供的受控空入口，首个可达通道立即接管；失败使用入口默认。自动结果不跨批持久保存，回国、换网或恢复前台后的新批重新判断；已开始的传输不自动换路。人工换国内／国际仅覆盖当前批或重试，历史照片位置不变。

聊天与饮食使用同一上传器；原图一次读取、真实百分比、10分钟总传输、60秒无字节停滞、15分钟凭据，100%后核对成功才就绪。每张可取消／重试，国内可人工同源备用；国际不经过旧4MiB兼容入口。照片说明保留既有算法，手机助手页按系统键盘占用后的可用高度安放输入与消息，顶栏固定；隐藏的拍照内容不参与视口监听和定位，草稿与焦点继续保留。

新调用只开放千问original与小米compact。智谱通过既有FORMWARD_CHAT_GLM_DISABLED开关停用，默认停用；旧偏好显示千问但不重答，历史标识、授权和费用保留。补充复用原任务绑定与来源原文校验。共用营养规则允许同口径总能量及两项宏量反推唯一缺项，结构化数值与依据分别填写；多项缺失且无依据、冲突、特殊供能或明确不估算仍保留未知。服务端不自动补值，手动录入不变。

## 单次上下文与历史管理

普通聊天的单次模型请求上限为50万估算单位。当前图文、相关历史、系统说明及工具结果占用输入空间。查询饮食的站内模型请求只带一份餐次明细，结果回执和MCP契约保留完整内容。临近上限时按下次请求的预计峰值提示，未选图时给一张图及普通工具增长预留约10万。选图后按直传或分批的实际路径计算。发送仍可使用。

两张图通常直接进入聊天工具轮，三张及以上自动分批。后续轮次仍超限时，在同一任务复用已完成的查询和已有预览，必要时自动切换一次分批读图。已获得的照片观察复用，之后以文字证据汇总，原图继续用于预览关联。较早问答按需整轮清减，部分查询明细标明实际覆盖范围。

原回复中断后保留正文及真实审核卡。「新建对话」打开空白会话。「新会话继续回答」在同一次站内操作中建立新会话和后台续答任务，无需再发一条消息。新会话携带原问题、日期时区、照片及有效的检查点；刷新和同一操作重试接回同一个任务。已有待确认或已保存预览沿用原审核编号和当前状态。记录版本、权限和人工确认仍由审核服务验证。旧待发送引用仍可继续查看、取消和发送。

历史的「回到这段对话」只激活本人会话。删除会话经过人工确认，仅移出历史与可继续范围。旧消息作为私有存档保留，健康记录、审核及用量继续独立可查。移除时间由0046迁移新增，公开启用前保留同样识别移除状态的兼容回退包。
