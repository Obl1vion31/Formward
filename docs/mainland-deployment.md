# 国内服务器与双区部署

## 目标和阶段

国内节点使用上海腾讯云轻量应用服务器：2 核 CPU、8GB 内存、80GB SSD、Ubuntu 24.04 LTS x86_64。现有国际站继续由 Vercel、Neon 和新加坡 Private Blob 提供服务。第一阶段在国内服务器建立通过 SSH 验收的独立环境，并验证生产数据库备份能够完整恢复。

最终目标是两个入口使用同一账号和同一份记录，国内 PostgreSQL 为唯一权威数据库；国内新图片进入上海私有 COS，国际图片保留在 Blob。两个入口共享数据并不意味着国际图片在国内必定能读取，也不意味着两个节点具有独立容灾能力。

服务器准备、图片双存储、双区业务路由和正式数据切换分别验收。仅部署第二套应用不会自动完成账号互通、OAuth 迁移或图片复制。

## 服务器部署安排

| 部件 | 安排 |
| --- | --- |
| Node.js | 使用项目固定的 24.21.0，运行经过本机构建的 standalone 发布包 |
| 应用进程 | 独立 `formward` 系统用户，systemd 管理启动、退出及失败重启 |
| 反向代理 | Nginx 负责请求转发；保留流式响应，覆盖可信 Host 和来源 IP 头 |
| 测试访问 | Nginx 仅监听 `127.0.0.1:8080`，应用仅监听 `127.0.0.1:3000` |
| 本机验收 | SSH 将本机 `127.0.0.1:3300` 转发到服务器 8080；使用该地址登录 |
| 数据库 | PostgreSQL 18，与源 Neon 主版本一致，仅允许本机连接 |
| 测试数据库 | `formward_preview`，只有虚构账号和健康记录，独立认证 secret |
| 恢复演练数据库 | `formward_rehearsal_*`，只用于备份一致性核对，不连接测试网页 |
| 发布目录 | `/srv/formward/preview/releases/` 保存版本，`current` 指向当前版本 |
| 运行配置 | `/etc/formward/preview.env`，root 可读，由 systemd 注入；不放入发布包 |
| 防火墙 | 准备阶段仅放行 SSH；网页和数据库通过回环地址访问 |

| 自动备份 | 每日只备份 `formward_preview`，私有目录保留 14 天；至少实际取回一份至本机；不覆盖演练库或未来正式库 |

源码和配置入口见 [服务器维护工具](../scripts/self-hosting/README.md)。部署包显式列出需要的文件，不将 `.env*`、私钥、`data/` 或本机工具打包。正式域名启用时，需要另配置 HTTPS、固定可信域名和 80／443 入站规则。

## 数据库工作

1. **确认源库条件**：只读获取 PostgreSQL 版本、编码、locale、扩展和表结构，不修改生产数据库。当前源为 PostgreSQL 18.6、UTF8、C.UTF-8，仅使用 plpgsql。
2. **制作一致性归档**：在只读 repeatable-read 事务中导出快照，让 `pg_dump` 与源库摘要读取同一快照。保留 `public`、`drizzle` 全部表、数据、索引、约束及序列。
3. **恢复到空演练库**：目标必须是回环连接的 `formward_rehearsal_*` 空数据库。使用单事务恢复，不覆盖已有数据库，不复制 Neon 平台角色及 ACL。
4. **逐项比对**：核对表、字段、约束、索引、序列、迁移账本及全部行的规范化摘要。时间戳与 numeric 由数据库生成规范文本，避免 JavaScript 时间精度损失。
5. **业务测试另建库**：测试网页只接 `formward_preview`。使用虚构 owner、普通账号和样本，验证实际登录、保存、授权、撤销和导出。
6. **检查恢复能力**：验证每日归档能够再次恢复，并在重启后核对数据库及应用状态。

原有 `backup-database.mts` JSON 快照适合项目惯用审计，但缺少完整对象定义，不能单独承担无损迁移。新增演练工具及参数见 [维护工具](../scripts/README.md)。原生数据库归档同样不包含 Blob 或 COS 的图片原件。

数据库备份包含账号哈希、授权及健康记录，保存到受限私有目录，不输出行值或提交 Git。服务器同盘归档只能覆盖部分误操作；COS 就绪后还需配置加密的异机副本、保留策略和定期恢复验证。

## 国内图片与国际图片

当前应用仍使用 Vercel Blob，国内测试环境没有生产 Blob 身份。图片功能必须在真实 COS 接通后单独验收，未配置存储时应明确失败，不产生伪成功图片记录。

后续实施内容：

- 上海 COS 使用私有桶，凭据采用桶及必要操作范围内的最小权限。
- 新增 Drizzle migration 保存图片 provider 和存储定位，旧记录明确保持 Blob。
- 签名、浏览器直传、完成登记、读取、删除和失败清理按服务端记录选择存储；继续保持 20 MiB、真实字节校验、账号归属和撤销后的事务复核。
- 国内无法获取海外原图时说明失败；经用户确认后转国际图片处理节点重试，沿用同一草稿、账号和幂等标识。
- 同账号同 SHA 的去重可能返回原有国际图片，不能把这种结果描述为已经复制到 COS。
- 两区共享文字记录；海外原图连通性另测，自动双向复制图片不属于第一阶段。

## 双区账号和业务接口

当前页面、Server Actions、HTTP API 和 MCP 都直接调用 feature 与数据库。双区需要增加受限的服务间调用，让国际节点访问国内统一业务能力；不向公网开放 PostgreSQL。

正式设计需落实：

- 两个网页入口各自拥有 host-only 会话，共享账号、密码及记录；网页的入口选择不能自动改变已连接的 ChatGPT MCP 地址。
- OAuth issuer、MCP resource 和 token audience 按确定的入口验证，旧国际连接的延续或重新授权需要明确处理。
- 登录、owner 十分钟再次验密、邀请／重设链接、停用和访问版本在两区一致；跨节点调用不能只凭任意 `userId` 或未经验证的转发令牌。
- 写入、图片登记及审核确认仍进入同一套 feature 事务，保留行锁、幂等和撤销检查。
- 实测国际节点到国内服务的时延、失败和恢复。上海服务器已经出现访问现有 `vercel.app` 超时，不能假设两边天然互通。

## 域名和备案办理顺序

1. 选择支持 ICP 备案的自有域名，直接在腾讯云注册便于统一管理。实名主体与实际备案主体保持一致；腾讯云建议域名实名完成后至少等待三天，让信息同步至工信部。
2. 在[腾讯云 ICP 备案控制台](https://console.cloud.tencent.com/beian)输入主域名，按系统判断办理首次、新增或接入备案，关联已购买的上海服务器。备案省份依主体资料及当地规则，不能根据服务器地域猜测。
3. 如实填写 Formward 的饮食、运动、身体指标记录功能及多用户使用方式，由备案审核确认适用的主体及服务分类。本人完成证件、人脸、电话和短信核验。
4. 腾讯云初审通常 1–2 个工作日；提交管局后收到核验短信需在 24 小时内处理；管局审核通常在 20 个工作日内，补件时间另计。
5. 备案通过后再正式开放国内网页，配置 HTTPS、ICP 页脚查询链接，并在网站开通后 30 日内办理公安联网备案。

域名结构可采用同一域名下的 `cn` 和 `global` 两个子域名。`cn` 的 A 记录指向上海公网 IP；`global` 在 Vercel 添加后，采用平台实际给出的 DNS 记录。登录页的选区入口和生成链接必须使用已确认的地址；现有 MCP 地址不能因为改 DNS 就自动更换认证身份。

参考：[腾讯云备案流程](https://cloud.tencent.com/document/product/243/18909)、[首次备案](https://cloud.tencent.com/document/product/243/97668)、[备案域名准备](https://cloud.tencent.com/document/product/243/18905)、[域名及网站信息要求](https://cloud.tencent.cn/document/faq/243/19644)、[公安联网备案流程](https://cloud.tencent.com/document/product/243/19142)。

## 正式切换条件和顺序

正式切换需要同时满足：域名及备案就绪、COS 真正接通、双区账号与业务路由完成、跨境路径实测通过、实际网页经用户验收，以及正式库自动备份、加密异机副本与实际恢复验证就绪。当前 timer 只处理预览库，正式库须单独配置并验收。服务器测试环境搭建完成只代表基础条件就绪。

切换时统一暂停所有生产写入口，包括业务保存、登录、会话续期、退出／撤销、OAuth 刷新、限流写入及后台任务，等待已进入的事务结束后再制作最终备份。恢复到正式库并核对全部数据及授权状态，再同时切换国内／国际入口的数据来源。保留原认证 secret，重新核对域名相关的 OAuth 身份。停止旧实例并撤销旧 Neon 应用角色的写入能力，Neon 保持受控备份状态，避免两套库同时接收写入。

目标开始产生新记录后，回退必须先同步新增记录与撤销状态，不能直接切回旧 Neon 快照。回滚保留停用、访问版本、迁移结构和审计；出现问题时先关闭相关写入口并修复。

验收至少覆盖：数据库完整恢复、真实账号流程、文字保存与导出、图片真实读写、跨区授权及撤销、网页和数据库重启恢复、独立备份恢复，以及桌面／手机实际页面。虚构数据截图、运行报告及备份保存在私有目录，未测项如实列出。
