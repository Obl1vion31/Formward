## 已修正的问题

| 问题 | 修正与验证 |
| --- | --- |
| 聊天和AI JSON超限后等待取消，取消失败会盖掉413；安全／AI读取锁未完整释放 | 共用有字节上限的流读取，在拼接前拒绝超限。正常、恰好上限、分块中文、空／无效JSON、读取错误、取消拒绝与取消不结束均验证。保留各入口原有错误约定。 |

| 豆包与Garmin在异常清理时等待上游取消 | 清理不覆盖原错误或阻塞返回；Garmin认证拒绝和4MiB超限有回归覆盖。 |
| 旧COS SDK与部分传递依赖含已公开安全问题 | COS升级至3.0.0，移除旧request／配置依赖链；Zod使用4.6.7，旧4.x统一兼容补丁；undici 6.29.0和source-map-js 1.2.1分别固定到6.29.1与1.2.4。COS本机HTTP验证上传签名、中文对象键、私有URL、列表及删除。 |
| README结构检查把Python字节码和工具验收目录误当源码目录 | 跳过`__pycache__`与`.impeccable`工具资料，继续检查项目自有目录，结构检查通过。 |

请求和响应的六处手写读取循环收敛为一个实际复用的读取器。没有为测试辅助函数的少量重复建立额外框架，也没有拆分已有保存事务来追求复杂度数字。非测试函数复杂度超过25的候选仍为92处；这不是新发现的92个缺陷，后续按实际功能改动处理。
