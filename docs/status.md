## 当前产品决定

身体记录正文最大 1120px 并居中，同时展示六项实测摘要，当前体重和当前体脂率同等突出、等宽；下方体重图与体脂图常驻，纵轴独立，共用日期、晚间、估计及“估算规则”，默认 30D。最近记录为五列、晨晚各两行读数，逐值标识实测／估计，点击直接进入正确记录与指标，差值只统计真实配对。漏记日期从账号／记录／已保存日期的最早一天补到今天，只在展示时推导；最近 10 个日历日，完整历史每批 50 日期，可加载更早日期并补记。所有日期统一行高、边界和分隔线，桌面查看与状态按钮同排，手机上下排列。统一 Inspector 320ms 滑入、240ms 退出，渐变遮罩同步淡入淡出，结束后恢复滚动与焦点，减少动态效果设置下直接开关。沿用石墨、暖白、金色、冷蓝。 每行常驻“查看”；今天无实测显示“录入”，过去无实测显示“补录”，已有任意实测显示“编辑”，只有估计仍按日期显示录入或补录。桌面按钮同排，手机上下排列，每个按钮点击高度至少 44px，行高统一且不横向溢出。

四项可独立保存，包括仅体脂；晨间固定空腹，旧非空腹／未知条件只读，晚间固定非空腹。每个空项旁独立估算，草稿不参与计算；先保存实测，再估算剩余项。表单末尾仅“保存录入”，下划线距文字 4px，错误与操作结果在按钮之前。页面没有自动弹窗、新增日期或跳过入口；日历空行只在展示层推导，已有日期与提醒状态保留。历史修改携带 updatedAt 防止覆盖并发写入，遗漏字段保留、显式 null 清空，每条实测至少一个主要指标非空。冻结历史允许实测补录，禁止新增或重算估计。 晨间、晚间各自填写数据来源，只回显已保存来源，未知来源保持空白；点击后提供按最近使用排序的历史建议，支持自由输入及本账号历史建议的鼠标、触控和方向键／Enter／Escape。来源随实测成功事务保存，草稿与失败不更新历史；来源必填不约束估算。已有实测允许只改来源，保留原录入入口、准确测量时间与原始输入，并保存修改审计。设备与连接应用合成 `device_label` 名称快照，修改某条记录不影响其他记录。

首页按用户确认采用 Newsreader 主词、统一轨道标注和默认隐藏输入底线，人物、Logo、构图与转身节奏保持。身体估计区分正常 morning-baseline-v3 与一次性 historical-initialization-v1，体重、体脂独立。正常只用此前 28 天真实记录，至少 3 配对日取中位差，晨间最近最多 7 日、至少 3 日、距最新不超过 7 天；只有晚间且配对不足时可用晨间趋势备用。

指定账号 2026-09-09 至 10-06 已完成一次性初始化：统一全范围真实配对、相邻晨间插值和受限边界外推，允许已存在的后续真实数据。12 条旧估计软删除，27 条初始化估计（晨间 21、晚间 6）有效；重复实测保持软删除。整个范围冻结，补录只替代对应时段／指标，其他估计保持。真实原始字段、来源及准确时间未变，私有备份和完整报告保留。初始化权限和实际未来数据使用保留在私有报告；普通 Inspector 展示用户可理解的依据与参考列表。

所有归属按测量地当地时间：06:00 前归前一天晚间，06:00–17:59 归当天白天，18:00 起归当天晚间；真实时间、当次时区与唯一记录日期分别保留，实际发生日期从来源时间读取。用户已确认这批记录为 Asia/Shanghai、白天为空腹，现有和以后晚间统一非空腹，来源为 `evening_rule`。晚间条件与准确时间确认保存事件，原始文件未改变。每日分析区分 D 日晨晚差对照 D 日盈余，以及 D+1 日空腹变化对照 D 日盈余；当前展示实测及明确标记的历史估计，饮食与全天消耗未接入。

## 已实现

- `0007_strong_omega_sentinel.sql` 已在实际数据库执行：测量主表 30 列，measurements 与 measurement_days 使用唯一 record_date，实际发生日期从 source_local_time 读取；准确时间、跨午夜原分组及历史 JSON／幂等键保持。迁移前校验旧实际日期与来源时间一致，异常停止。9 张业务／认证表和全部 99 条测量记录按日期列转换后逐字段一致，私有备份和核对报告保留。旧维护 JSON 可读、已执行旧批次返回原结果。
- `0006_living_tarantula.sql` 已在实际数据库执行：移除 BMI，设备／应用合并为 device_label，增加四列 measurement_sources。当前账号 3 条未知来源实测已补齐并审计；私有一致性备份与逐字段核对确认数值、准确时间、原始输入、旧键、冻结依据、日期与旧审计保持。`sources.ts` 与 `source-input.tsx` 提供事务化来源历史及键盘／触控建议，完整字段与关系见 [数据库字典](database.md)。
- `measurements`、`measurement_imports`、`measurement_events` 与 `0001_broken_moira_mactaggert.sql` 已建立身体测量、导入批次和写入快照。TSV 支持体重与体脂率，缺项为空；时区与夏令时由统一 feature 校验。同一文件重试与重新排序的相同记录不重复，冲突事务回滚，不覆盖既有修改或复活软删除记录。
- `/dashboard` 在当前会话下读取本账号测量、已有日期状态与账号创建时间；展示六项实测摘要、独立纵轴双图和五列最近 10 个日历日。数据缺项保留空值，日历空行不写库；同段多候选只有明确代表选择才改变摘要、图和表。无记录账号可以从四项表单开始录入。
- `estimation.ts`、`estimate-records.ts` 提供晨间基准估计及明确操作后的逐项／批次估计；真实与估计按指标选择，不把缺失体脂当作缺失体重。`completion.ts` 预览／执行来源维护与空缺补全，`rebuild.ts` 提供冻结外正常重建，`initialization.ts` 提供一次性预览／执行与持久报告；账号锁、幂等、软删除和完整审计保留。0005_medical_beyonder.sql 已在实际数据库执行，允许仅体脂实测；每条测量至少一个主要指标非空，空白日期和当天停止提醒单独存入 measurement_days，请求内容摘要支持幂等校验。0004_dapper_valeria_richards.sql 已执行，批次初始化元数据保存冻结范围与报告，部分唯一索引保证每账号仅有一次初始化。
- `editing.ts`、`entry-state.ts`、`measurement-entry.tsx` 与 dashboard Server Actions 已接入四项部分录入／仅体脂、逐项估算、版本化历史编辑、日历空行补记和晨间空腹校验；网页只暴露保存与估算，所有操作验证会话与账号归属，普通写入不自动估算。
- `maintenance.ts` 与 `scripts/maintain-measurements.mts` 提供账号快照预览、条件修正、保留较早候选与软删除／恢复。摘要绑定账号和记录当前状态，预览后变化拒绝写入，操作事务化、幂等并保存前后快照；维护不会在页面加载或导入时自动执行。
- `code-study.md` 按页面上可见的功能解释代码用途、识别线索和修改影响，包含样式的具体例子、登录与数据流程、修改位置速查和检查入口。首页、配置、测试与维护脚本有中文注释，CSS 按功能分组展开。
- 数据层使用 PostgreSQL / Neon、Drizzle 与 Better Auth。版本化 migration 建立内部账号与会话表，密码保存 scrypt 哈希；公开注册关闭。`/dashboard` 每次请求验证当前身份并提供退出登录，按账号显示测量或无记录空状态。配置与维护命令见 `auth-setup.md`。
- 共用数据库入口将 Node 进程的单地址连接尝试时限设为至少 1000ms，避免跨区域网络在默认 250ms 下提前终止可用连接。数据库连接时限为 15 秒，保留环境中更长的单地址设置；修改配置或连接代码后需重启开发进程以更新缓存连接池。
- 运行框架为 Next.js 16.3.7 App Router、React 19.3、TypeScript 和 Tailwind CSS 4。动画使用浏览器内置 rAF、HTMLVideoElement 和 WebGL API，没有新增运行时依赖。
- 首页采用“数字雕塑 + 编辑式界面”。素材就绪后显示同级单行的 Discipline / NUTRITION、Drive / BUILD YOURSELF、Effortless / AI LOGGING；主词为本地 Newsreader 正体 400、自动光学尺寸、0.035em 字距、1.2 行高与暖灰白，桌面 20–26px、手机 14px。哑金副标签及 SCROLL 使用本地 IBM Plex Mono，Logo 和产品 UI 沿用系统 sans serif。桌面棕金轨道随人物同一 500ms 游标转动 150°，节点、上方引线和下方两级文字共用空间坐标；文字距节点水平线 12px，引线距文字边缘 12px，左右对齐连续插值。完整标注尺寸在字体就绪与视口变化后缓存，不逐帧读取布局。登录终点为 Discipline 右上、Drive 右下、Effortless 左侧；标题及轨迹减弱，微标签至少保留 84% 亮度。手机保留底部三列，位置不随转身变化；reduced motion 使用 180ms 两套静态构图交叠。登录与认证保留终点，失败保留，成功后随最终人物动画淡出；加载及素材失败时隐藏，辅助技术只读取一份文案。末段平滑为表单让出 24px 间距。文案表达产品方向，饮食、运动和正式 AI API 尚未实现。
- 首页是深石墨色的中央人物舞台，躯干后方有微弱暖金环境光与宽幅暖色层次，侧下方叠加极淡 petrol；文字和控件使用暖象牙白与哑金。第一屏显示左上角 Logo、居中人物和左下角 SCROLL TO ENTER；提示固定为 7% 左边距。提示为 IBM Plex Mono 8.5px 暖金文字、75% 透明度与 1×26px 细轨道，7px 动标每 1.6s 轻移 12px。仅在图片就绪、INTRO、宽度超过 700px 且支持精细指针悬停时显示。停在 INTRO 时持续显示，鼠标移动或未触发播放的输入不会隐藏；离开 INTRO 后 120ms 淡出，每次倒放完整回到 INTRO 都重新显示。加载期间的操作不影响回到首屏后的显示。加载与失败文字独立保留。
- 人物外层支持极弱反向鼠标视差：INTRO 最大水平 6px、垂直 4px，朝鼠标方向倾转最多 0.6° / 0.3°。90ms 时间常数跟随，静止 180ms 后以 600ms smoothstep 回中，静止后停止 rAF。正放、倒放和最终过渡暂停联动，播放开始时在 100ms 内回中；LOGIN_READY 未填写时与 FINAL 输入框失焦时允许半幅联动，只接收新的鼠标移动。Logo、背景、Login 和提示不随人物移动；触屏、窄屏、reduced motion、窗口失焦及页面隐藏均归零，鼠标离开舞台缓慢回稳。
- 页面滚动区域约 155vh，视觉舞台以 100svh sticky 固定在视口中。桌面和窄屏表单均位于液态尾部前方，保留肩背与腰线；静止时只显示 Email、Password、输入内容和 `ENTER`。输入底线默认透明，保留 1px 占位，仅可操作字段 hover / focus 时在 180ms 内显现；键盘保留焦点框，触屏点击标签可聚焦，reduced motion 即时改变底线。暖烟色衬底使用 10px 背景模糊，边缘渐隐，没有外框、标题、说明或实心按钮。ENTER 为 15px 哑金文字与短下划线，禁用时仍保持可辨认；表单按视口高度向尾部下方定位。
- `PRE_LOGIN_FRAMES` 仅包含原来的 1.png 与 12.png 静态端点，`FINAL_FRAME` 独立指向 13.png。中间动作使用 `golden-turn-1s-v6.mp4` 生成的 60 帧播放视频，页面按 2 倍速在 500ms 内完成转身；正倒放共用同一时间游标，中途可反向，同方向惯性不重启。静态首尾及第 13 张的校准、鼠标联动与认证流程保持原有行为。
- 状态为 INTRO、FORWARD_ANIMATING、LOGIN_READY、REVERSE_ANIMATING、AUTHENTICATING、FINAL_TRANSITION、FINAL。滚轮在 250ms 内同方向累计 44px，触控累计 40px 后选择目标 0 或 1；手势不提供播放进度。监听在认证开始时暂停，失败时恢复，滚动边界不会阻止方向触发。
- 视频使用逐帧关键帧以便双向寻帧；未完成的寻帧合并到最新目标，黑色背景以 WebGL 转为透明 Canvas。首尾各 40ms 与原图按互补权重混合，原有隔离人物组和 `plus-lighter` 合成继续使用，背景与表单保持独立。播放文件为 960×1440，制作入口为 `scripts/prepare-turn-video.sh`。
- Login 的透明度与位移直接映射 `animationProgress`：前 60% 时间隐藏，接近背面时在最后 200ms 淡入并上移 16px，Frame 12 完整进入。表单本身不缩放或模糊，倒放同步隐藏，只有 LOGIN_READY 可提交。首次聚焦 Email 或 Password 后以 180ms 回中并锁定整个 LOGIN_READY；切换字段、失焦、点击空白或移动到 ENTER 都不解除。完整倒放回 INTRO 或进入 FINAL 后解除阶段锁定，FINAL 的输入焦点仍暂停联动。Email 和 Password 在倒放后仍保留于组件内存。
- 停在 12.png 且两项输入非空时，点击 Enter 进入 AUTHENTICATING 验证账号，禁止重复提交与方向输入；验证成功后再进入 700ms 的 FINAL_TRANSITION，交叉过渡到 13.png，伴随轻微 scale / blur。若快速提交时回中未完成，立即归零再开始过渡，不增加等待时间。最终过渡开始后拒绝方向输入并移除手势监听；最终动画结束事件触发后进入 `/dashboard`。失败显示中文提示并返回 LOGIN_READY，密码不保存到浏览器持久存储。真实账号、scrypt 凭据哈希与会话保存在 PostgreSQL / Neon。
- 运行时三张静态 PNG 通过静态导入设置 Next.js `preload` 并全部解码，视频以 `preload="auto"` 提前准备。全部素材就绪后才启动播放，加载期间的最近方向会自动执行；图片或视频失败都保持原始首帧并显示刷新提示。
- 1、12、13 的原始 PNG 与桌面、移动端校准保持不变；其他原图保留为素材，不再加载。视频首尾有额外画布留白，独立按头顶和尾滴匹配静态端点，参数见 `turn-video.ts`；原图测量与视频校准见 `frame-calibration.md`。
- SCROLL 提示仅用于视觉引导；键盘用户可通过聚焦时才显示的“进入登录”入口触发，完成后自动聚焦 Email 并锁定居中。页面方向键、PageUp / PageDown、Home / End 和 Space 支持双向播放，输入框、按钮及可编辑内容中的键盘操作不会改变动画。手机键盘改变视口不会自动倒放。
- reduced motion 保留双向交互：180ms 首尾 crossfade，Login 跟随全程进度仅淡入淡出；Enter 最终过渡为 240ms，省略人物位移、缩放、模糊效果。SCROLL 动标保持静止，离开首屏时提示立即隐藏，无鼠标联动。
