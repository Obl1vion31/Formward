# 当前实现与验证

Formward 是 Next.js 16.3.7／React／TypeScript 模块化单体，Node.js 24.21.0、pnpm 9.15.9，Neon PostgreSQL／Drizzle 与 Better Auth。app 负责入口，features 负责业务；网页、MCP 和 HTTP 复用规则。定位见 [代码索引](code-study.md)，新会话先读 [交接](../handoff.md)。

## 产品状态

- `/dashboard` 为“总览”：保留今天四项摄入、餐次数、最新真实空腹摘要和 7 日变化，新增空腹体重 kg、体脂 %、每日摄入 kcal 三张历史图，共用范围、日期坐标和选中日。读数明确区分 D 日摄入、D 日空腹及 D+1 日空腹，不移动次晨曲线。点击打开只读当日详情，带日期进入饮食或身体记录。
- 总览默认只显示真实空腹，开关仅显示已有估计，以空心点／虚线区分，不生成估计；缺日留空，多候选不自动选择。7D／30D／90D／全部／自定义固定宽度，桌面默认 30D、手机默认 7D。运动、消耗、盈余和活动建议待后续接入。
- 饮食历史每天一根冷蓝 kcal 柱，纵轴从零起，读数区显示热量与三项营养 g；短范围有柱顶数值，长范围只显示当前日期与完整起止范围。连线默认关闭，缺日或不完整摄入断开。历史食物默认展开，摘要始终是今天。
- 手动录入只有食材库／自由填写。桌面宽双栏：左侧搜索与食材列表，右侧本餐多项；手机全宽分步并保留草稿。食材按自身单位输入克数或小数勺／份，选择或更换不默认用量。自由项营养为本次实际摄入，分量可选且不再相乘。
- 手动营养依据只有标签／成分表和直接预估，前者使用 reference；AI 及旧来源保留，未知不自动改写。旧 misc／whole 接受并按自由填写展示，用户编辑后的新版本统一为 food，不批量修改历史。
- 食材库显示名称、简短规格、真实基准和标准营养列，详情放右侧，删除记录次级展示且可恢复。名称与依据只说明实际组成、份量／单位和成分／热量，不写上传背景或无关排除项。六项基础预设及采用流程保持。
- 饮食审核常驻日期、餐次、项数、库引用／自由填写数量、食量及逐项营养，详情可展开已保存的来源、估算方法和不确定性，不补造旧依据。保存后明确终态、刷新保持，旧 pending 响应不能覆盖已保存结果。
- 原图最多 8 张，每张 20 MiB，保留 JPEG／PNG／WebP 原字节。网页 OIDC 预签名直传 Private Blob，MCP 下载临时文件；逐图返回错误码／阶段／requestId，部分成功保留。缺图需补传或用户明确选择先保存文字并进入审计，AI 不能跳过事实核对。
- 身体页保留六项摘要、双图、晨晚 Inspector、四项录入和已有估计规则；最近记录展开显示今天及最近 10 日内待补录／待选择日期，完整历史每批 50 日期。合法 date 查询打开指定日期，普通入口不自动弹窗。
- 身体和饮食 Inspector 从内容拖到遮罩松开不关闭，真实遮罩按下／抬起且小幅移动才关闭；关闭按钮、Escape、焦点和忙碌保护保留。滚动条预留／实际释放宽度补偿保持，页面和弹窗不横移，320px 不溢出。

## 数据与权限

schema 共 29 张业务／认证表，另有 Drizzle 账本。0016 仅扩展 foods_source_valid 接受 reference，无新增列或回填；0015 的可展开依据与 20 MiB 约束保持。共享 migration 不修改，执行前私有一致性备份，执行后逐表核对旧字段和值。

所有用户数据按 user_id 隔离，未知 null，删除可恢复，历史食材营养和计量快照不随当前规格改变。AI 写入先预览、网页登录确认；15 分钟有效期、revision、快照、幂等、凭据撤销和审计保持。身体 AI 支持批量、逐行修改／确认与整批事务。

食材说明维护通过内部事务预览、绑定摘要后写入。ON 当前按每 1 勺（约 30.4g），标签数值和历史克数／营养快照保持；Pasta Express 保留成分估计克数、整体热量范围与采用基准。食材库专用文案整理使用 updateMealDescriptions:false，全部个人餐次及历史快照保持。旧维护同步方式仅限完全匹配的说明快照；原始请求与旧审计保留，新增审计记录 AI 代执行和用户授权。私有请求／备份／报告为 0600，Git 和部署忽略。

身体规则保持：体重和体脂独立，晨间只接受空腹、晚间非空腹，凌晨归前日晚间；普通保存不自动估算，历史初始化冻结范围不重算，补录只替代对应指标。来源建议删除不影响历史，网页可留空，AI 必须核对实际来源或明确留空。
