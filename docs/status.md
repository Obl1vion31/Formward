# 当前实现与验证

Formward采用Next.js16.3.7、React、TypeScript、Node.js24.21.0和pnpm9.15.9。app负责页面／动作／HTTP入口，features共用业务，PostgreSQL／Drizzle保存事实及审计，Better Auth认证。新手阅读[学习指南](code-study.md)。

## 当前功能

总览采用双层日期关联图：上层为蓝色摄入线和红色消耗线，线间柔杏金（#D8B38A，28%）表示盈余、雾蓝灰（#92B2C2，28%）表示缺口，交点处分区；下层暖白线显示严格相邻次晨变化，两层共用日期、选择线和命中区域。能量折线按完整区间取整并留余量，kg轴独立包含零；未知断线，填色在有效段末尾轻淡出，不跨缺日。顶部展示摄入−消耗＝盈余／缺口，以及两日晨重与差值；部分摄入和估算不阻止相减。保留7D／30D／90D／全部／自定义、估计开关、固定图宽；鼠标、触屏或方向键选日，Enter或“查看记录”打开详情。下方为紧凑的身体、摄入、消耗入口摘要。

消耗录入为分开记录／只记总数，活动为记合计／按运动累计，模式互斥，隐藏旧值不重复相加。分项来源独立，运动继承当天日期并可随日记录事务保存。公式仅供独立对照，不自动生成每日消耗；日常默认值已停用，旧表与审计保留。网页移除来源记录编号、活动估算勾选及实现说明。详见[消耗规则](energy.md)。

网页、HTTP、MCP使用同一业务计算与确认事务，展示读数在服务端整理，浏览器只输入、选择及绘图。未知与0区分，没有记录的日期不自动生成消耗。一次性历史初始化使用私有明确范围的审核批次，不能变成长期偏好。

统一审核支持身体、摄入、食材和消耗混合提交；逐项操作只改草稿，底部确认后同一事务保存，失败整体回滚。旧消耗预览须刷新后按新规则确认，退役默认项只能取消。原始请求、来源、操作者、版本及可恢复审计保留。

身体页的双图、晨晚录入、既有估计、来源、时区与准确时间规则保持。摄入页保留食材／餐次、单位换算、PFC展示、私有原图和受保护的删除恢复。照片最多8张、每张20MiB，原字节存Private Blob，数据库只存元数据与关联。

总览、身体、摄入和消耗图形复用原生动效，首次可见450ms、区间切换200ms；数字、坐标和命中区保持稳定，遵循减少动态效果，首页与弹窗行为保持。

## 协议与数据库

仓库协议OpenAPI1.11.0／MCP1.8.0，共12工具。消耗查询沿用GET /api/v1/energy和query_energy；统一提交扩展entryMode、activityMode与分项来源，旧无模式请求兼容。OAuth仍按身体／饮食／消耗原权限隔离，不自动扩权；AI正式保存必须用户网页登录确认。

0021新增energy_days模式、分项来源及resting_estimated。36张应用表原字段和值保持，账本另计；旧行模式为null，不在migration补零或改个人数值。energy_defaults仅保留退役存储与审计。完整字段见[数据库字典](database.md)。

## 维护边界

这轮后以维护和体验优化为主，不新增训练计划、预算或佳明自动同步。身体准确时间／归属网页纠正、持久代表选择、网页删除恢复和通用导入尚未接入。真实手机／微信观感仍由用户最终核对。用户健康数据、私有请求、备份和凭据不进入公共代码、测试、截图或public。
