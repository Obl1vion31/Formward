# 当前实现与验证

Formward采用Next.js16.3.7、React、TypeScript、Node.js24.21.0与pnpm9.15.9。app承接页面／动作／HTTP入口，features共用业务，PostgreSQL／Drizzle保存事实和审计，Better Auth提供认证。新手阅读[学习指南](code-study.md)。

## 当前功能

总览仅保留一张综合图：D日浅蓝摄入、浅红最终消耗、金色盈余三柱并排，暖白线显示D+1晨重−D晨重。严格相邻日配对，缺记录或候选未决留空；估计开关只展示已有数据。标题与日期紧邻，图例和读数收紧，保留区间、键盘和日期详情；移除晨重基准、晨晚差及实现说明，身体详情保持原有规则。

消耗页支持每日静息、活动合计、全天总数、活动明细和按生效日使用的公式资料。全天总数优先，否则静息加活动；没有活动合计才汇总完成明细。活动数字原样使用，不扣静息。未知null，明确没有活动可填0；资料或体重依据不全不自动补值。缺静息时按Mifflin公式，以当天空腹实测、当天已有估计、过去30日晨重依次取值；查询不写身体记录。来源和依据按需展开，支持版本保护与软删除恢复。[规则与接口](energy.md)。

统一审核支持身体、摄入、食材与消耗任意组合；逐项核对、编辑和取舍仅改草稿，底部确认后同一事务保存，失败整体回滚。原请求、修改、确认人和审计保留，旧链接兼容。照片最多8张、每张20MiB，原字节保存在Private Blob；数据库只存元数据和关联。用户未提供的原图无法由过期URL恢复。

身体详情保留双图、四项晨晚输入、已有估计、来源与时区；最近记录显示今天和近10日待补录／选择，完整历史每批50日。摄入支持餐次／食材、库规格换算和自由项、PFC克数／能量占比、图片、最近删除和受保护的永久删除。食材物理删除保留历史餐项快照。

总览、身体、摄入和消耗SVG共用原生动画：首次可见450ms、区间200ms，数字、坐标和点击区域稳定，遵循减少动态效果；首页和弹窗原有行为保留。

## 协议、数据库与授权

仓库协议OpenAPI1.10.0／MCP1.7.0，共12工具，新增GET /api/v1/energy与query_energy；统一items增加日消耗、活动和公式资料保存／删除／恢复。OAuth独立energy:read／energy:write，旧连接不自动扩权；刷新工具列表后缺权限需重新授权。手动令牌沿用read／write。AI预览15分钟，网页登录确认前不写正式事实，撤销立即阻止未确认操作。

0019新增energy_profiles、energy_days、activities、energy_operations、energy_events，record_operations增加可空消耗关联和版本，共35张应用表，账本另计。独立数据库迁移测试确认原30表字段值保持。健康数据按账号隔离，版本、来源、原单位、时间／时区、请求标识与操作者保留在事实／操作／审计中。

## 维护范围

这轮完成后以维护和体验优化为主，不扩展训练计划、预算或佳明自动同步。身体准确时间／归属的网页纠正、持久代表选择、身体网页删除恢复／通用导入尚未接入；维护脚本能力不等于网页入口。真实手机／微信观感和用户原图仍需用户使用时核对。
