# 身体指标记录

## 当前范围与推进顺序

首页现阶段收尾，身体指标记录是第一个业务模块。当前支持四列 TSV 的校验、预览和维护脚本导入，并提供登录后的身体记录回看、体重／体脂趋势与晨晚对比。手动新增、编辑、网页删除／恢复及正式 AI API 尚未实现；维护脚本支持授权条件与来源修正、日期时段实测补录、历史缺测估计、保留较早候选与软删除／恢复。

实际收到的样本为聊天粘贴的 27 条测量，来源字段是测量时间、体重、BMI 和体脂率。用户确认这批记录使用 Asia/Shanghai，白天记录为空腹；肌肉、水分等详情不要求逐日补录。聊天转存文件与真实数据只保存在 Git 忽略的私有目录。网页与后续外部 AI API 共用 `src/features/measurements` 的校验、时间归属和读写函数。

## 核心与候选指标

体重和体脂率是核心展示，BMI 按实际导出保留。当前数据库只建立这些已确认数值；其他指标在实际收到来源后通过新 migration 增加，历史缺项保持为空。下表中的其余指标是后续候选，不是首批导入的必填项。

| 指标 | 单位或来源语义 | 展示与记录建议 |
| --- | --- | --- |
| 体重 | 标准化为 kg，同时保留原单位 | 核心记录与趋势 |
| 体脂率 | % | 核心记录与趋势，标明设备估计来源 |
| 骨骼肌率 | %，具体口径以设备说明为准 | 次级详情，与总肌肉率区分 |
| 骨骼肌重量 | kg | 次级详情，可关注同设备长期变化 |
| 肌肉率 | %，具体口径以设备说明为准 | 保留原名，不当成骨骼肌率 |
| 肌肉重量 | kg | 保留原名，不当成骨骼肌重量 |
| 骨量 | 通常为 kg，须核对导出 | 设备估计值，不作为骨密度或骨质诊断 |
| 基础代谢 | 通常为 kcal/日，须核对导出 | 保留设备估计；与全天总消耗分开 |
| 去脂体重 | kg | 次级详情；不等同于肌肉重量 |
| 蛋白质 | 可能为 % 或质量，须核对 | 保留设备含义，与饮食蛋白质摄入分开 |
| 水分／含水量 | 可能为 % 或质量，须核对 | 次级详情，保留设备含义 |
| 内脏脂肪 | 可能为等级、指数或其他单位，须核对 | 不把等级当百分比或重量 |
| BMI 等其他已有指标 | 按实际来源确认 | 如来源有提供可保留，暂不主动补算 |
| 腰围，可选人工补充 | cm | 产品建议，独立于体脂秤估计，不作为首阶段前提 |

产品上优先体重，再结合体脂率、骨骼肌重量、去脂体重和水分做回看。体脂秤的体成分值受设备算法与测量条件影响，不能因为小数位多就假定精确。一项对三款商用智能秤与 DXA 的比较研究发现，体重表现较准确，体成分估计存在明显误差；该结果不能泛化为所有型号，也不能据此保证同设备的趋势准确性。[原始研究：Accuracy of Smart Scales on Weight and Body Composition](https://mhealth.jmir.org/2021/4/e22487)

去脂体重包含肌肉之外的水分、矿物质等成分，不能直接标作肌肉；短期体重变化也可能来自水分、糖原及消化道内容物。页面保留数值与来源，不把单次涨跌自动解释为脂肪增减。[原始研究：Composition of two-week change in body weight under unrestricted free-living conditions](https://pmc.ncbi.nlm.nih.gov/articles/PMC5506524/)

## 测量时间、晨晚归属与空腹条件

主趋势以空腹测量为基准。白天／起床后测量可以接近中午，不强制限定早上钟点。尽量保持同一秤与相近条件，便于比较；一致性原则可参考 [NHS 体重记录指南](https://www.england.nhs.uk/wp-content/uploads/2021/06/PRN00916-how-to-record-your-weight.pdf)。

| 测量地当地钟点 | 归属日 `analysis_date` | 时段 `period` |
| --- | --- | --- |
| 00:00:00–05:59:59 | 前一个当地日历日 | 晚间 |
| 06:00:00–17:59:59 | 当天 | 白天 |
| 18:00:00–23:59:59 | 当天 | 晚间 |

凌晨分界 06:00 已由用户确认；18:00 是当前白天与晚间的自动划分规则。规则可由明确的人工归属覆盖，已写入的归属不因规则更新而默默重算。当前界面尚无保存归属修正的入口。

- `source_local_time` 保留原始当地时间，`local_date` 是实际日历日期；`analysis_date` 只用于晨晚分组。例如 D+1 日 01:00 是 D 日晚间，实际日期仍是 D+1。
- 每条记录保存发生地 IANA 时区，例如 Asia/Shanghai、America/New_York，另存当次 UTC 偏移与 UTC 时刻。旅行后按新测量地归属，不把旧记录转换到当前所在地再分类。
- 夏令时跳过的钟点拒绝写入；重复钟点需要来源偏移。未知时区可保存原始当地时间，但 UTC 时刻留空。当前 TSV 入口要求完整时分秒；日期时段实测入口使用 day_period；明确授权的占位时间使用 assumed，界面注明时间为占位，UTC 时刻为空，原始输入时间仍为空。
- 空腹区分是、否、未知，并记录确认来源。白天记录须明确确认；晚间按已确认产品规则统一非空腹，包括归属前一天的凌晨读数。来源分别为 `user_confirmed`、`evening_rule`。历史晚间条件经授权维护修正，保留事件前后快照；一般新来源不能仅凭白天钟点推断空腹。
- 同日同一时段多条都保留。恰好一条时作为查看候选；多条时保留候选，不取平均或最低值；选择同时作用于图表、晨晚表与详情，尚未持久保存。当前已有重复组经用户明确授权保留较早一条，其余软删除，未来不自动清理候选。
- 缺失指标使用空值。骨骼肌与肌肉、百分比与重量分别处理，未确认语义前不换算或补算。

## 数据准备与导入

当前指定账号有效记录为 28 条实测与 27 条历史估计，实测中晨间空腹 7 条、晚间 21 条；一条重复晚间实测保持软删除。原始文件及原始测量字段完整保留。实测来源标为“开发后台加入”，设备按用户提供信息写“普通蓝牙体重秤”，连接应用为 OKOK；品牌、型号及来源同步系统不编造。估计来源为“开发阶段录入”，不标为设备测量。

原始文件放在 Git 忽略的 `data/imports/`，保持原文件名和内容。截图也按私有来源处理，不能放入公开目录或提交。已有历史 Excel 使用 [独立迁移规则](excel-import.md)，不要未经检查就把不同来源当成同一种格式。

导入流程为：只读解析 → 字段、单位与日期映射 → 预览缺项、异常和重复 → 用户确认 → 写入对应账号 → 保存来源与导入结果。确认前不写入真实健康记录。先支持实际样本格式，不为了未知品牌提前增加解析依赖。

当前 TSV 入口保存文件内容与时间解释的摘要、批次、来源行和数值指纹。相同文件重试返回既有批次；重新排序的相同测量跳过，不覆盖人工修改或复活已删除记录。同秒、同时区的不同数值进入冲突并回滚整批，未来跨设备来源需再明确来源命名空间。不能按归属日去重。后续有稳定来源记录标识时优先采用。

所有查询、写入和导入都校验 `user_id`，不信任客户端指定的账号归属。人工修改、AI 写入和导入保留操作者、时间及来源；删除可恢复。自动测试使用虚构或脱敏样本，真实用户文件不进入测试固定样本。

## 登录后报表的日期关系

报表主页区分两种观察关系，不能把日期口径混在同一列：

1. 当天晨晚差：D 日晚间体重减 D 日白天体重，对照 D 日热量盈余；即使晚间实际发生在 D+1 日凌晨，也仍按 D 日归属分析。
2. 次日空腹变化：D+1 日空腹体重减 D 日空腹体重，对照 D 日热量盈余；需要相邻两日的空腹记录，缺任一条不计算。

体脂率与热量分别保留 % 和 kcal 刻度。原来的“D 日空腹对照 D−1 日盈余”仍用于次晨观察，不替代当天晨晚对比。

| 共用的测量日 | 体重／体脂数据 | 关联热量盈余 |
| --- | --- | --- |
| 10 月 6 日 | 10 月 6 日早上第一顿饭前的测量 | 10 月 5 日的盈余 |
| D 日 | D 日的晨间测量 | D−1 日的盈余 |

关联只作用于展示和查询，不更改原始记录日期。选择某点时同时写出测量日与热量日，避免误以为这三项发生在同一天。短期体重会受水分等因素影响，因此不把次晨结果等同于前一天热量盈余的确定影响，依据见上面的原始研究。

热量盈余需要先明确总摄入与全天总消耗的口径、数据覆盖和估计来源；不以摄入减已记录运动或仅减基础代谢冒充全天盈余。缺少饮食、消耗或测量时不计算关联、不补零、不把最近测量冒充今天；热量关联只使用实测，历史估计不生成关联值。

当前主页显示最新空腹与 7 日摘要、空腹主趋势、7D／30D／90D／全部／自定义、最近记录及按需日期／原始详情。饮食、全天消耗与计划尚未接入，页面只展示已实现的测量能力。未授权补全的缺项显示 —；授权估计带明确标记，涉及估计的差值注明“估计差值”，不补零或移用其他日读数。

## 存储与界面方案

当前界面采用正常坐标：体重、体脂率越高越靠上，最小跨度为 3 kg／3 个百分点。晨间空腹为金色主线，晚间为较淡蓝色折线，默认都显示。实测是圆点，估计是菱形；相邻实测端点为实线，经过估计端点的线段为虚线。未补全缺口使用极淡同色点线，未解决真实候选处断开。早晚反常数值继续保留。页面按仅实测摘要、趋势、按需日期栏和最近记录组织；完整历史、时间精度、BMI、来源、设备和预测区间放在抽屉中。

数据库使用 measurements、measurement_imports、measurement_events。record_kind 区分 observed／estimated，entry_channel 独立区分 api／manual／development_backend；设备、连接应用、原始采集方式和执行审计分别保存。0002_complete_lockjaw.sql 增加来源维度与估计模型，并约束有效估计时段唯一及占位时间不生成 UTC。已有共享 migration 不修改。

日期提供 7D／30D／90D／全部／自定义，默认 30D，以最新记录归属日截止；日历按钮展开自定义起止日期。真实日历间距保留，长区间按屏幕宽度显示少量刻度，不逐日生成空表格。最近记录只展示当前区间最新 10 个有记录归属日，查看全部打开不受图区间限制的完整历史。

摘要随指标切换，但始终仅取真实数据的最新有效空腹状态，并标明实际日期。7 日窗口以当前指标最新空腹日为截止、包含前 6 天；变化取窗口内首末代表值，不足两个记录日为空。均值按有值日期计算，每日最多一个代表值，并显示实际覆盖天数；体脂变化用百分点。另一指标当前值保留自己的最新有效空腹日期。未选代表候选不参与摘要、主线和差值；候选选择共享于各视图，不持久化或自动删除记录。本阶段不加入移动均线。

`maintenance.ts` 提供只读账号快照预览、绑定摘要的事务维护及按记录恢复，脚本入口见 [维护目录](../scripts/README.md)。授权维护将现有晚间条件修正为非空腹，同归属日同一时段保留真实发生时间较早的一条，其余软删除。事件保存前后快照、理由、操作者、时间与重复请求摘要；预览后数据变化则拒绝写入，重复请求幂等，恢复和重导不重新执行旧维护。

后续补齐“新增记录”和“导入数据”入口。新增表单展示测量地时区，预览自动归属，允许改为白天／晚间并修正归属日，白天空腹状态单独确认、晚间统一非空腹；更多指标放在展开区域。记录详情提供纠正、软删除与恢复。导入页展示全部候选、重复、冲突、跨午夜归属和账号，确认后事务写入。

## 历史估计与来源维护

completion.ts 与 scripts/complete-measurements.mts 接收指定账号和私有请求 JSON，预览来源修正、新实测、补全清单及区间。写入绑定账号当前快照摘要、锁定账号并事务提交，重复请求幂等，失败不留下部分来源修改、记录、批次或审计。只在显式授权调用时运行，不在页面读取时补值。精确格式见 [脚本目录](../scripts/README.md)。

当前历史补全范围为 2026-09-09 至 10-04，训练阶段为 09-09 至 10-06，补全 21 个晨间与 6 个晚间时段，每条同时保存体重、体脂估计；10-06 晚间继续缺测。私人数值和模型结果只存忽略版本控制的导出目录。

训练阶段最多 28 天，晨间确认空腹和晚间分别拟合日期一元线性回归，体重、体脂独立建模。只使用真实、有效、已选定的每日代表值；已删除、估计和未解决候选排除。至少 3 条有效样本，否则保留缺项并报告原因。点估计是确定的拟合值，不随机制造日常波动。

双侧 95% 单次预测区间采用 ŷ ± t(0.975,n−2) × s × sqrt(1 + 1/n + (d−平均日期)²/Sxx)，s²=残差平方和/(n−2)，包含单次测量波动和拟合不确定性。临界值使用 [NIST Student-t 表](https://www.itl.nist.gov/div898/handbook/eda/section3/eda3672.htm)，区间口径见 [NIST 单次响应预测](https://www.itl.nist.gov/div898/handbook/pmd/section5/pmd512.htm)。区间依赖线性阶段、独立且近似正态的残差假设；历史回顾性补全不能当作未来预测准确率验证。

估计保存方法版本、训练范围与样本快照、完整系数、残差方差、样本量和区间；计算不提前舍入，显示两位小数，区间向外舍入。只有没有真实记录的时段才补估计，真实候选未解决也不补。未来实测补录或恢复优先，并软删除对应估计、保留前后审计；有有效同段记录时不能恢复估计覆盖它。

晨晚和估计默认显示，可分别关闭。关闭估计影响图、最近记录和日期栏，完整历史仍保留全部。点击／键盘选择估计点，日期栏和抽屉展示估计值、95% 预测区间及模型，晨晚差任一端含估计时标注“估计差值”。摘要和实测覆盖天数始终排除估计。

## 外部 AI 接口方案

正式 HTTP API 尚未实现。计划提供测量查询、每日配对分析、候选预览和确认写入，网页与 AI 共用 feature。令牌只存摘要，支持撤销及 read／write scope；服务端由令牌取得 user_id，忽略请求里自称的账号。

| 拟定入口 | 职责 |
| --- | --- |
| `GET /api/v1/measurements` | 查询当前令牌账号的原始测量，支持时间区间 |
| `GET /api/v1/measurements/days` | 查询按当地归属日的晨晚配对、缺项与关联日期 |
| `POST /api/v1/measurement-imports/preview` | 校验批量候选，返回归属、重复、冲突和待确认内容 |
| `POST /api/v1/measurement-imports/:id/confirm` | 验证用户对该份预览的确认，并幂等写入 |

每条候选显式提供当地时间、IANA 时区与数值单位；体脂率采用百分数，不能把 0–1 比例当成百分数直接存入。体重为最小数值必填项，BMI 与体脂率可缺失。修改、软删除与恢复接口随网页维护能力一同实施，先落实历史变更确认与并发版本检查。

候选字段包含来源当地时间、IANA 时区、必要的 UTC 偏移、体重、体脂率、BMI、白天空腹确认及来源标识，晚间由统一 feature 应用非空腹规则。AI 可以提出时段和归属候选；服务器应用同一规则，未知信息保持空值。批量导入及历史修改必须先生成绑定账号、内容摘要和有效期的预览，再取得真实用户确认；不能让 AI 自填 `confirmed: true` 代替确认。每次写入用稳定请求键去重，并保留 AI 操作者与原始设备来源。

每日查询返回当天晨晚记录及差值、次日空腹变化、对应热量日、数据覆盖与缺项。分析可指出观察到的变化和依据，不把体重差直接换算为热量，也不把同日相关认作确定因果。

## AI 录入与设备连接

截图、语音交给 AI 转换成候选记录，是后续降低录入负担的方向。人工网页保留最小录入与核对能力，AI 解析后沿相同 feature 校验、归属和重复规则写入；识别者是 AI，原始数值来源仍可能是秤或用户口述。修正历史记录须展示影响并明确确认。

设备直连等实际型号明确后再评估。[openScale 官方仓库](https://github.com/oliexdev/openScale) 提供 Android 开源体重与身体指标记录，支持部分 Bluetooth 秤及 CSV 导入导出；[型号兼容列表](https://github.com/oliexdev/openScale/wiki/Supported-scales-in-openScale)列出了不同设备的指标、实时和历史能力。它是候选方案，不意味着用户设备已受支持，也不意味着网页可直接使用其蓝牙连接。首阶段文件导入不依赖设备直连。
