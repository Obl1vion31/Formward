# Formward 设计与视觉验收

豆包专用H5连接页遵循本文件D2／D3／D6的实际视口、可读输入和操作可达要求，扩展原OAuth表单；原生宿主首页与自定义登录页共同使用连接组件，明确跳转到同源Formward登录。授权说明、拒绝／失效／网络错误与返回结果分别验收。本地Chrome中的回传失败不能写成豆包WebView通过，平台接通也不能代替矮屏及键盘的页面验收。

本文件是 Formward 手机、桌面界面设计和视觉验收的统一依据。涉及界面修改时，实施前与验收前都读取本文；验收记录逐项对应下面的适用标准，附实际网页截图、结果及未通过项。调研和页面说明引用本文，不另设一份竞争的检查清单。

当前验收以正常字号为准。按用户最新决定，200%文字放大退出本轮及后续整改、测试和发布门槛；下文旧条款中的200%场景不再执行。既有适配代码保持，正常字号下的长内容、输入、触控、真实界面和加载稳定性继续逐项检查。

## 适用范围与设计方向

手机是随手记录、查看与后续训练执行的入口，桌面是整体记录与对照工作区；两端共享业务规则、日期关联、查看／编辑语义与返回路径，允许不同布局外壳。总览均先呈现真实趋势卡，再展示关系图；电脑并排并保留完整分析，手机横滑并优先高频动作。手机采用连续底栏与可拖动详情，电脑保留左侧导航及Inspector。研究原型、本地实现与正式发布分别记录。

用户明确的设计方向优先于技能的通用风格偏好。卡片、毛玻璃、较大圆角、边缘高光和弹簧动效可用于分组、层级、反馈和连续交互，按可读性与实际性能验收。下文的页面构图、尺寸、按钮顺序和已选参考描述当前实现。新增或调整功能时，对照用户本次要求和受影响的完整任务决定哪些布局继续适用。真实事实、权限、保存确认、草稿保护、输入边界和无障碍贯穿不同布局。

## 信息层级与布局

显式日期链接进入的饮食、身体、消耗页，在该日期仍属于当前区间时把它作为默认读数日期；退出录入／详情、鼠标离开和响应式接管不改成最近记录。手动点击另一日期继续保持；明确切换到不含原日期的区间后使用该区间真实默认日期。

### D1：首屏按任务呈现行动与事实

先明确用户从哪里来、要找什么、看完或操作后去哪里，再安排控件、说明和详情。新增功能要与原有内容一起判断主次。例如新增「历史会话」时，把当前聊天、会话列表、旧对话阅读、继续和返回串起来，决定哪些内容共享消息排版、哪些动作属于阅读或续聊。若已有布局能自然完成任务就沿用；若用户必须去无关分组找入口、来回切换才能看全事实，或两个位置重复承担同一操作，就重组相关部分。手机与桌面可分别选用合适的容器。

- 总览：电脑将选中日摄入、消耗、盈余／缺口、当天晨重、次晨重和次晨变化同排，能量36–38px、身体28–30px，共用数值基线；宽度不足按三列、两列退让，不缩字。电脑保留已有七日横向摘要，起止晨重与必要依据直接显示，取消独立详情。手机先给出记录饮食、身体或消耗等真实可用动作，再用有主次的卡片展示状况；紧凑净收支与次晨变化图直接可见，手机在区间栏右侧放「统计」，默认收起。展开后用同一个浮层对照选中日及截至该日的近7天，部分计入时注明已计天数。图表和日期轴位置稳定。首屏不强制六项同排、两排或完整双图，未知保持真实，饮食未记全／待确认／营养未知的原因进入日期详情。
- 饮食、身体、消耗：普通页面保留日期、真实读数、完整图表及记录列表，不能为“记录优先”隐藏趋势。紧凑布局用于录入／编辑面板：日期与填写动作在前，合计与保存在手机底部。view=trend继续保留来源日期、范围和返回位置；普通入口默认今天，明确日期和自选范围优先，今天缺测不静默挪到最近完整日。手机饮食统计卡默认显示主热量、供能环和营养详情入口，展开后蛋白质、碳水、脂肪使用卡片全宽并排三列，名称在上，克数在下，可计算的供能占比置于克数下方；餐次构成由记录列表提供。身体主读数、迷你走势、较前一日和7日均共用紧凑卡，消耗主数、组成条、静息／活动的数值与百分比就近归组。桌面保留现有完整读数与图表。
- AI 确认：日期、本餐营养合计、前两项食物及统一保存；图片、依据与次级操作按需展开。
- 身体的桌面与完整趋势：采用体重主卡及真实7日小图，设置入口贴主卡标题；开启体脂时下方为体脂及7日均重，关闭时为前日差及7日均重。点击指标卡切换唯一完整趋势，保留所选日期；7日变化与实际起止贴图表，旧隐藏值不丢失。

账号后台优先搜索与账号状态；邀请页先显示生成链接的输入和期限。本人设置的手机首屏优先登录标识、设备与连接，密码和全部撤销在下方。管理弹窗按需展开，底部操作必须可滚动到达。

当前没有数据时显示简短空态；日期、未知、未记全状态保持准确；设备与手填消耗不重复显示泛化估计标签；系统计算明确显示公式来源，活动估算显示全天估算，已保存数值和内部来源留档保持。手机快速记录优先呈现填写动作，回看优先呈现要找的记录和理解它所需的上下文，报表优先呈现主要事实。次要状态不能独占与主事实相同的大片区域。编辑任务及饮食日期列表中的“已记全”用紧凑勾选控件，文字始终保留；勾选后显示勾选标记、文字变淡，仍可取消，保存中不替换文案。日期列表最近与展开历史均可直接操作，空餐日不显示控件。行内确认不触发全屏等待，不插入顶部回执；当前页保留日期行所在列表、滚动、焦点和图表选日，默认列表始终只显示今天；其他日期在“查看全部”中原位查看或维护。错误就近显示并可重试。查看详情仅展示静态状态。


手机录入的实测门槛：390×844及390×667、正常字号下主操作完整可达；饮食点击「手动填写」后名称框立即出现并聚焦，矮屏可滚动看到完整表单。普通图表页面不套用“首条记录320px以内”的限制。日期、餐次、食物名及营养输入16px；空间不足或200%文字时自然退列、增高，不缩字裁切。备注与照片展开，但数量、上传阶段及错误可辨。

手机顶栏正常高度52px，页名20px／600字重／28px行高，两侧操作占位对称、页名真正居中；44px点击框与可见文字分别验收，200%文字允许增高。总览“今天”为16px／500分区标题；同组8px、标题至内容12px、分区16px，由一层容器负责，不叠加旧margin与padding。正常无键盘、引用及附件时，助手消息区至少占扣除安全区后面板高度70%；浮动箭头显隐高度变化≤1px。

首帧显示已知标题、语义图例、日期和操作槽；默认选中日依赖查询时保留中性等待，不先猜今天、未连接或空记录。加载采用下文的真实内容保留策略，不制作虚构摘要与记录行。

### D2：按实际可视空间验收

首屏空间扣除页头、底部导航和安全区；浏览器工具栏占用通过较矮视口模拟。手机首屏优先保证当前主要动作、关键状态及明确日期可读，三类普通记录页保留完整趋势，录入面板优先实际填写。矮屏、横屏和长内容允许自然下滑；桌面报表继续优先主要读数与图形。

先删除重复内容并安排合理展开层级，再按空间设计图形。摘要可省完整坐标与次要图层，但必须有明确入口查看完整趋势、其他已开启指标、日期和历史，不能裁掉事实或冒充完整图。完整图不缩小整幅SVG压低字号；横屏和文字放大允许自然滚动，保持可读和可操作。

### D3：紧凑与可读同时成立

桌面四页沿用选中日期／查看记录、主要读数、日期区间、图表标题与实际选项、图例与图表、原有记录的顺序。手机按行动、状态、趋势与历史安排，不要求四页采用同一构图；同类控件、数据含义和返回行为保持一致。手机首页状态数值约28–32px，普通记录页沿用有主次的真实读数卡，录入合计约22px、桌面36–40px；营养分项可作为次级读数。区间文字13–14px，选中用轻量下划线，保留44px点击范围。桌面区间独立一行，与说明区间隔约16px，标题、单位、图例同排，选项靠右；手机完整图表按实际宽度安排区间、标题、图例与选项，保持关联清楚。单位不另占一行。完整图表中的晚间数据开关、营养占比切换直接可达，不额外套无意义菜单；手机摘要不必同时铺开全部图表选项。

读数、标签、图形形成清楚层级；少量数据不必拆成多行大块。日期与所属读数放在一起，相关图表紧邻，筛选区域上下间距一致。长数字、未知和状态变化不使布局跳动或横向溢出。同一区间把各日的数值、单位、标签一起测量，安排列数与稳定标签／状态高度，不因选到较短数字反复切换列数；只测量文字宽度，不重算健康数据。当前区间可能出现的必要短提示共同决定最小提示高度；鼠标选日只换文字，读数、区间和图形位置不变。区间完全没有提示时不留空行。身体与总览只展示实测，缺测留空，不为已移除状态保留说明行。鼠标、键盘和触屏选日只换内容，同一配置下读数、筛选、图形及页面滚动变化不得超过1px；区间、尺寸与字号改变后可以重算；晚间开关只调整可见系列和实际纵轴范围，绘图区、日期轴与读数外框保持。电脑总览短提示放进已有日期行，长文字在查看记录中解释；手机总览不插入状态说明行，相关原因放日期详情，不因选日新增占位。部分数值含义保持。身体记录的晨间／晚间标签与各自读数保持完整，桌面同排，窄屏允许按时段组换行。

数字填写必须以实际控件字体、当前值、内边距和选择箭头核对可见文字宽度，不能只检查容器无横向溢出。手机常见数量125.00保持名称／单位／数量同排；200%文字或更长数值时依次退为名称独立、单位／数量两列，再逐项单列，数字不裁切、不缩字。

录入组件的主字段、只读数值和名称使用一致的字号与行高；一餐编辑器主内容16px／22px，表头13px、辅助说明12px。文字左对齐、数字右对齐，同类字段的表头、框内值与只读值必须落在相同内容边缘，边框内距与选择箭头都计入可用宽度。随数值展示的单位紧跟数字、字号较小并对齐基线，数字和单位作为整体不拆行；放不下时整项换行。单位与数值必须完整可见，不能以缩字、静默裁切或不合理留白换取固定列数。列宽优先分配给长名称、单位和实际数字，空间不足切换布局；包装依据等次级信息不得独占一行撑高全部单元格。

图表左边距按实际坐标字体与最长刻度测量；长整数刻度必须完整，不能切掉开头，也不缩字。图表标签实际显示至少12px；空间不足时减少等距标签数量，保留单位和关键零线。触屏常用按钮保持至少44px高的可操作区域，不能仅靠缩字缩按钮换取密度。

### D4：高频操作直接，详情渐进展开

账号、低频设置和解释放入菜单或展开区。账号菜单保留邮箱、跟随系统外观、外部接入和账号管理；owner另有管理与测试。电脑五项左侧暖雾窄栏，助手右下非模态；手机五项底栏与独立助手入口。助手页提供聊天、历史和待办，快捷记录、按需补记与工具归待办，不自动展开完整面板。编辑／保存／确认优先，导航先退出助手。所有表单保持可辨认边框与底色、清晰焦点和44px目标；正文对比至少4.5:1，必要图线与控件边界至少3:1。图表点击保持日期；悬停离开才恢复默认，控件不推移绘图区。

手机冷进入/刷新时，程序聚焦同样不绘制按钮外框；首个绘制前初始化触摸呈现，键盘事件恢复可见焦点。验收同时覆盖未触摸的直达、点击后、程序返回和外接键盘，不能只凭点击后的截图通过。此规则不改变键盘/视口/面板定位。

总览、身体、饮食、消耗复用选日规则、区间控件、记录内容与编辑逻辑；业务专用内容留在对应模块。呈现外壳按设备适配：电脑可沿用Inspector，手机详情、历史及快捷录入可从底部连续展开为半模态面板，支持拖动调整高度及清晰关闭按钮；长表单可以展开到近全屏。关闭恢复原卡片、滚动与焦点，有草稿时共用确认保护，不能用手势绕过。桌面鼠标实际移动时预览，点击后保持所选日期，后续悬停和离开不取消；Escape或换区间解除。身体切换指标保留日期并重新建立当前指标的选择，不沿用旧指标的点击锁定。移到面板内的“查看记录”保留日期，未点击时真正离开整个面板才恢复当前区间最近完整日（无完整日时回退至最近有效记录）。键盘选日保持到焦点离开面板；触屏点选及横拖保留选择并直接跟手。查看入口先捕获日期及晨晚时段，再清理临时预览，明确点击／触屏选择在关闭详情后保留。自定义日期填写期间暂停预览，界面排布变化不触发换日；区间及可见系列改变后重新核对默认日；无独立前后一天控件。桌面查看记录保留在日期／图表标题右侧；手机可由可点击状态卡、日期或清晰按钮进入，避免重复操作栏。

饮食、消耗、身体的最近与历史记录共用标题、日期、摘要、分隔线和操作。录入／编辑／补录、查看全部／收起历史和加载更早日期使用 32px 单层浅底，查看采用文字操作。行内文字 14px，按钮命中区域至少 44px。正常记录行基本高度相同，长内容自然增高，操作与记录内容对齐。展开后「收起历史 ↑」「选择日期」「查询」同一行，320 CSS px 下保持 16px 日期文字和至少 44px 命中高度。日期字段使用系统选择器，自带可访问名称。空值显示「选择日期」并禁用查询，从详情返回时保留查询日期、已加载批次和原列表位置。对比三页的默认、悬停、焦点、禁用和返回。

独立食材库入口固定在饮食统计卡内的右缘，手机和电脑均竖排「食／材／库」并配右箭头，点击区域至少44×72 CSS px。手机营养详情在卡片内向下展开，蛋白质、碳水、脂肪同排。整卡共用20px圆角，展开时营养行顶部的1px线贯穿卡片，在同一高度接齐右侧挂签底边。文字留白放在行内，摄入、详情按钮和挂签保持原位。菜单打开时挂签继续绘制，触摸由当前层接管。加载和正式页面共用已知标题与操作位置。

从饮食进食材库时建立 `section=foods` 浏览器历史项，两端显示「食材库」与「← 饮食」。正文从右进入，返回从左接回，沿用约200ms，顶栏和主导航保持位置。按钮返回和浏览器后退恢复选日、营养展开、历史查询、已加载批次、滚动和焦点。浏览器前进回到食材库，直接打开可退回饮食。历史状态按当前账号核对，只保留界面的日期、展开和阅读位置。餐次内选材从本餐进入，回到本餐草稿。

饮食、身体与消耗的默认记录列表只显示今天，其他日期统一从“查看全部”进入；图表选日与列表日期分别处理。电脑保留列表下方“查看全部”原位展开，每批50日并排除重复日期；手机可在指标详情面板中展示历史与记录，保留明确日期、已加载批次和返回位置。主列表不铺开餐次、图片或运动全文。未知不当作0，空日期不写占位记录。

操作菜单和选材参考气泡紧邻触发按钮，正常间距约8px，边缘空间不足时可翻转。手机库选食物的本次营养附在行下，不改变其他行的布局。滚动、窗口调整或手机可视区变化后仍留在编辑器可见范围。长内容内部滚动，不撑开主内容，不额外遮暗整屏。Escape先关闭当前气泡并恢复触发焦点，不能顺带关闭有草稿的编辑器。

颜色同时配合文字、圆点／方点、虚线或标记；不单靠颜色表达状态。照片和大段依据默认收起，需要时再查看。

餐次面板先呈现日期、餐次、「手动填写」「拍照录入」与本餐列表。食材库入口放在「本餐食物」右侧。手机选材沿同一面板进入带搜索和竖向分类的视图，跨分类勾选后一次加入。食材库从右侧进入，返回时本餐从左侧接回，并恢复餐次草稿、滚动和焦点。手机日期、餐次与两种录入方式使用相同双列、间距和40px可见面。手机每项的名称、数量、单位、「营养」和移除入口按固定列对齐，库选、包装和手填共用列宽。「营养」与行内输入同高，显示完整描边和展开箭头。行尾「×」直接移除草稿中的该项。更换食材是来源详情里的小操作，与来源链接同行。固定单位位于数字框外。同一列的数量、单位和营养均从左侧起排，落焦及离焦保持各自的文字起点。名称、数量和营养输入使用32px高的浅底和完整细边，触控仍使用44px的输入区域。聚焦只强调小框边界，长数值使用原生输入浏览。库选点「营养」只显示四项读数，打开和收起时普通视口行位置偏差最多1 CSS px。手填的四项营养默认可编辑，在所属食物下方等宽显示，手机的依据与四个输入框同行。矮屏上重新展开时把营养区滚到合计栏上方。依据点开即显示可选来源，标记当前值并在选择后把焦点还给触发按钮。热量、蛋白质、碳水、脂肪共用标签及数值单位样式，值和单位同一基线。

导航与加载反馈保持连续。底部导航先即时回应点击或拖动，保留可用的页面外壳、原内容和各页滚动位置；导航超过350ms且缺少数据时，在所属内容区提供一处读取状态，失败可原位重试。保存按钮立即反馈并防重复提交，只有确实不可并发的事务才阻断相关操作；完成前不得假装已保存，失败保留输入。预取与缓存继续遵守账号归属、失效和退出清理，不为流畅性混用旧账号数据。

### D5：外观不改写事实

身体仅记录和展示实测，不提供估算、历史插补、估计开关、标记或依据。缺测保持空值和断线；真实7日均值及实测变化继续保留。该规则覆盖两端、骨架、助手、AI接口与导出。

四页选日线、选中带和高亮点共用永久图层，以100ms的cubic-bezier(.2,0,0,1)短过渡快速起步、轻收尾；鼠标与键盘一致。快速移动取消旧动画并续接当前视觉位置，不排队；同日同输入方式不重复更新状态。首次定位、尺寸／区间替换、触屏选日与拖动及减少动态效果直接就位。真实曲线、缺测与命中范围不参与插值，读数立即显示目标日，不播放虚假的中间健康值。

选日底纹统一为主题正文中性色4%透明度，辅助线为主题次级文字色1px、3／4虚线；键盘焦点用金色实线及现有命中区描边。饮食与消耗柱图同有底部金色短标记，折线图高亮统一为空心圆环（半径6px、线宽1.5px），各系列原色和身体晨晚含义保留。底纹与线共用同一变换并裁在绘图区，放在真实数据下方；宽度依据既有日期命中范围，不改柱宽、坐标或点击范围。未点击的悬停离开完整面板才恢复最近完整日；点击后的选择保持，移向查看入口准确捕获日期与晨晚。

现有日期详情中，只在全天合计显示一个营养环图，每餐不再显示小环图或百分比行；统一为4P／4C／9F供能比例，不能拿标签热量作分母。宏量未知或部分缺项不画完整比例，全0显示零供能，已知宏量而热量未知仍可显示比例。未记全状态由原有确认控件表达，不重复追加常驻说明；几何使用原始精度，百分比最多一位。颜色与P／C／F文字说明相配，不把微小扇区做成点击目标；总览与饮食入口共用展示。


未知不当作0；缺测断线，不能跨缺日连接或平滑真实波动。刻度整齐、覆盖全部数据，选日不改变坐标范围。缺测不在图边缘额外堆叠短横；选中日期的缺失原因在读数或详情表达。总览次晨结果显示在图上方的当天读数行。体重图由刻度说明单位。能量与kg分别使用单位和范围；柱图从零开始，局部折线范围按既有规则留余量。

总览上层绘制净收支柱，下层绘制次晨变化细杆，两层按同一日期对齐并各用自己的零线。图间距为电脑26px、手机24px。手机绘图区对称留边，7D柱宽上限14px，较长区间按日期密度绘制。手机每图标零点及一条圆整参照，参照线取实际刻度值及其纵坐标，绘图留白由数据范围决定。千卡在图例，kg随体重参照。点按沿用精确单日读数。电脑保留侧边刻度。确认持平显示零线短标，无法计算的日期留空。首次进入时两层从各自零线伸出。7D、30D、90D扩大区间时，共同日期先用约180ms向右收拢，补入的柱和次晨细杆随后用约220ms同时从各自零线伸出，沿用首次入场缓动。缩短时早期日期先淡出。快速换档从当前位置续接，减少动态效果时即时应用。

总览7D每天一条淡日期线。30D在首日、每隔五天及末日绘制七条。90D首尾和中间尽量均匀放五条，相隔约22天。日期文字独立按宽度显示。每条日期线在上下绘图区各画一段，图间保留可辨识的间隔。同一区间内，选中的日期用等宽的浅色带和竖线贯穿两层，日期文字独立于命中框，键盘焦点用金色实线。手机点按、电脑悬停或点击锁定，从柱或对应日期位置打开同一张三层卡片。日期与收支左对齐，蓝色摄入和红色消耗并排，次晨一行指出具体缺测日期、无晨重记录、无变化或实测变化。卡片用暖雾主题表面，靠边换侧，查看完整记录继续使用同一日期。「查看记录」关闭后保留已选日期及阅读位置。

蛋白质／碳水／脂肪查看时最多显示一位小数并去掉末尾0，手工填写最多接受一位小数；摄入热量、消耗与热量差四舍五入显示整数，手填热量／消耗仍只收整数，身体与kg差保留两位。格式化、聚焦和失焦不回写旧值，来源／备注修改保留旧精度。食量、包装换算及热量计算与落库不按展示提前取整；公开请求与查询精度保持。

网页餐次只需有效日期、餐次和至少一项有名称的食物；营养允许全部未知或明确0，未知不补0，空表单及无效日期／数量／单位仍禁用并说明原因。饮食及食材不按历史倍数弹窗或要求核对；同日严格重复餐只显示一次中性提示和查看入口，允许直接保存。实际修改保留增减与前后值。新建每日消耗及AI手工修改消耗仍要求当前采用的主要数值至少一项大于0，本人旧记录仅改来源／备注沿用既有例外；身体和运动原有数值提醒保持。上传、保存、真实版本冲突及草稿保护不因简化而绕过。

运动标题显示本次总数，分项与当天是否额外增加分开说明。例如运动741＋期间静息110共851，已包含在活动1357时不再额外增加；静息2058时当天3415。填写、详情与AI确认一致，不用无条件“计入741”暗示重复累计。固定总数与首节仅一条分隔线，修改包含关系与移除分开，至少16px可见间隔且点击范围不重叠。

活动累计与手填合计之间的替换属于需核对的操作：入口放“来源与备注”中的“活动填写方式”，确认框说明当前值、参与累计的运动和切换后的全天总数。清空手填活动仅将该项置为未知，不自动切换为运动累计或弹出累计确认。确认前不改变模式，取消保留数值、来源、包含关系；确认只改草稿，正式保存另行提交。

业务读数继续由服务端提供。部分已知、未记全、冲突、失败和确认要求如实保留；消耗估计标签不显示，内部历史标记及数值不改写；实现过程、历史初始化和推理文案不占普通展示区域。

AI消耗确认先按业务日期分组；手机纵向阅读，电脑同日左侧全天总数、右侧运动对照。先展示当天最终总数及紧凑分项，再展示运动；主要总数约32px（桌面36px），运动总数24px，单位跟随数字。来源、长备注和原记录按需展开，不堆叠模式与重复日期。包含问题仅在对应运动旁展示，明确后只留结论与修改入口；不放顶部批量按钮，不显示同值到同值的修改。组内更多取消须说明已有事实保留并二次确认；底栏写明新增／更新范围，单一正式保存。视觉样本必须包括待核对、已包含、额外增加、真实修改、同值不同精度、多日、未知和0。

### 加载策略与全过程验收

优先保留同账号、同页面、同日期／区间及筛选条件的上次成功读取内容，后台重新校验。展示缓存只在本人浏览器内存，每类页面仅保留最近一次成功视图、总计最多5组；退出账号、记录保存／删除／同步或明确读取最新后失效，跨日不复用。录入、编辑和草稿不缓存；迟到响应只归原请求键，不覆盖新日期。后台读取时旧内容只读，不从缓存发起设备同步或写入，保存仍核验最新版本。

首次没有同条件内容时立即显示已知标题、日期、导航、图例、图框与操作槽。超过350ms在所属区域显示一处低强调文本，真实内容准备好就原位出现。已有同条件内容时后台核验。

手机和电脑的饮食、消耗、身体主图缺少同条件数据或仍在准备尺寸时，在正式绘图区显示三条中性细线。桌面总览的净收支和次晨变化上下两层各用一组。350ms 后光带只沿细线横扫，减少动态效果时保留静态线条。真实数据和尺寸就绪的同一帧撤下占位，沿用柱从零线延伸、体重点先显再连线。图框四边保持一致。缓存图表直接显示，其后的展现沿用原位接管。失败进入既有重试，等待图层随即退出。

验收覆盖直接打开、刷新、模块切换、返回、同条件缓存、换日期／区间、慢请求、失败及重试。正常和慢速均保留连续录像与时间记录。已知标题、导航、日期／操作槽和图表框在固定视口、滚动下偏差≤1 CSS px，同时核对槽位文字、颜色和控件形状。最近记录按真实条数自然填充，变化单独记录。

正文切换记录等待、实页及正文缺失的全部呈现帧。空档使用当前目标的同一布局，真实内容就绪后原位接管。共用弹框从当前遮罩深度连续淡出，保持透明直到浏览器关闭弹框。验收记录面板末态及关闭后的帧，正文空帧、遮罩回黑和同页重复滚动均属于失败。

结果确认前，未知读数保留空位，记录或设备的空状态等待实际结果。失败就近重试并保留已有内容及草稿。设备尺寸、字体和容器变化纳入接管检查。只读预取不触发模型、上传或设备同步。截图、轨迹及未测项归入现行验收记录，核心过程未通过不得发布。

### D6：实际网页与交互共同通过

验收先写清用户要完成的事和成功时能看见的具体结果。从平常入口，用接近日常内容的虚构记录实际操作到结果和返回。观察入口能否找到、事实能否读懂、下一步是否清楚，以及返回后上下文是否还在。记录任务、实际所见、截图或连续过程，并给出通过／失败／未测。核心任务失败或未测时，界面验收不得判为通过。

例如核对历史会话，用一段可辨认的多轮交流，让验收者从列表找回它，说出用户问了什么、助手如何回答、所附照片或引用属于哪条消息，再返回原会话。两个入口展示同一条内容时，用同一份对话核对，检查足以理解原意的关键信息。列表分页要找到仅在下一页出现的目标。图表的尖峰、缺测与零值、慢网、尺寸和权限等检查按受影响功能选取，报告优先呈现用户日常任务的结果。

- 手机首屏视口：320×560、390×560、390×640、430×780，另查触屏横屏；涉及桌面或共用样式时检查1100与1440px。检查范围对应受影响页面与组件。
- 等字体、数据和默认区间稳定后，在 scrollY=0 截取实际视口；自动核对绘图区及日期刻度与底部导航的边界，再逐张人工查看。手机核对主要行动、状态卡、导航与详情层级，完整趋势视图核对双图和日期刻度；电脑总览核对双图，身体核对体重图，饮食／消耗核对有效读数及主要图形；矮屏可自然滚动，不能为同屏而缩字或裁剪；碰撞检查包含标题、选中读数、刻度，不只比较轴标签。
- 检查触屏横向选日／纵向滚动、键盘、菜单、弹窗、面板离开恢复、区间切换及布局稳定。来源历史必须在真实触屏浏览器上下文点选后回填，再实际保存核对；覆盖重复点选、输入失焦先于点击、列表滚动、视口变矮、外部关闭、键盘与中文输入法确认。不能以菜单出现或点击事件收到代替回填／保存成功；身体、消耗及AI确认共用入口都要检查。
- 动效用于触摸反馈、导航位置与层级连续性，允许有限形变、弹簧收束及整个面板连续移动。连续操作可中断并续接当前位置，不排队、不人为延长加载；图形与命中区同步，真实读数不播放虚构中间值，不能扭曲真实曲线或坐标。减少动态效果时移除非必要形变与位移，保留即时状态反馈。实际检查拖动、快速反向、滚动冲突、关闭、返回与慢网，不以静态截图代替动效验收。
- 有顺序的横向切换共用来向与去向。下一项从右侧进入，当前项向左让出位置，上一项反向。层级详情从右进入，返回从左接回来源。照片在下一张解码完成后移动，聊天与待办只切正文平面，标题、输入边界和独立滚动保持稳定。减弱动态时直接交接。
- 食材库两个入口分别验收：餐次窗口里的选择列表，以及从饮食页进入的独立食材库。独立入口核对统计卡右缘的挂签、营养详情、加载原位、图表命中和返程恢复。切换为手机网格列表时，电脑百分比列宽必须退出；实测名称框应铺满分配区域，不能只检查容器无溢出。长中英文名称应自然成行，不能因列宽被重复压缩而一词一行。
- 共用录入组件必须使用同一组混合数据：自由项、长中英文名称、包装项、按克项和空白行；检查完整的份／包／g／mL、长小数、未知和0。手机逐条滚动查看并留图，不能只检查首项。打开每种详情，覆盖顶部、底部、滚动后位置及Escape／外部关闭。
- 详情改动必须同时比较单餐与多餐、总量与分项、日期与所属内容，检查结构横线及重复日期／文案；计算间距并保留展开、悬停、键盘与手机截图，不能只验证控件存在。
- 排版改动按需要量取可用文字宽度、字号、行高、对齐和浮层边界，并按正常显示比例查看实际内容。改到共用编辑器或其入口时，走完受影响的填写、核对与保存流程。
- 每一项分别记录通过／失败／未测／不适用，未测不得计为通过。任何核心文字裁切、混乱对齐、浮层远离触发点或不合理空洞均为阻止发布的问题；测试数量、DOM存在和无报错不能代替视觉结论。
- 验收记录写明浏览器、视口、模拟安全区／工具栏、适用条目、截图和结果。未测与未通过必须明确标记，不能用“无横向溢出”代替首屏验收；真实iOS和软键盘体验不能由模拟测试冒充。

### D7：同类组件一致与双端适配

### D10：双色主题与应用版本提醒

外观通过持久顶栏账号图标旁的44px日／月按钮直接切换，业务内容与详情不重复摆放。账号菜单保留单个“跟随系统外观”开关，点日／月改为手动模式；沿用本设备偏好，未设置默认深色，系统变化和跨标签同步继续有效。手机按真实剩余空间排列Logo／返回、页名和助手／主题／账号，不绝对居中压住操作。登录人物首页固定深色。

### 跨端控件材质与反馈

手机和电脑共用暖色材质与清晰的选中态。轻玻璃主要用于导航、浮动助手入口、菜单和独立工具。正文里的清晰文字操作，以及小助手输入栏的加号和模型选择，平时直接显示文字或图标。发送和停止共用一个清楚的圆形底色。表格、图表、照片及文字录入采用易读的内容底，保存键使用明确的主操作样式。玻璃下方有图形、文字或深色背景时，核对实际合成后的对比度。

账号菜单和模型菜单以一块可见轮廓从真实触发点展开及收回，内容随轮廓露出。边缘折射仅在实测支持的环境给背景像素做局部位移，前景文字和图标保持清晰。折射不可用时沿用相同轮廓，使用遮蔽更强的暖色材质。减少动画时直接到位，减少透明度时使用实色。空间不足时在菜单内部滚动。模型菜单位于按钮上方 8 CSS px，附件、长稿和键盘改变可用空间时按实际按钮位置更新。用浅深主题、Chromium／WebKit 的窄屏与桌面复查按下、开合、快速反向和操作结果。实体 iPhone Safari 的系统键盘、日期选择器和触摸手势单列结果。

### D11：录入任务、草稿与反馈

新消耗的自动静息预览、浏览公式及切换填写方式不制造草稿；手填内容、运动和明确选择的全天活动档位继续保护，切换后可恢复的输入也不遗漏。删回空白可直接退出，清空已有记录仍保护，异步读取计算依据不制造未保存提示。

界面工作先用 Mobile Design 检查任务起点、当前填写、保存结果及返回路径，再用 Impeccable 比较同类控件的字号、边框、层级与交互状态，最后用 Unslop 对真实问题作适度打磨。三者共用D1的布局依据和D6的任务验收方法，保留品牌识别和业务含义，不增加运行依赖。

同组字段的密度以实际阅读关系验收：食材热量／蛋白质／碳水／脂肪默认四项同排，只有实测文字宽度或文字放大确实放不下时退为两列／一列；不得继续继承旧的固定两列。字段只由一层gap控制8–12px组内间距，不能叠加label下边距、网格gap与分组margin。身体空白与已有实测共用字段行高，数值和单位保持基线，不新增提示行将来源向下推。直接录入不重复返回按钮与晨晚说明，晨间空腹条件归入“晨间（空腹）”按钮，不作为独立文字插在两个时段与设置之间；辅助条件必须与所属选项相连，不能看成第三个选项，也不新增说明行。配对字段的选填提示使用短字，不让一侧标题常规字号下换行并错开输入基线。视觉验收同时检查实际同排列数、数字完整、同组字段间距和状态前后位置，不能只检查字体／触控下限与无溢出。

身体编辑的标题和日期在手机居中，更多设置与紧凑晨晚分段同行，体重／体脂、来源和保存按填写顺序排列。面板按内容增高，手机身体录入标题不支持拖动。键盘收起时保存按钮下方至少保留16px，开启时保留12px。短屏字段区滚动，来源候选随输入框定位并限制在面板可读区域内。电脑晨晚并排。编辑已有单时段时先打开该时段，其他编辑默认晨间，明确时段链接优先；切换保留两侧输入和未保存标记，保存提交所有实际修改的时段。保存失败在保存操作附近说明，保留来源、时区及两时段草稿，不覆盖另一时段。

草稿保护按有效内容对比初始状态，不按是否聚焦、点过标签或展开设置判断。空白输入后删回空白可直接退出；清空已有值仍保护。数字比较不使用舍入显示，70与70.00等价，旧精度不回写。自动沿用来源不制造草稿；本次清空不自动补回。内部返回、Logo、导航、关闭、Escape与遮罩共用“继续编辑／放弃修改”；刷新与关闭浏览器保留原生离开保护。保存失败保留输入，不新增云端草稿。

总览和助手待办发起的饮食、身体、消耗快捷录入返回实际入口。关闭、Escape和浏览器后退经过同一草稿保护。放弃或完成保存后退出录入地址，刷新及前进显示普通记录页面。其他时段仍有未保存输入时留在原编辑面板。独立设置页返回发起页面与账号入口。常用功能打开的独立工具返回待办原分组、滚动和入口焦点，独立地址直达使用页面标出的父级。

来源习惯仅用于身体新录入：晨晚合并，目标时段之前最近连续3次采用中的有效实测来源一致且仍在来源建议中，才预填；同日同槽只计一次，空来源中断。补录不采用未来设备，不覆盖已有记录或手工输入；清空后本次不补回。说明“已沿用常用来源”，仍可直接更换。身体与消耗不混算，不扩大AI来源权限。

小助手事项、忽略与常用功能遵循下文统一交互。电脑区间摘要在双图之后按已应用范围说明可计算收支及资料不足天数，缺口原位展开、每批50日，不随悬停改写；手机总览移除此区域。

只有真正空白的餐项可忽略。无名称但填写营养、明确0或其他内容的行保留草稿与已知合计，提示缺名称并禁止整餐保存；退出可继续或明确放弃。AI食材只改名／备注保留每包与标签基准，缺必要包重不猜。超额照片在修改队列之前整批拒绝，剩余容量明确，原照片与合法缺图事实保留。

消耗编辑任务的添加运动入口直接展开一条空草稿，普通编辑不额外添加；空白退出不提醒。保存失败必须在主保存操作附近可见：消耗两端均位于底部保存区，身体在字段后保存区；输入保留。三页历史日历有明确查看按钮，Enter和同日反复打开均有效，分页与滚动保持。导出在原页验证日期并异步请求现有受保护文件入口，失败保留范围并给重试／重新登录，不导航到JSON。

消耗手机编辑依次为日期、紧凑记录方式、数据及各自来源、步数、运动明细、备注与更多操作；合计和保存贴底，短内容不在保存下留大块空白，长表单仍可滚动。分开记录／只记总数使用14px文字及44px点击范围，分组间距由单层容器控制。日期与饮食共用一个可见边框的原生日期选择器，加载禁用时也不露出底层输入，不水平滚动。时区和备注低频展开，不重复日期。改期核对原编号、原日期和版本，每日汇总与运动整批移动，有运动时明确确认；目标日有记录则拒绝合并并保留输入，来源时间不随日期自动改写。

主输入至少16px、点击至少44px；可编辑字段有稳定边界和底色，只读值使用不同外观，“未知”不高于主输入。手机长名称自然换行，不让电脑百分比列宽挤压成逐词窄列。验收覆盖空白退出、删回空白、已有值清空、实测保存反馈、全时段来源、提醒边界、无名营养、包装改名、超额照片、长表失败、同日历史、导出异常与教程8秒超时。教程加载期间文字流程、返回与开始使用保持可用，更新失效片段而不重复提速。

### D12：查看与填写的操作归属、紧凑营养与同规则对照

消耗录入按已认可的三种记录方式组织：帮我估算／手动输入／从设备同步。默认估算只展示静息结果与圆圈依据，公式及重新计算收进按钮旁的计算设置浮层；活动估算／运动明细仍平级互斥。手动输入直接显示同样式的静息和活动输入，右侧保留“只有总数？”入口；静息旁的估算展示方法、各自结果和依据，选择后填入且仍可修改。设备直接展示已采用事实，不呈现可编辑外观。四档不跨日预选，计算及设备包含关系、补填和草稿保护保持。

消耗录入以已认可修订稿为基准：日期之后为三种记录方式，接着是该方式的结果或输入。静息估算与设备读数为28px只读文字，手动分项为24px输入、其他输入仍为16px。估算页不放活动占位框、总数切换或常驻公式下拉；缺资料提示与补填直接显示。步数标签与输入、运动明细与添加运动仍各自同排；来源、备注、时区按需展开，底部唯一合计与保存保持。计算设置与手动估算使用按钮旁浮层，不把下方内容挤开；可外点／Escape退出，键盘返回按钮，补填返回恢复选择。200%文字自然增高和退列，不能裁切。

参考对照必须使用相同视口、字号、填充值、展开状态和主题；本表单以390×845及1539／331／6500为正常字号对照。逐项核对实际同排关系、主次字号、控件高度、分隔线及组间距，保存并排图；任何未按已选方向落实的差异不得以“功能可用”“没有溢出”或“保留旧组件”记作通过。计算样式必须检查浏览器最终值，尤其覆盖通用form规则后的字号与高度。

这些规则同时约束既有工作流与已纳入的Unslop，不是某个技能的专属输入。

- 身体、消耗、饮食与食材的查看任务只展示事实、来源、状态、照片与历史；允许展开和切换查看指标，不挂载编辑表单，不提供录入、编辑、添加、删除、估算、记全或采用候选操作。饮食、消耗与食材的外部列表并列提供中性实底的“编辑／录入／补录”和次级“查看”，同级样式一致且点击范围至少44px。
- 身体最近与历史日期行以晨晚读数为主，右上「编辑」，右下「详情／收起」。同日明细从所属时段标签起点左对齐，长来源在列内完整换行。空时段用静态状态，空白日提供录入或补录。编辑关闭恢复原行、展开状态与焦点。有效保存用中央向两侧约200ms的按压反馈，等真实结果。
- 饮食日期“编辑”进入当天餐次管理，添加一餐、餐次编辑／更多删除及已记全只在此任务内出现；单餐保存后回到当天编辑列表。查看与外部列表的已记全仅展示状态。消耗的活动增改移除和日记录删除归编辑任务，有活动而无日汇总也显示编辑；食材删除归编辑中的更多操作，保留永久删除确认。身体候选可只读浏览，候选采用与实测维护仅在录入／编辑中可用。

- 饮食手填与库选共同编辑同一餐。手机分类包含全部、肉类、蔬菜、主食、其他和整餐。备注与附照片放在食物之后，外观低于本餐合计和保存。桌面以34%／66%分配食材库和本餐；宽度适合时库选与手填四项营养直接同行，较窄本餐栏中四项一起到下一行。局部图层参考和检查按 D4 的实页流程执行。
- 身体录入的日期属于“身体录入”标题，放在标题旁；不再为日期和保存重复建立一行。输入保持晨晚及来源顺序，删除单项保留原确认并归“更多设置”，不挤压主数值输入；首次等待与真实内容复用同一头部和禁用表单。唯一“保存录入”位于字段之后右侧，错误与结果贴近保存。长内容中操作须可到达，菜单／键盘不能遮挡操作；不为把按钮推到视口底端制造空白。
- 长表单的持续计算预览保留真实核对用途。消耗手机合计与保存置于底部操作区，避免顶部大号重复总数；桌面维持原结构。日期、主保存和所属草稿始终一致。食材列表操作与食材编辑保存遵守相同控件基准。
- 每日消耗主按钮只写“保存”，可访问名称说明目标日期；日期位于顶部记录信息区，完整日期作为不可拆文字块，空间不足独占一行，不缩字或裁切。两端Inspector标题直接排列在面板底色上，无独立胶囊、内高光、弧线、模糊或负边距。电脑保留侧栏宽度与滚动，把手隐藏且不占位；手机保留外层圆角、把手及关闭叉，拖动区与面板连续。关闭及展开／半屏控件至少44px，键盘焦点只围实际控件；装饰把手不单独获取焦点。
- 手机底部面板的标题以整个面板中线为准。左右操作槽等宽，返回、展开和关闭各自至少 44×44 CSS px。返回位置固定在左侧，空间足够时显示短标签，窄屏只显示箭头并保留完整可访问名称。标题较长就在中央列内换行，日期在可用空间内保持完整。粘顶高度随实际标题测量，滚动与输入聚焦使用同一个避让距离。逐级返回保留搜索、草稿和发起操作的焦点。验收以 320／390 CSS px 的真实标题位置、可点击范围、长标题和连续进出为准。

- 需要设计对照时，先实现共同规则并冻结A，再从完全相同的A创建B，额外运行固定版本Unslop。比较数据、草稿、日期、主题、视口、浏览器、时钟和展开状态保持一致。功能、字段、操作顺序、计算、文案事实与原始精度相同；共同修正不算作Unslop独有改善，差异与代价逐项记录。
- 既有共同规则与已采用的Unslop方案作为回归证据，原A与对照截图保留。局部修正不强行让所有页面产生差异；已授权的手机重设计可替换其首页构图、导航和转场，不把历史A／B布局当成永久限制。用户同意纳入Unslop与本地方案不自动授权发布或更新main。

- 信息取舍先于间距调整：默认视图只保留识别信息、主数值和决定含义的短状态，不能把完整名称、长备注、计算依据和所有操作直接铺在收起行。饮食收起为餐次、热量及最多一行食物摘要；长摘要可明确省略，展开后隐藏重复摘要，直接显示本餐三项宏量与完整食物清单；热量只保留餐次标题及各食物所属读数，来源数量统计退出。自填、食材库与拍照共用持续挂载的面板头部、日期和餐次，方式切换保留草稿与照片；返回当天编辑并入头部，空草稿底部只保留一处状态与保存槽。食材库不重复标题和返回行，手机不主动聚焦搜索。食物默认显示完整名称、份量和热量，点该行原位查看宏量、来源与依据；备注／照片有内容才提供折叠入口，打开附件后加载原图。按当前食物、附件、餐次顺序处理Escape并恢复焦点，下一次才关闭日期详情；不能省略必要数值和单位。
- 展开层级按任务递进：第一层摘要回答“是哪条、多少、如何计入”，第二层展开提供完整事实；编辑任务另提供维护动作，第三层“更多”仅放删除等低频操作并保留原确认。展开入口始终可见、至少44px、键盘可达，开合标记一致；不依赖悬停才能发现完整信息。更多菜单Escape先关闭并恢复焦点，不能同时关闭整个详情。
- 运动摘要保留本次总数、运动／期间静息分项及简短计入状态（如“已含在活动合计”）；时长、来源和完整包含解释在本条展开后查看。短状态与长解释从同一共用计算结果产生，不能靠截断长说明丢掉未知、额外增加、历史未计入或待核对事实。已有顶部总数不在收起行再重复整句。
- 验收同时检查收起、展开、更多、删除取消及返回状态；手机和电脑使用同组单餐／多餐、长名称、已包含／额外／未知／0样本。确认摘要易扫读、完整事实可找到，且不出现句尾孤字、缩字、数值裁切或隐藏内容占位。规则共同约束基准工作流与Unslop，不以减少线条或压缩间距代替信息分层。


### 公共食材库与记录一餐

公共参考的各类名称在同一列表按约 160 ms 原位开合，分类标题字号与行高固定。类别内再展开食物及部位，按食用态、熟食或生重呈现。手机结果简图约 32 CSS px，垂直对齐名称块。长名称可换行，份量与详情可读，整行触控至少 44 CSS px。电脑个人食材在名称右侧使用约 40 CSS px 简图，展开处只呈现规格补充、换算、依据与附件。公共参考详情继续呈现具体做法、每 100 g 可食部或每 100 mL 营养、实际用量和来源。

宽桌面餐内详情使用完整左栏，右侧本餐和保存留在原位。左栏独立滚动。窄桌面和手机的标题及返回入口随「本餐、列表、详情」更新。详情和列表以 200 ms 左右的淡变与相反方向轻移交接，快速折返从当前动画姿态接续。独立食材库按内容区实际宽度采用并排或单栏。详情返回原搜索、展开位置、滚动和焦点，加入或更换返回发起操作。无匹配可带词转手填。开启减少动态效果时即时交接。验收以连续录屏和关键帧检查展开、切换、返回、加入、保存与回看。

公共整餐详情在菜名下放「按整份记｜拆开记」双段胶囊。整份录入左边选「按比例」、右边选「填重量」，下方共用全宽滑条或克数框，两态总览顶部对齐。显示参考一份的可食克数，默认 100%，每 5% 吸附。总览紧接整餐组成，宏量可收起，完整依据可展开。拆开模式按原料及调料对齐选择、名称、份量和单位，可添加实际配菜及调味，已有项原位改量。有同规格计件依据的分项在输入旁提供贴合的单位胶囊和参考重量。数字输入保持至少 16 px，滑条、单位和主要按钮至少 44 px 触控边界。加入后本餐和保存历史以一个菜名呈现，按需展开分项及来源。相关整餐在原详情内继续进入，逐级还原触发位置与已有输入。

### D13：设备连接与直接同步

- 从账号菜单“外部接入 → 设备与数据来源”进入；电脑独立页、手机底部面板。开放范围由服务器 personal／pilot／disabled 模式决定，未配置沿用原固定账号试运行；personal 只管理本人的连接，pilot 的固定user_id不能由owner角色替代。未开放账号显示真实空态，不查询连接或健康事实，无绑定控件。
- 首次无内容时先显示已知标题、日期、图例、图表框和操作槽。超过350ms在与未返回内容相同的位置轻显一处「正在读取…」，真实内容到达立即就位。已知事实、无数据和读取失败分别呈现。
- 保存配置和读取为明确的两个结果：配置成功但上游失败时保持已保存选择，只重试读取。草稿、忙碌、错误与版本保护保持；同步局部反馈，不清空图形、重播入场或覆盖草稿。
- 来源运动全部有效载入；相似手工记录独立保留，不拦截或自动合并删除。同一连接及activityId幂等更新。只采用日汇总计热量，源明细不再加到日总数；未知不补零，部分／零不伪造占比。手动保护与历史不一致的手工总数保持；保护日只追加全新源明细，不复活手工删除或覆盖维护过的明细。
- 今日设备累计以“今日已消耗”所属标签表达，详情将步数和相同来源合为一行，不重复“来源同步”“今日累计，尚非全天总数”等解释；必要异常只出现一次。运动的来源事实与gross／BMR在展开后保持可查，不猜纯运动值。
- 同步勾选不改变上游密钥权限；暂停保留历史，来源覆盖结束时间不冒充手表最后同步时间。后台每日任务及前台最短间隔保持，凭据不持久化到浏览器或进入日志／AI。

### D14：AI 接入、紧凑列表与提交来源

- 页面只有一个可见的“AI 接入”标题；电脑正文28px、手机顶栏20px，均600字重。保留品牌与漂浮导航。ChatGPT始终第一行、豆包第二行；每行约64px，以名称18px／600字重为行内最强信息，状态、权限摘要及操作14px常规。未接入豆包的“内测 · 需联系管理员加入白名单”紧邻所属行，已接入只留内测标识，不提供公开测试二维码或虚构联系方式。
- 权限默认收起。电脑在按钮附近打开紧凑浮层，手机沿用底部面板；四类实际权限使用“查询／提交预览”共用列头。同AI多连接分别展示，按当前同意与原scope交集显示，不合并或自动扩权。只读是正常状态；失效、撤销、停用不表示可访问。未接入显示可申请权限与明确的接入按钮，失效显示重新接入。手机未接入行的接入按钮打开步骤及历史，已接入的“详情”合并当前管理与历史。
- 连接方法、授权／最近使用／真实到期时间及撤销留在管理内容。历史名称与辅助时间电脑14px、手机13px，次级颜色；撤销14px，不超过当前AI名称。撤销保留确认、失败就近重试、成功保留原操作结果；有效期仍为30天。44px仅为点击范围，不能放大文字满足触控；焦点框紧贴控件，不覆盖整行或整个页面。
- 权限组内8—12px、列间16—24px，单层控制间距，按内容排布。正常手机保留三列；文字放大或空间不足时，整行改为数据类别及两项带标签状态，不缩字、不裁切。输入和下拉保持16px，长内容自然换行。
- AI提交记录默认收起，分区标题16px／500字重，筛选与标题同行，极窄空间自然换行。电脑展开后按“时间｜来源｜内容｜状态｜查看”一条一行，正常行高44—48px；手机显示“来源｜业务日期与短摘要｜状态｜查看”，完整提交时间在原审核详情查看。记录正文与操作14px；长名称、混合内容与200%文字自然增高，不固定拆成三行。
- 记录跨业务按提交时间倒序，来源依原OAuth／令牌及子操作追溯，手动来源注明令牌名，未知或冲突不猜测；初始化仍留在饮食入口。保留原筛选、审核、部分保存数量和真实预览期限，不统一写15分钟。
- 开合约160ms淡入与轻位移，悬停、按压及键盘焦点就近反馈，减少动态效果时即时交接，静态状态不循环播放。页面统一说明“AI可查询、提交预览，保存由你确认”。
- 设置页读取超过350ms才显示局部等待。首帧保留标题、两条AI行及操作槽；未知状态不闪现为未接入。连接与历史独立接管，保留已展开面板及焦点。正常与慢速查询都必须记录五个结构锚点及两个AI名称的全过程，最大偏移不超过1CSS px。

本页沿用Mobile Design、Impeccable及D7中的既定Unslop版本、署名和许可。以已认可ImageGen桌面／手机内容区为参照，当前视觉对照见根目录`design-qa.md`；实际截图、并排图及逐帧JSON保存在本机`C:/Users/14878/.codex/visualizations/2026/11/11/01a1cb4e-f688-7e00-82e5-c39be8e68155/formward-ai-access-compact`，均为虚构账号。普通AI行64px、提交48px、权限组内8px／列间20px；正式包验收及未测项以当前视觉验收和维护验收文档为准。模拟浏览器和等效文字放大不记为真机、软键盘、屏幕阅读器或系统字号验收。

### D15：站内聊天、模型选择与每日用量

站内聊天按独立会员档位开放，Free保留确定性提醒、手工记录和每日4次本餐识图，聊天标Plus；内测与Plus及指定管理员可聊天，Pro暂不开放。用户只见用量百分比或识图次数。业务、授权、预算与接口规则见[站内助手](assistant-chat.md)。

- 电脑采用背景可见的双栏非模态浮窗，常规宽860px、左栏312px，窗口收窄时优先给右栏保留足够的输入宽度。右侧专注聊天，不重复显示聊天／待办切换。左侧三个“手动记录”动作各一行，下方依次按需补记、AI确认、常用功能，统一向下展开，不能向上覆盖内容。AI确认计有效待审核批次。桌面餐次摘要以13px原值和6px组间距同行呈现蛋白质、碳水、脂肪。超长值按项折行。训练和使用说明等归常用功能。
- 手机从底栏直接进入独立助手页。返回、聊天／待办、历史和新对话在同一行。聊天在左、待办在右，两侧进出和快速折返按这个顺序。选中背景与文字使用同一对深浅主题色，触屏悬停保持足够对比。历史列表返回聊天，详情返回原列表条目。历史正文横移时标题和不透明底层稳定。列表用整组圆角和与文字对齐的内缩分隔线，详情标题、正文和「回到这段对话」对齐。行内左滑从右侧露出红色删除，也可从行尾「更多操作」进入。用户确认后移出本人历史。当前与历史使用同一消息排版，记录摘要沿用可核实的状态和事实。切换保护草稿、照片、阅读位置及焦点，触控区至少44px。
- 标题18px／600，欢迎21px／600，说明14px。欢迎为「今天想聊点什么？」，说明「可以拍照记饮食、记录体重或查询记录。」在320px及以上正常字号完整单行。当前与历史正文均为15px，输入16px，操作14px，来源及时间13px。输入提示是「想聊点什么？」，长内容在原输入内自然增高。
- 主输入行从左到右依次是加号、文字、当前模型和发送。发送和停止共用一处，手机以36px圆形呈现，触控区至少44px。照片选好后出现在输入栏左上方。短输入行上下各2px，输入16px，边界清楚。附件和文字共用同一外框。文字、附件和控件沿用普通输入、焦点及按钮状态。
- 选图即显示72px缩略格；准备暗色遮罩、传输真实字节百分比及圆环，100%标核对中，服务端登记完成才可发送。每批随当前网络自动选路，不永久记账号地区；单张取消、重试、人工换通道与国内备用上传保留原文和其他附件；原图不缩放重编码。回放、真实存储和真机Safari分开记结果。
- 手机底栏与助手外壳由同一个固定视口定位。底栏贴底并应用当前安全区，助手顶栏贴顶。软键盘开合时按可用高度调整内容区底边。键盘打开后若外壳实际移到可视区上方，按外壳边界补偿，保持顶栏与输入区可见。输入行保留至少一行文字和 44px 触控区。矮屏中照片缩至 48px 并可横滑，引用摘要保持一行，引用、提示与附件共用输入行上方的可滚动区域，空间不足时从该处滚到照片操作。长草稿在原生文字框内滑到首尾，同一次触摸在边界反向仍能继续滑，高度变化时保留阅读位置。光标在末尾且内容追加或已读至底部时仍跟随末尾。
- 手势归属从按下到松手保持。文字、照片、附件和输入周围留白分别接收自己的触点，消息区只响应从消息区开始的拖动。验收包括键盘上方缝隙长按、先横后竖、首尾继续拖动及同高度的迟到视口偏移。系统视口稳定时，顶栏、发送区和未起滑的聊天列表在拖动及松手后偏差≤1 CSS px。实体 iPhone 单独用系统中文键盘核对，浏览器模拟另记。
- 助手入场首帧使用完整不透明底色，前景只做横移和淡变。外层滚动锁不改写页面定位，进入到退出期间保留来源滚动。退场首帧原来的底栏和来源正文同时露出，路由恢复后归还入口焦点。从已滚动的总览分别用助手返回和浏览器返回，再快速打开。逐帧核对固定视口下底栏和助手顶栏的纵向偏差≤1 CSS px，另核对实际窗口和安全区变化后的底部锚点。

- 饮食拍照留在当前餐次面板：原图上传及可选说明→识别→补充→回填待核对草稿→用户统一保存。面板定位、视口补偿与滚动复用录入面板的可视视口处理。用双浏览器模拟检查布局和完整录入，实体 iPhone Safari 和系统软键盘单独记录。键盘开合不重播面板入场，布局只采用一套位置计算；键盘出现后让工具行随内容滚动，当前输入框保持在可视区域和标题下方，不依赖聊天状态，不重建焦点或文字。保留手填、日期和餐次；重复识别沿用预览，迟到结果不能覆盖已变更草稿。独立任务不挤占主聊天当前会话，共用模型、授权、用量及每账号单生成限制。

## 产品参考

Formward 学习 MacroFactor 组织高密度健康信息和减少录入步骤的方法，不照搬其品牌、文案、图标、具有识别性的整页构图或视觉资产；可采用通用交互模式。以下保留已有调研；未实现的教练和训练功能不作为当前界面要求。

## 值得学习的产品设计

### 同时提供今日、每周和长期视角

MacroFactor 的营养看板把当日摄入、每日目标和一周进度放在同一组件中；Energy Balance 使用更长时间区间观察摄入与消耗；Expenditure、Weight Trend 和 Goal Progress 再提供解释性指标。

Formward 应保持同样的信息层级：

```text
现在发生了什么
→ 本周是否形成趋势
→ 长期目标是否需要调整
```

### 将事实和解释分开

MacroFactor 的看板既有 Scale Weight、Nutrition 等原始记录，也有 Expenditure、Weight Trend 和 Goal Progress 等解释结果。

Formward 页面必须区分：

- 事实：用户、设备或导入产生的记录。
- 派生值：根据明确公式计算的汇总与趋势。
- AI 判断：包含假设、不确定性和可追溯依据的建议。

三种信息不能使用相同的确定性语气。

### 让高频记录足够快

MacroFactor 通过统一 Food Logger、Plate、多入口快捷操作、常用食物和批量记录减少重复步骤。Formward 的 PC 端从手动汇总录入起步，并逐步支持：

- 全局快速记录入口。
- 键盘优先输入与搜索。
- 常用餐食、运动和模板。
- 一次提交一整餐的多个条目。
- 外部 AI 助手通过正式 API 提交候选记录，并由用户检查需要确认的写入。

### 看板可调整，但默认必须优秀

MacroFactor 允许用户隐藏和调整看板模块。Formward 首版先提供经过设计的默认布局；用户形成稳定习惯后，再增加组件显示、顺序和密度设置。

### 教练体验保持克制

MacroFactor 的 Check-In 在固定节奏中给出调整，并允许用户拒绝；其 adherence-neutral 理念关注实际行为而不是对偏离目标进行惩罚。

Formward 的 AI 教练应：

- 先解释观察，再提出动作。
- 只在答案会影响决策时提问。
- 允许拒绝、修改或延后建议。
- 不使用羞辱、夸张警报或道德化食物标签。
- 明确区分一般健身建议与需要专业人员判断的健康问题。

### 双端连续交接与指标偏好

- 手机总览一张宽卡为主，下一卡露出约24px；按账号／设备仅一次的晨重8px双次引导在触摸、滚动、导航或减少动态效果时停止。
- 首次无内容时先显示已知标题、日期、图例、图表框和操作槽。超过350ms在与未返回内容相同的位置轻显一处「正在读取…」，真实内容到达立即就位。已知事实、无数据和读取失败分别呈现。
- 手机饮食为热量主读数及小型供能环，餐次构成直接列在所属区域，宏量与依据按需展开；消耗为总量主读数及同行静息／活动数值和真实比例，不再重复两张分项卡。未知、部分和零不伪造百分比。长数值按实际宽度整组退让，不缩字裁切。原右上记录动作退出，首页／助手／日期行保持可达。
- 身体页使用体重主读数、紧凑的较前一日／7日均值及一个当前指标趋势；分区不重复留出卡片空白，不叠加完整双图。设置沿用账号偏好，体重必选、体脂可选、骨骼肌指标未开放；单项／双项录入、隐藏事实、严格相邻日差及7日窗口规则保持。
- 手机账号菜单在按钮附近连续展开；助手、记录、详情、资料／安全和管理统一从底部上来，电脑保留对应锚定浮窗或侧边详情。不得混用全局来源矩形，草稿、忙碌和焦点保护保持。

### 加载与材质的阻止发布条件

- 从总览进入关联趋势时，顶栏及导航位置固定，离场与入场的正文用同一条时间轴。首个可见的详情正文内，图形、坐标轴、图例及已知数值一同出现。主读数仍未知时，等待文字在读数槽。同日主读数已知时，等待文字在最近记录标题下。详情露出超过350ms仍在读才显示文字。窗口或日期变化交给当前有效请求。
- 验收保留原速实录，核对总览正文开始退出、详情正文紧接出现、图形和坐标轴同帧，以及局部等待和真实内容的接管。关联趋势阅读保持当前滚动。

- 逐页检查总览、饮食、训练、消耗、身体：固定文字、真实日期网格、图例和操作槽首帧可见，未知值不补零。任何缺失、错误空态或虚构记录均失败。

### D17：鸿蒙启动与系统交接

鸿蒙首版沿用已认可的网页与品牌。新增原生层只承接联网前隐私选择、系统选择器、文件保存、返回和恢复；不在启动页重复业务导航。母版 F、小写 formward.、暖纸色／深橄榄黑、金色主操作与系统中文字体保持。首次页先给标题和短说明，再给本地协议入口，底部为 52vp 的“同意并继续／暂不使用”。失败页使用相同层级和底部锚点，承接“重新连接／应用信息”。浅色链接使用足够深的金棕色，系统安全区绘制连续背景。

首次同意前不创建远程业务页。本地协议不执行 JavaScript，加载超过350ms在原内容位置提示。有效会话冷启动直接打开总览；未登录沿用现有登录。成功登录交接不再触发登录输入的丢弃确认，实际未保存的业务输入仍受保护。
