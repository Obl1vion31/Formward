# Formward 设计与视觉验收

本文件是 Formward 手机、桌面界面设计和视觉验收的统一依据。涉及界面修改时，实施前与验收前都读取本文；验收记录逐项对应下面的适用标准，附实际网页截图、结果及未通过项。调研和页面说明引用本文，不另设一份竞争的检查清单。

## 信息层级与布局

### D1：首屏先呈现核心事实

先明确用户打开页面最需要看到什么，再安排控件、说明和详情。手机优先考虑一眼能否看到重点，不能只把桌面组件改成纵向排列。

- 总览：选中日摄入、消耗、盈余／缺口，以及共日期的热量收支和次晨变化两图。
- 饮食、消耗：明确日期的有效读数及主要图形，随后是每日记录和补录。
- AI 确认：日期、本餐营养合计、前两项食物及统一保存；图片、依据与次级操作按需展开。
- 身体：手机首屏展示当前体重、当前体脂率及完整体重图；近7日变化、均值按需展开，体脂图允许下滑查看。桌面保持六项摘要。

当前没有数据时显示简短空态；日期、未知、未记全及估计状态保持准确。新增内容先确定优先级：主数据 → 查看／录入 → 次要状态 → 解释详情。次要状态不能独占与主事实相同的大片区域；“已记全”用紧凑勾选控件，文字始终保留；勾选后显示对勾、文字变淡，仍可取消。保存中不替换文案。

### D2：按实际可视空间验收

首屏空间扣除页头、底部导航和安全区；浏览器工具栏占用通过较矮视口模拟。总览手机在默认区间、加载稳定且未滚动时，两幅完整绘图区和共用日期刻度必须位于底部导航上方。

先压缩重复内容、无意义留白和低频控件，再调整图形高度；不能缩小整幅 SVG、裁剪数据或隐藏下层图来通过检查。横屏和文字放大允许自然滚动，优先保持可读和可操作。

### D3：紧凑与可读同时成立

读数、标签、图形形成清楚层级；少量数据不必拆成多行大块。日期与所属读数放在一起，相关图表紧邻，筛选区域上下间距一致。长数字、未知和状态变化不使布局跳动或横向溢出。身体记录的晨间／晚间标签与各自读数保持完整，桌面同排，窄屏允许按时段组换行。

图表标签实际显示至少12px；空间不足时减少等距标签数量，保留单位和关键零线。触屏常用按钮保持至少44px高的可操作区域，不能仅靠缩字缩按钮换取密度。

### D4：高频操作直接，详情渐进展开

账号、低频设置和解释放入菜单或展开区。输入框可辨认、单击可填；标签与控件保持约10px间距，带边框的输入内左右保留10–12px。表头与实际字段一一对应，食物、单位、数量分列；辅助说明放表格下，不撑偏单元格的主输入基线。键盘焦点清楚；SVG点击列不显示浏览器默认大外框，键盘焦点限定在绘图区内。图表选日直接点击，固定日期后可点图外或按 Escape 解除；控件不能重复占据主内容空间。

总览、身体、饮食、消耗共用选日状态、区间按钮、每日列表行和Inspector外壳；业务专用内容留在对应模块。桌面悬停预览、移开恢复、点击固定，点击其他日切换；图外／Escape解除。范围内固定日保留，越界解除；无独立前后一天控件。查看记录放在日期／图表标题右侧，不另加图下操作栏。

最近记录始终显示今天，前6个日历日只保留待补录、补全或确认；其他日期从“查看全部”进入。“查看全部”放在最近记录下方，在页面内展开历史日期，每批50日并排除重复日期；再次点击收起，保留已加载批次。单日查看与编辑才使用Inspector，关闭后恢复页面滚动和触发焦点。主列表不展开餐次、图片或运动全文。未知不当作0，空日期不写占位记录。

颜色同时配合文字、圆点／方点、虚线或标记；不单靠颜色表达状态。照片和大段依据默认收起，需要时再查看。

### D5：外观不改写事实

未知不当作0；缺测断线，不能跨缺日连接或平滑真实波动。刻度整齐、覆盖全部数据，选日不改变坐标范围。缺测不在图边缘额外堆叠短横；选中日期的缺失原因在读数或详情表达。次晨标题与单日结果合并在两图过渡区右侧，不挤占刻度。能量与kg分别使用单位和范围；柱图从零开始，局部折线范围按既有规则留余量。

业务读数继续由服务端提供。估计、部分已知、未记全、冲突、失败和确认要求如实保留；实现过程、历史初始化和推理文案不占普通展示区域。

### D6：实际网页与交互共同通过

使用虚构账号和有代表性的数据验收，不能只看参考稿、DOM存在或长截图。样本包含尖峰、低谷、连续缺测、未知、0、未记全、长名称与长数字。

- 总览首屏视口：320×560、390×560、390×640、430×780；桌面检查1100与1440px，另查触屏横屏。
- 等字体、数据和默认区间稳定后，在 scrollY=0 截取实际视口；自动核对绘图区及日期刻度与底部导航的边界，再逐张人工查看。总览核对双图，身体核对完整体重图，饮食／消耗核对有效读数及主要图形；碰撞检查包含标题、选中读数、刻度，不只比较轴标签。
- 检查触屏横向选日／纵向滚动、键盘、菜单、弹窗、固定与解除、区间切换及布局稳定。
- 动效保持轻量，真实数字、轴和命中区不移动；减少动态效果时直接显示终态。
- 验收记录写明浏览器、视口、模拟安全区／工具栏、适用条目、截图和结果。未测与未通过必须明确标记，不能用“无横向溢出”代替首屏验收；真实iOS和软键盘体验不能由模拟测试冒充。

## 配色与页面说明

- Graphite #10100F：背景。
- Warm white #F0E9DD：主要文字。
- Gold #BEA478：品牌点缀和主要操作。
- Muted #A8A195：辅助文字。
- Line rgba(210, 194, 168, 0.32)：表单边框。
- 总览摄入蓝、消耗红；柔杏金盈余、雾蓝灰缺口；次晨变化暖白。图例、形状与文字辅助识别。

## 产品参考

Formward 学习 MacroFactor 组织高密度健康信息和减少录入步骤的方法，不复制其品牌、文案、图标、页面构图或视觉资产。以下保留已有调研；未实现的教练和训练功能不作为当前界面要求。

## 值得学习的产品设计

### 同时提供今日、每周和长期视角

MacroFactor 的营养看板把当日摄入、每日目标和一周进度放在同一组件中；Energy Balance 使用更长时间区间观察摄入与消耗；Expenditure、Weight Trend 和 Goal Progress 再提供解释性指标。

Formward 应保持同样的信息层级：

```text
现在发生了什么
→ 本周是否形成趋势
→ 长期目标是否需要调整
```

### 将事实和解释分开

MacroFactor 的看板既有 Scale Weight、Nutrition 等原始记录，也有 Expenditure、Weight Trend 和 Goal Progress 等解释结果。

Formward 页面必须区分：

- 事实：用户、设备或导入产生的记录。
- 派生值：根据明确公式计算的汇总与趋势。
- AI 判断：包含假设、不确定性和可追溯依据的建议。

三种信息不能使用相同的确定性语气。

### 让高频记录足够快

MacroFactor 通过统一 Food Logger、Plate、多入口快捷操作、常用食物和批量记录减少重复步骤。Formward 的 PC 端从手动汇总录入起步，并逐步支持：

- 全局快速记录入口。
- 键盘优先输入与搜索。
- 常用餐食、运动和模板。
- 一次提交一整餐的多个条目。
- 外部 AI 助手通过正式 API 提交候选记录，并由用户检查需要确认的写入。

### 看板可调整，但默认必须优秀

MacroFactor 允许用户隐藏和调整看板模块。Formward 首版先提供经过设计的默认布局；用户形成稳定习惯后，再增加组件显示、顺序和密度设置。

### 教练体验保持克制

MacroFactor 的 Check-In 在固定节奏中给出调整，并允许用户拒绝；其 adherence-neutral 理念关注实际行为而不是对偏离目标进行惩罚。

Formward 的 AI 教练应：

- 先解释观察，再提出动作。
- 只在答案会影响决策时提问。
- 允许拒绝、修改或延后建议。
- 不使用羞辱、夸张警报或道德化食物标签。
- 明确区分一般健身建议与需要专业人员判断的健康问题。
