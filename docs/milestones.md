# 首版里程碑

本文件管理首版的交付顺序和每个阶段的完成标准。产品边界见 `product.md`，具体页面决定见 `interface.md`，数据语义见 `data-model.md`。里程碑按依赖推进；页面细节会在进入对应阶段前与产品负责人确定。

当前已实现中央人物舞台式登录入口、真实邮箱密码登录、会话与退出，以及受保护的身体记录回看。身体模块支持三列 TSV（兼容旧四列）预览与维护脚本事务导入、空腹／晚间趋势和晨晚对比；维护脚本支持条件、来源修正、历史缺测估计和软删除／恢复；网页手动录入、编辑与逐项估算已实现；网页删除／恢复及正式 AI API 待实现。

## 首页与运行框架

- 使用 Next.js App Router、TypeScript 和 Tailwind CSS 建立可运行的网页入口。
- 首页以登录为唯一主要操作，一次自然下滚即可到达表单。
- 桌面与窄屏使用中央人物舞台，表单在同一视口叠于人物前方。
- 使用深石墨背景、暖白文字和柔和金色；一次明确下滚触发 0.5 秒转身视频（v6、2 倍速）及 Login 显现，上滚倒放并隐藏表单，播放途中可反向。静态首尾保留原来的 1.png、12.png，两端各 40ms 与透明合成的视频交叠；三张静态图和视频提前加载。点击 Enter 验证成功后以原来的 700ms 过渡到 13.png，实际动画结束后进入主页。
- 登录表单显示 Email、Password 和 `ENTER`，接入真实认证。验证中禁止重复提交与倒放；失败显示错误，成功才播放最终动画并进入主页。
- 页面适配窄屏、键盘操作和 reduced motion。

完成标准：首页视觉经评审确认；登录入口在桌面、窄屏和键盘下可用；本地可启动，lint、typecheck、production build 和目录结构检查通过。

## 账号与应用外壳

- 建立少量内部账号的邮箱密码登录、会话和退出登录。
- 登录后进入共享的应用外壳，页面导航与账号入口统一。
- 每个请求验证当前用户，敏感记录按 `user_id` 隔离。

完成标准：登录、无效凭据、重复请求和跨账号访问均有验证；登录页接入真实认证。

## 身体数据

- 已收到测量时间、体重、BMI、体脂率的样本，支持预览与脚本导入；更多指标按后续真实来源扩展，不要求逐日补录。详细范围见 [身体指标记录](measurements.md)。
- 体重与体脂率为核心，其他指标按实际来源保留；允许来源缺项，不凭空补算。
- 补齐最小手动录入、编辑、软删除和恢复入口。保留真实时间、每次测量地时区、来源与空腹确认；当地 06:00 前归前一天晚间，实际日期不变，同一时段多条不自动合并。
- 在该阶段支持实际体脂秤样本的导入预览、校验、去重和确认写入，不等待完整历史导入系统。
- 所有操作按账号隔离，并由网页和未来 AI API 共用 feature 规则。截图／语音 AI 录入与设备直连留作后续扩展，不绑定品牌。

完成标准：用户能录入、回看和纠正自己的测量记录；样本导入有清晰预览与确认，重复请求不会重复写入；缺项和未知条件为空或明确未知。数据库与认证相关检查覆盖正常、无效、重复和跨账号访问。

## 饮食与运动记录

- 饮食按实际餐次手动填入汇总数值和备注，不依赖食品库或站内 AI 估算。
- 运动采用开放式手动记录，用户填写运动内容和估算的热量消耗。
- 两类记录都有清晰的发生时间、来源、修改和软删除行为。

完成标准：用户能完成一天的饮食与运动记录，并能修正历史数据。

## 总览与趋势

- 身体记录可用后先提供体重与体脂趋势；饮食、运动和消耗口径具备后再接入热量盈余，不要求同时完成。
- 登录后的第一页最终提供报表与当日、昨日或最近状态汇总，身体记录当前提供最新空腹与 7 日摘要、7D／30D／90D／全部／自定义，其他报表区间按实际能力增加。明确日期与数据覆盖，不把最近测量冒充今天的测量。
- 每日分析区分 D 日晨晚差对照 D 日盈余，以及 D+1 日空腹变化对照 D 日盈余。保留实际时间与独立分析归属，缺少配对保持空值，不暗示确定因果。
- 训练计划和全天热量消耗按后续能力接入，当前页面只展示已实现内容。缺记录时显示空状态或图表缺口，不填零。
- 明确全天总消耗的来源和估算方式，不把摄入减已记录运动或仅减基础代谢称为全天热量盈余。

完成标准：所有汇总与原始记录一致；空白日和跨时区日期有正确表现。

## 外部 AI API

- 提供可撤销的访问令牌，供用户授权的外部 AI 助手读写数据。
- API 与网页调用相同的 feature 函数，写入保留操作者和来源，并防止重复请求。
- 修改目标或历史事实等高影响操作按产品规则要求确认。

完成标准：令牌撤销、权限限制、重复写入和跨账号访问均有验证；不接入站内 AI 饮食评估。

## 提醒与完整历史导入

- 提醒按用户选择的本地时间和时区处理；发送渠道和跨时区变更行为在本阶段确定。
- 将身体数据阶段的样本导入扩展到现有 Excel 等完整历史数据；继续先预览、校验和识别重复，再由用户确认写入。

完成标准：提醒和导入在各自约定的边界内可用，并保留来源与处理结果。

## 发布检查

- 完成 lint、typecheck、必要的单元及集成测试、production build。
- 使用虚构或脱敏数据验证关键页面、无效输入、重复写入和数据归属。
- 更新运行、部署、备份和恢复所需文档。

完成标准：首版功能和文档一致，可以在目标环境中安全运行。
