# 数据模型原则

## 核心事实

首版围绕以下数据建立：

- `User`：内部账号。
- `Session`：网页登录会话。
- `AccessToken`：AI 访问令牌摘要与状态。
- `Meal`：一次进食事件。
- `MealItem`：一次进食中的食物或整餐估算项。
- `Activity`：计划或已完成的运动事件。
- `Measurement`：一条身体指标实测或明确标记的历史估计；已实现体重、体脂率和 BMI。骨骼肌、肌肉、骨量、基础代谢、去脂体重、蛋白质、水分和内脏脂肪等按后续真实来源新增字段，不要求补齐历史缺项；候选语义见 [身体指标记录](measurements.md)。
- `MeasurementImport` 与 `MeasurementEvent`：已实现的测量导入批次和写入快照，保留来源行、去重结果、操作者与时间。
- `DailyStatus`：正常、放纵或无法计算等日期状态。

每日汇总和趋势属于派生结果，首版不作为独立事实来源。

## 通用字段

用户健康事实应具备：

```text
id
user_id
occurred_at
local_date
timezone
source_type
source_system
source_record_id
source_confidence
created_at
updated_at
deleted_at
```

- `source_type` 保留原有采集方式；身体记录另用 `record_kind` 区分 observed／estimated、`entry_channel` 区分 api／manual／development_backend。真实性不由写入工具或 AI 操作者决定，操作审计独立保留。
- `source_system` 标识具体平台、设备或文件。
- `source_record_id` 用于重复识别和回写。
- `source_confidence` 表达 AI 或估算数据的不确定性，不用于伪造测量精度。
- 事实写入另需保留操作者与操作时间；外部来源保留原始时间、原始单位及同步／导入状态，具体字段随首个真实来源确定。

## 身体测量与关联日期

- 测量保存原始当地时间、实际本地日期、当次 IANA 时区与 UTC 偏移、UTC 时刻，以及独立的 `analysis_date` 和 `period`。归属按测量地当地钟点：06:00 前算前一天晚间，06:00–17:59 算当天白天，18:00 起算当天晚间。旅行后不按新时区重新分组旧记录。
- 空腹条件可为是、否、未确认，并保留来源；白天记录须明确确认，晚间按产品规则统一非空腹，分别使用 `user_confirmed` 与 `evening_rule`。已有晚间条件经授权维护修正，不在读取时暗改历史。
- 当前 TSV 须包含时分秒；时区未知时 UTC 时刻保持空值。日期／时段来源使用 day_period；明确授权的占位时间使用 assumed，二者 UTC 时刻为空，原始输入中的真实时间仍为空；夏令时重复钟点须提供偏移，不存在的钟点拒绝。
- 同日多次测量是不同事实，不仅按日期去重。同一时段多条时保留候选，由用户选择查看，图表、配对和详情共用选择。当前已有重复组经用户授权保留较早一条，其余软删除；后续不按时间接近自动删除。持久代表选择与归属修正入口尚未实现。
- 骨骼肌与总肌肉、质量与百分比分别表达；内脏脂肪等级与基础代谢等按实际单位处理，不为不明字段推算转换。
- D 日晨晚差关联 D 日盈余；D+1 日空腹变化关联 D 日盈余。这些都是派生查询，不修改实际 `local_date` 或测量时刻。缺少任一配对或关联日数据时保持缺项，不移用其他日期的值或补零。
- 热量盈余的摄入、全天总消耗与覆盖条件尚待确定，不能以记录的运动消耗或基础代谢替代全天消耗。

## 历史缺测估计

体重与体脂按自身真实晨间空腹和真实同日晨晚差独立估计。正常 `morning-baseline-v3` 仅取目标日前 28 天：差值至少 3 个配对日取中位数，晨间最小二乘回归取最近最多 7 日、至少 3 日、最新实测距目标不超过 7 天。只有晚间而配对不足时可用同门槛晨间趋势备用；不足留空，不加入其他变量。

一次性 `historical-initialization-v1` 可用初始化范围内已存在的后续真实记录。全范围配对中位差、相邻晨间插值及最近 3 个晨间的受限边界外推独立于正常模式。估计元数据保存模式、规则版本、窗口、生成时间、真实参考快照、差值／样本数、回归系数或插值比例、实际未来数据使用情况，以及初始化批次 ID；旧版本只读兼容。

`measurement_imports.initialization_metadata` 保存独立初始化批次、冻结范围、策略、来源摘要及完整报告。部分唯一索引保证每账号至多一个初始化批次，账号锁和预览摘要保证并发与快照一致。报告含逐指标结果／缺项原因、来源快照、新估计 ID 与替换旧估计，不依赖本地文件才能恢复。

冻结范围即使仍有空缺也不再自动生成估计；普通新增不回写历史，补录真实只移除同日同段对应非空指标的估计。剩余指标和另一时段保留原值，全部替代软删除旧快照；普通重建及旧估计恢复禁止覆盖冻结范围。冻结外实测批次仍只刷新当天。

实测原始缺项不填系统值，独立估计行可仅有体脂；数据库保证实测必有体重、估计至少一个指标、有效同段估计唯一。两类估计均不参与实测摘要、晨晚差与热量关联；页面读取不写入估计。统一记录 Inspector 的估计依据显示简洁算式及按需展开的真实参考，初始化权限保留在私有报告；估计保留两位小数，不展示预测区间。设备、BMI 和实际发生时刻不伪造。所有读写校验归属并保存操作者、来源、时间及前后审计。

相同真实体重可补录原来为空的体脂／BMI，已知不同值须核对；原始输入保留。准确 `measuredAt` 验证跨午夜归属、保存 IANA 时区与 UTC，可确认占位／未知时间。

## 单位

内部使用稳定标准单位：体重 kg、营养 g、能量 kcal、时长 minute、体脂百分比。连接器负责外部单位转换，并保留必要的原始值与原始单位。

## 多生态连接

每个外部来源作为 Connector 实现，遵循：

```text
认证授权
→ 增量拉取或接收数据
→ 保存同步游标
→ 转换为统一候选记录
→ 校验与去重
→ 写入事实
→ 保存同步结果
```

首版不创建完整 Connector 表，但 schema 中的来源字段不能省略。真正接入第一个平台时，再增加连接账号、授权状态、同步游标、错误和冲突记录。

## AI 数据规则

- 外部 AI 代用户写入的记录保留 AI 操作者、用户提供的值及原始来源；不把 AI 操作等同于设备测量。
- AI 建议不自动覆盖事实数据。
- 计划变更保存提出者、依据、用户确认和生效时间。
- 任何外部或 AI 重试都应使用稳定请求或来源标识去重。
