3. Scroll 是方向 Trigger，不是 Scrubber
==================================================

核心原则：

SCROLL IS A DIRECTIONAL TRIGGER,
NOT A FRAME SCRUBBER.

当用户在初始状态做一次明显的向下滚动：

触发：

playForward()

然后动画自己从当前进度连续播放到 12。

不要继续依赖后续 wheel events。

同理：

当用户往上滚：

触发：

playBackward()

然后动画自动从当前进度反向播放到 1。

9. 底层请用统一 animationProgress
==================================================

建议不要用：

currentFrame integer

作为唯一动画状态。

维护一个连续值：

animationProgress

范围：

0 = Frame 1

1 = Frame 12

根据 animationProgress 自动计算：

currentFrameIndex
nextFrameIndex
localFrameProgress

例如概念：

const framePosition =
  animationProgress * (PRE_LOGIN_FRAMES.length - 1)

currentIndex = floor(framePosition)

nextIndex = min(currentIndex + 1, lastIndex)

localProgress =
  framePosition - currentIndex

然后：

current frame opacity =
1 - localProgress

next frame opacity =
localProgress

这样未来增加图片数量，
动画逻辑不需要重写。

==================================================

用户滚多少像素，
不等于动画播放多少。

Wheel / trackpad 的用途只是判断：

开始动画。

例如：

→ forward

累计 deltaY < -30–60px

→ reverse

触发后：

动画自己播放。

不要要求用户持续滚动。

当已经朝某方向播放时：

只需要忽略或维持当前目标。

只有检测到明确的反方向 gesture，

==================================================
